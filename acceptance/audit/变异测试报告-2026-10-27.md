## 5. 逃脱（SURVIVED）分析与等价变异说明

6 个存活中：**4 个是真实测试盲区（已在副本复现 → 写最小回归断言 → 验证原 PASS / 变异 FAIL → 落到真实仓库新增文件）**；**2 个在合法参数域内是等价变异**，任何测试都无法区分。

### 5.1 MW-04：批内 supersede 的"工作副本失效"未被覆盖（真实盲区，已补杀）

- 变异：删掉 `memorywriter.js#L117` 的 `e.status = 'superseded'`（工作副本立即失效）。
- 为什么现有测试抓不到：host-sim 的 supersede 用例是"单条新值取代单条旧值"，同批重复用例只测 `(subject,relation,object)` 完全相同被拒。**没有用例覆盖"同一批里两条不同 object 的新值先后取代同一条旧值"**——这种场景下旧条目会被写 **2 条墓碑**（supersede 事件计数虚高、JSONL 出现重复行）。
- 补杀断言（新增 `plugin/dsh-lingshu/mutation-regressions.mjs`）：同一批 `[贝塔, 伽马]` 取代 `阿尔法` 后，`out.superseded` 中 `mem_001` 只出现 1 次、落盘墓碑只有 1 行。实测：原代码 PASS，变异代码 FAIL（"出现 2 次"）。

### 5.2 MW-05：墓碑与新条目的排序（last-wins 语义）未被覆盖（真实盲区，已补杀）

- 变异：`store.append(fresh.concat(tombstones))` → `tombstones.concat(fresh)`。
- 为什么现有测试抓不到：墓碑 id 与旧条目相同，与**新条目 id 不同**，所以"墓碑排在新增之前还是之后"只在**同批内后写取代先写**（先阿尔法 → 贝塔 → 伽马）时才影响读取侧 last-wins 结果。现有用例没有这种"批内链式取代"，因此顺序退化后全套绿。
- 补杀断言：同一批 `[贝塔, 伽马]` 后，按读取侧"同 id 后写覆盖"规则，`mem_002`（贝塔）必须是 `superseded`。实测：原代码 PASS，变异代码 FAIL（`status=active`，即被取代的旧值会重新变成 active，属阿尔法泄漏）。

### 5.3 IDX-03：冲突判定的 active 过滤是"防御性冗余"（真实盲区，已补杀）

- 变异：`detectConflicts` 去掉 `if (String(e.status ?? 'active') !== 'active') continue;`。
- 为什么现有测试抓不到：端到端路径上 `recall()` 已经把 `superseded` 条目挡在 `hits` 之外（IDX-02 那层），所以 `detectConflicts` 永远见不到非 active 条目——**这层过滤是防御性冗余，只有直接单元测试它才能钉住**。现有 host-sim 冲突用例全是端到端，去掉这行依然全绿。
- 补杀断言：直接 `detectConflicts(entries, hits)`，`hits` 里混入一条 `superseded` 条目时不得产生冲突；同时保留"两条 active 不同 object 仍判冲突"的对照。实测：原代码 PASS，变异代码 FAIL（制造 false unresolved）。

### 5.4 IDX-05：quality_label 词表没有被"逐词"钉住（真实盲区，已补杀）

- 变异：`QUALITY_LABEL_RULES` 的 `wrong` 词表去掉 `'不对'`。
- 为什么现有测试抓不到：host-sim `[26]` 的每个标签用例句子都同时命中同规则里的第二个关键词（例如"不对"的用例同时含"记错"/"不是这样"），删除任一非唯一关键词后仍判对——**标签断言只钉了"类别"，没钉"词"**。同理，删掉五类里任意一个"非唯一"关键词都能改版全绿。
- 补杀断言：对五类各取一个关键词单独构造句子（如 `你说的不对` → `wrong`、`你漏了…` → `missing`、`这个别提了` → `should_not_recall`、`你又来了` → `drift`、`你凭什么…` → `overreach`），断言 `kind` 且 `quote` 是原话逐字子串；并断言普通消息无标签。实测：原代码 PASS，变异代码 FAIL（`null`）。

### 5.5 等价变异（2 个，无法也无须补测试）

- **JS-16 / PY-11：积分钳位的 `-cap` 负分支不可达。**
  `IntegralBaseline` 里钳位发生在 `e > 0` 且未饱和分支：`nxt = integral[k] + ki*e*dt`。由于 `integral` 初始为 0、只按正增量累加、只按乘性衰减回落，**不变式 `integral[k] >= 0` 恒成立** ⇒ `nxt >= 0` ⇒ `nxt < 0`/`math.copysign` 的负分支是死代码。把 `nxt = next < 0 ? -cap : cap` 改成 `nxt = cap`（Python 同理）在**合法参数域（Ki > 0）**内行为完全一致，故 SURVIVED。
  唯一能让它可区分的是 `integralKi < 0`（增益取负、语义反了）这种**超出契约的配置**；为它写回归断言等于把非法配置行为固化成契约，因此**不补测试**，只在此说明。
  结论：这 2 个不是测试缺陷，属于变异测试教科书里的等价变异（equivalent mutant）。
