## 4. C. 真实覆盖率

### 4.1 Python：方法（可复算）
- 工具：**自建 `sys.monitoring`(PEP 669) tracer**（本机无 coverage/pytest，pip 不可用）。
- **逐测试独立子进程**：每个 `tests/test_*.py` 在独立进程里 `runpy.run_path` 执行，进程内开 `LINE|BRANCH` 全局事件 → 采集 → 写原始 JSON；排除 A4 的 `test_mutation_regressions.py`，**按 13 个基线文件口径聚合**。
- **行覆盖**：回调记录 `(code, line)`，命中即返回 `DISABLE`（覆盖率只需布尔，避免热点循环重复回调；这是 tracer 能在几十秒内跑完 13 个文件的关键）。
- **分支覆盖**：`BRANCH` 事件 `(code, src_offset, dst_offset)` → 用 `code.co_lines()` 映射成 `(src_line, dst_line)`；再用 `dis` 静态枚举 3.12 条件跳转（`POP_JUMP_IF_*` / `JUMP_IF_*_OR_POP` / `FOR_ITER`），每个条件跳转有 **taken / fallthrough** 两个目的地。`taken` 由 BRANCH 事件精确判定；`fallthrough` = BRANCH 事件命中 **或** 目的地行已覆盖（近似，JSON 中 `fallthrough_approx` 标记）。**同行目的地剔除**，不计入分母。
- 可执行行 = 所有 code object 的 `co_lines()` 行并集（递归）。
- 已知限制：`fallthrough` 侧为上界近似（33 个目的地靠"行已覆盖"推断）；同行分支被剔除（3948 个目的地）；`DISABLE` 策略下只有布尔覆盖、无执行次数。
