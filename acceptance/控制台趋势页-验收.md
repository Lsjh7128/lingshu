## 5. 为什么这不是「只差一个页面」

### 5.1 页面不是瓶颈，指标落盘才是

现在有两条互不相通的路：

```text
engine/gray.py  ── 7 条护栏 + learn/* 事件（只在内存，测试里用）
        │
        └─ 没有 writer ──✗

plugin/dsh-lingshu/index.js ── audit.jsonl（事件流水：pre_step / memory_write / agent_state …）
        │
        └─ console 读它 ── 只能画「事件计数」，画不出「指标趋势」
```

趋势页要的是**按窗口聚合后的指标**，不是事件条数。当前 `audit.jsonl` 里：
`pre_step` 51 条、`memory_write` 1 条、`agent_state` 1 条；这些是**过程记录**，不是 `recall@k`、`P95`、`token_ratio`。

### 5.2 版本归因不成立

设计稿要求顶部有 `param_version` / `prompt_version` 筛选器，`docs/15` 的 `ENG-1` 也要求每个事件带版本。
但插件审计 0/81 带版本（截至本次运行），`contracts/event-bus.yaml:148-151` 的 `common_fields` 也没实现。
**没有版本，任何「指标变差」都无法归因到一次改动**——趋势页会退化成一张好看的折线图。

### 5.3 回滚状态无法诚实显示

设计稿说每张卡都含「跌破时的回滚状态」。但 `docs/14 §4` 是分级动作：
G5/G6 立即回滚/阻断，G1/G2/G7 连续 2 窗口回滚，G3/G4 只做局部降级、不整体回滚。
「每卡一个回滚状态」无法表达分级动作；正确显示至少要有
`正常 / 预警 / 已降级 / 已回滚 / 已阻断 / 缺数据` 六态，且数据来自 `learn/rollback` 与 `learn/degrade`。

### 5.4 14 天趋势缺一个聚合层

`docs/14 §2.3` 写的是「最近 24h 全量 + 更早的 1% 抽样」。
「近 14 天」如果需要每天一个点，就必须先定义：按天聚合、样本加权、抽样后如何估计比例、时区、窗口闭合规则。
这些一条都没写。**先有聚合层，才有一致的 14 天趋势。**

## 6. 最小补齐路径（按依赖顺序）

### 第 1 步：定死指标集（决策，不是编码）

三选一，写进 `docs/14` 或新 ADR：

- **A. 只画 7 条护栏**（推荐）：每条都有阈值、方向、动作，回滚语义完整；
- **B. 只画设计稿 9 指标**：需要补 7 条里没有的 4 条护栏，且大部分没有阈值；
- **C. 并集 13–14 个（不合并是 16 条）**：最全，但页面噪声最大，且要解释两套编号的关系。

无论选哪个，都先产出一张 `指标 ID ↔ 名称 ↔ 阈值 ↔ 方向 ↔ 动作 ↔ 聚合口径 ↔ 缺失策略` 的单表。
**没有这张表，验收无法判定「画出来的线对不对」。**

### 第 2 步：加指标快照（数据契约）

新增 `metrics/snapshot`（建议由插件侧的 metrics writer 发布，或由离线聚合工具生成）：

```jsonc
{
  "kind": "metrics/snapshot",
  "ts": 1792940000000,
  "iso": "2026-10-25T23:00:00+08:00",
  "window": {"start": "...", "end": "...", "tz": "Asia/Shanghai"},
  "metric": "G3.token_ratio",
  "numerator": 1234, "denominator": 9876,
  "value": 0.125,
  "missing": false, "reason": null,
  "param_version": "f7a694e0", "prompt_version": "mem-3.0+emo-3.0",
  "session_batch": "2026-10-25/am", "sample_n": 200
}
```

缺数据时 `value: null` + `missing: true` + `reason`，同时发 `guardrail_missing`；
**绝不写 0**（`docs/14 §4.1`）。回滚写 `learn/rollback`（已有契约字段 `guardrail`/`reason_code`/`restored_combo`）。

### 第 3 步：聚合与保留

- 原始事件：24h 全量（按 `docs/14 §2.3`）；
- 日级聚合：至少 30 天，字段含分子/分母/样本数，支持重算；
- 时区固定（建议 `Asia/Shanghai`），窗口左闭右开；
- 抽样数据要带 `sample_n`，图上标注置信区间或样本量。

### 第 4 步：页面

- 独立 `console/trends.html` 或 `report_trends.py`，保持**单文件、离线、只读**；
- 指标卡四要素：当前值、趋势、阈值/目标区间、动作状态；
- 窗口选择（7/14/30 天）；版本筛选/对比；
- 缺失显示为断点/`N/A`，不画 0；
- 生成时间 + 数据源 + 「旧快照」提示；
- **不复用 v0 的记忆表明文列**（原始 quote 不进趋势页）。

### 第 5 步：验收再跑

补齐后必须同时满足：

```text
python tools/audit_console_trends.py     → 0 FAIL；P1–P12 全 PASS 或有明确 n/a 理由
python tools/audit_console_data.py       → 0 FAIL
```

外加三个夹具测试：
