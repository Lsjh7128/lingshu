## 矛盾是什么

自动标定公式（task-13 写死）：

```
new_shift = max(0.40, hard - 0.15, floor((min(degraded_ratio) - 0.05) * 100)/100)
```

当前 `phaseShiftHardRatio = 0.85` → 下限 = `0.85 - 0.15 = 0.70` = **当前 shift 值**。
因此：**即使夜间收齐 3+3 条真实 host 退化证据，也不可能产生低于 0.70 的可执行下调**，
工具会如实输出"证据达标但没有可执行的下调"，不会 apply。
而 H0 的原始要求是"若真实宿主在 60% 上下文就崩，自动把阈值修正"——两者直接冲突。

另外：真实的"退化"证据只能来自 host 模式的 `keyword_hit=false` + 对照 `true`；
当前 host 首跑（`chaos-20261026-203440-host`）max_ratio=1.46、keyword_hit=True，
**还没有退化证据**，所以矛盾暂时不影响运行，但会在收满证据后卡住。

## 三个可选裁决（需要 H0 选一个）

| 选项 | 规则 | 优点 | 代价 |
|---|---|---|---|
| **A. 放宽间距** | 只要求 `shift < hard - 0.05`；hard 不动 | 最小改动，能让 60% 退化触发下调 | 两阈值可能贴到 0.05 内，"critical" 失去预警余量 |
| **B. 双阈值联动（推荐）** | shift 按退化下调后，hard 跟随保持**原有间距宽度 0.15**（`hard = shift + 0.15`） | 保留"shift→critical"的预警结构，符合原始意图 | hard 随 shift 移动，但 hard 本身没有独立退化证据（属结构性跟随） |
| **C. 维持现状** | 保持 `shift ≥ hard-0.15 = 0.70`；若真实 60% 退化，视为"双阈值设计需人工重评"，走 ADR，不自动 apply | 最保守，不引入未经证据的联动 | 自动标定对 shift 实际失效（只能证明"无需下调"） |

## 建议

**B**。理由：H0 的意图是"退化早于阈值就提前前馈"，而 shift/hard 是同一套预警结构的两个触发点；
保留 0.15 的间距宽度比保留 hard 的绝对值更符合"预警提前量"的语义。
若选 B，需要同时更新（由 Lead 派回 A2）：`tools/chaos_calibrate.py` 公式与测试、
`docs/20` 的门槛说明、`docs/19 §2.3` 的阈值描述，并补一条 ADR（阈值联动规则）；
自动 apply 时四处同步对象从 1 个参数变成 shift+hard 两组。
