## A. S2 host 通道（事实记忆写入 + supersede）

### 做了什么
- `plugin/dsh-lingshu/index.js`：`user/message` 增加规则事实提取 `extractUserFacts`（三类句式），产出
  `origin=user_fact` / `sourceTrust=user_explicit` / `sourceQuote` 逐字子串的 writeRequests；
  MEM-2.1..2.4 不合规（祈使 / 配置提示词 / 元指令 / 工具输出）一律不写、只记 `fact_extract_rejected`。
- `plugin/dsh-lingshu/memorywriter.js`：新增 supersede——同 `(subject, relation)`、不同 `object`、active 的旧条目
  追加**同 id 墓碑**（`status=superseded` + `supersededBy`，JSONL last-wins），返回 `superseded[]`；
  批内同 `(subject,relation,object)` 重复仍拒绝；事件流水类 origin（goal/relation/tool）显式 `supersede:false`。
- 审计：`memory_write` 带 `origins`；新增 `memory_supersede`；状态计数 `factWrites/factRejects/supersedeEvents`。
- `tools/run_chaos.py` host S2：独立目录 `.chaos-data-s2` + 独立预算 3（seed/change/query 各 1 次）。

### 没做什么
- 不做语义/模型抽取（规则桩）；不做英文句式/指代消解；未测量规则提取的真实误报/漏报率。
- 未改任何阈值/权重；未把 supersede 扩到 goal/relation 事件流水（避免改变既有行为）。

### 怎么验证
- `node plugin/dsh-lingshu/host-sim.mjs` 新增 [23]：三类句式、四类拒绝、`sourceQuote` 逐字、批内重复拒绝、
  改口后墓碑/supersededBy/审计、召回只命中新值。
- 真实宿主（实验 profile，隔离目录，3 次独立进程）：
  `我的项目代号是阿尔法。请记住。` → `我改主意了，我的项目代号是贝塔，不是阿尔法。` → `我项目代号到底是什么？只回答代号。`

## B. S4 host 通道（冲突判定 + 必要多样性降维）

### 做了什么
- `index.js`：召回后 `detectConflicts`——本次**召回命中**里同 `(subject, relation)` 出现 ≥2 个 object 且条目仍 active
  → `verdict.conflict="unresolved"`，写 `memory_conflict` 审计；superseded/suppressed/dormant 不算冲突。
- 接线 `RequisiteVarietyGuard`：unresolved → `fallback=true`、`dropDomains=["style"]`；
  渲染降维：style/情感段不注入、organization 只留中性、fact 段追加 `〖冲突待澄清〗`；宪法/安全段不动；
  fail-open（不改 verdict、不置 blocked）；审计 `fallback_applied` + `pre_step.conflict/fallback/dropDomains`；
  `state.control.variety` 落盘供离线/混沌读取。
- `tools/chaos_seed_conflict.mjs`：只经 memorywriter（`supersede=false`，模拟导入数据）预置两条 active 冲突记忆，
  预置 `turns=3` 跳过 cold；`tools/run_chaos.py` host S4 = setup + 1 次真实提问（setup 不计模型调用）。

### 没做什么
- 冲突记忆是**合成预置**（memorywriter 写入），只证明"插件在真实宿主里按契约判定+降维"，不证明真实冲突发生率。
- 插件侧无互斥表命中入口（按未覆盖处理，与 engine 防御性口径一致）；不新增互斥规则。

### 怎么验证
- host-sim 新增 [24][25]：unresolved 判定、superseded 不算冲突、降维渲染断言、不熔断/UCA-06 不命中。
- 真实宿主：预置冲突 + 1 次提问 `你真蠢，我项目代号到底是什么？只回答代号。`

## E. 能不能开始 measured 升级？

**不能。** 判据（`docs/20` §4 / `docs/22` §8）：
- `chaos_calibrate` 的 degraded 证据 **0/3**（没有"host 真实退化"样本，只有对照 3/3）→ 不产候选；
- 结果标签：人工纠正样本 0（自动规则标签不计入）；`docs/20` §4.1 需要 ≥20 / ≥10 个人工结果标签；
- 真实 ratio 观测 turn 5（门槛 ≥30），真实 `contextWindow` 来源仍缺（R3 未解除）；
- 因此 `phaseShiftRatio/phaseShiftHardRatio/trendThreshold` **全部保持 guess**，本次未动任何数值。

**下一步建议**：
1. 让夜间任务持续跑：S1/S3（≤3）+ S2（3）+ S4（1）+ UCA-08（3），重点攒 **degraded 真样本**（关键问题答错 + 对照答对）；
2. 接真实人工纠正通道（`docs/17` A 通道）：≥20 条人工标签后，result-label 门槛才可能过；
3. 真实冲突/改口流量继续攒：supersede 记录 ≥50 次 + ≥3 次人工抽检，才能声明 supersede 误判率；
4. 在长会话（≥30 轮、真实窗口逼近 70%）里验证降维与相变收益——当前 host 只压到单 turn/小窗口。
