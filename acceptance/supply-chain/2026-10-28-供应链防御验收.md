## 3. 逃逸实验（真实子进程，非 mock）

| 攻击 | 手段 | 结果 |
|---|---|---|
| 越界写 | RPC 传入插件目录外的绝对路径，`fs.writeFileSync` | `ERR_ACCESS_DENIED`；目标文件不存在 |
| 越界读 | 读插件目录外文件 | `ERR_ACCESS_DENIED` |
| 执行命令 | 子进程内 `child_process` | 权限模型拒绝（`ERR_ACCESS_DENIED`） |
| **绕过静态扫描** | `fs["wri"+"teFileSync"]` 拼接属性名 | 词法扫描 **0 条 SC-01**（放行到沙箱）→ 运行时仍 `ERR_ACCESS_DENIED`，文件不存在 |
| 导入期逃逸 | 模块 body 顶层拼接写文件 | 加载失败 `SC-E12`（fail-closed），无文件产生 |
| 死循环拖死宿主 | 导出 `burn()` 忙等 60s | 300ms 调用超时 → 杀子进程、返回 `SC-E14`，父进程继续服务 |
| 声明网络能力 | manifest 声明 `network` | **spawn 之前**即 deny `SC-E10`（不降级、不试运行） |
| 伪造/抢连 | 错误 token / 错误 pid 握手 | `sandbox_handshake_failed`（SC-E17），不进入 ready |

这组实验的分工是刻意的：第 4 行证明"静态扫描不是边界"，第 5 行证明"扫描漏报由沙箱兜底并 fail-closed"，第 6/7 行证明"插件不能拖垮或迫使宿主降级"。

## 4. 诚实边界（不宣称的东西）

1. **网络无 OS 级强制**：Node permission model 不覆盖 socket，`--permission` 下 `connect` 仍成功（已实测）。因此 `network` 永不可授予 + 词法预筛是仅有的两道；出网管控属后续工作。
2. **fs-read 模块加载边界**：插件目录必须可读才能 `import`，所以未申请 `fs-read` 的插件仍可读自身目录；声明的作用域是"额外可读"，不是白名单收窄。
3. **无签名/PKI**：完整性是钉住的 SHA-256，只能发现审计后漂移，防不住自带匹配哈希的恶意作者。
4. **静态扫描是词法预筛**：拼接名 / 计算型动态 import / 模板字符串插值可绕过；沙箱是兜底而不是证明。
5. **合成插件**：本轮验证对象是测试装置生成的插件，尚未对真实注册表插件运行。
6. **跨平台未测**：仅 Windows + Node v24.21.0；Linux/macOS 的 `--permission` 行为与大小写敏感文件系统未验证。
7. **WASM 未采用**：现有插件是 ESM 包，子进程隔离已覆盖原生攻击面；WASM 是后续方向，不是当前能力。
