## 二、英文小节逐段中文对照（§5 Engineering Validation）

**开篇**：契约是否可信，取决于执行它的测试；断言条数本身不是证据。因此沿三条与条数无关的轴自查：变异测试（能否发现注入的语义故障）、断言强度分级（断言是否有区分力、是否恒真/自证）、实测覆盖率。

**对抗式流程**：变异测试由一名审查者角色执行，断言与覆盖率由第二名执行，子集由第三方在独立副本上复跑。全部操作在完整副本上进行；30 个实现源文件前后哈希一致（checked=30, changed=0），只有测试文件被新增/重写。

**变异测试**：44 个单点语义变异（无语法/导入错误，全部能加载执行），分布 JS 插件 29 / Python 引擎 11 / 规则文件 4。逐个单独植入，跑**完整**两套测试：每轮 1249 条断言，44 轮约 5.5 万次断言执行。杀死判定只认断言失败，不认崩溃；error-killed = 0。审计前捕杀 38/44 = 86.4%（JS 24/29 = 82.8%，Python 10/11 = 90.9%，规则 4/4 = 100%）。40 个代码变异中 34 个由行为断言杀死（85.0%）；4 个规则变异由跨文件一致性断言杀死——这个区分我们保留在正文里。

**四个真实盲区**：都在同一结构位置——**单次写入批内的一致性**。两个关于 supersede：删掉工作副本失效 → 同一批两条新值取代同一条旧值时旧条目落两条墓碑；墓碑顺序反转 → 链式取代时被取代值按 last-wins 退回 active。一个关于冲突判定：active 过滤是防御层，端到端测试永远到不了（召回已先过滤），只有直接单元测试能钉住。一个关于 quality_label 词表：每个标签测试句同时命中第二个关键词，删任一词仍全绿；修法是把每类标签钉到**单个关键词**并断言 `quote` 是原话逐字子串。四者均复现 → 写最小回归断言 → 验证"原代码 PASS / 变异 FAIL" → 落入仓库（Python 22、JS 15 条）。补测后 42/44 = 95.5%；剩下 2 个是**等价变异**（积分钳位的负分支在契约正增益下不可达，不变式 `integral ≥ 0`），故**非等价变异 42/42 = 100%**。正文写的正是这句，而不是笼统的"100%"。

**断言强度**：固定种子抽样 238 条（Py 165 / JS 73）：STRONG 179（75.2%）、WEAK 59（24.8%）、TAUTOLOGY 0。全量启发式扫描 1192 条：Python 597 强 / 227 弱 / 1 恒真，JS 278 / 89 / 0，即"弱+恒真"26.6%。发现并修复：1 条恒真（模块头已 import 的检查）、2 处 oracle 自证（期望值取自实现的 UCA 表 → 改为测试侧独立字面量表，159→161 条）、1 处阈值输入取自被审计配置。每处重写都用"注入对应退化 → 新断言 FAIL"验证。**因此不写"892 条都是独立精确字面量"**；写"抽样 0 恒真 / 全量 1 条已修 / 约 1/4 属弱断言"。

**异常路径**：严格口径 Python 199/825 = 24.1%，JS 82/367 = 22.3%（宽松上界 43.3% / 54.2%）。自设门槛 20%，两者刚过线；若剔除阈值边界类断言，Python 约 11%。准确说法是"刚过线，不算充分"。

**覆盖率**：实测而非估算（Python PEP 669 `sys.monitoring`；JS V8 coverage）。`engine/` line 89.95% / branch 80.71%；`control.py` 141/141 行、56/56 分支；全仓 line 45.81% / branch 43.17%，被 `tools/` 32.92%（26 个文件只有 3 个被执行）拉低。**不拿覆盖率论证"没有死代码"**：受测配置下 `control.py` 无未执行行，而等价变异存在——这正是覆盖率无法单独证明测试强度的原因。

**基线账**：审计前 13 个 Python 文件 868 条 + JS 381 条；审计新增 22+2 条 Python、15 条 JS → 14 个文件 892 条、JS 396 条，全绿，实现零改动。

**局限**：① 仓库无 git 历史 → 只能证明当前状态，不能证明"历史上从未放宽断言"；② 只做单点变异，未覆盖全部模块；③ 无跨语言差分对拍（0 个变异被两侧同时杀死）；④ `tools/` 覆盖率是下限（子进程调用的工具被计 0）。

## 五、审稿人可能追问（中文应答要点，英文模板见 `supplement/REBUTTAL.md`）

1. **"断言多不等于测试强"** → 给变异结果：44 个语义变异、12 个语料家族无关；38/44 基线、42/44 补测、非等价 42/42；并给 4 个真实盲区被找到并补杀的事实——这比"我们断言多"有力。
2. **"覆盖 45.81% 太低"** → 分组给：engine 89.95/80.71、control.py 100/100；总量被 tools/ 拉低，且 tools 是下限；说明论文只用 coverage 做"受测配置下无未执行行"的弱声明。
3. **"44 个变异太少 / 2 个存活"** → 承认单点变异、承认 2 个等价变异；补第三方 14/14 独立复核；说明非等价口径 42/42 的含义边界（回归检出，不是防御效果）。
4. **"自己审自己"** → 角色分离 + 副本 + SHA256 零改动 + 只改测试 + 第三方独立复跑；并主动给限制：无 git 历史。
5. **"这些与端到端安全无关"** → 同意：这是**工程回归证据**，不是效果证据；论文的效果声明仍受 §7 Limitations 约束（measured=0、真实样本少）。
