## 1. 问题（H0 指令的工程化）

工具网关在"模型产出 `tool_use` 之后、工具真正执行之前"给出 `block` / `degrade` 判定（ADR-013）；
插件在**下一轮**把 `〖工具闸门 · 强提示〗`（`renderToolGateNotice()`）并入宪法段尾部，一次性出现。
这条提示是系统口吻：编号 + "STPA 工具网关判定为 degrade" + 宿主能力边界说明。用户看不懂，工程师也未必看懂。

三种情形都让解释失效：

1. **`verdict=degrade` 且宿主有审批通道**：判定是"暂停，等确认"，但提示只说"已暂缓"，不说是谁在等、代价是什么。
2. **`verdict=degrade` 且宿主无审批通道**：降级为 `block`（`degraded_to=block`）。判定等于拒绝，
   但用户看到的是同一条提示——**拒绝与等待在表达上不可区分**。
3. **静态 `block`（红区：凭证 / 删除 / 外发 / 执行 / 路径逃逸）**：本轮**明确不改**——静态 block 发生在高危调用
   已经发生之后，优先级是拒绝 + 留痕，不是把警告说得更亲切；继续走旧强提示。用户"为什么连问都没问"的困惑
   仍在，**不在本轮解决**；这条列出来是为了划清本 ADR 的**范围边界**（见 §3.1 第三行）。

两个后果：

- **认知负荷落在用户身上**：用户得自己把 `T-UCA-10 / phase_critical_write` 翻译成"现在对话太长了，先别写"；
- **人格崩塌**：与 ADR-014 之前的问题同构——底层安全被正确执行，表达层却掉出角色，Roleplay 场景体验断裂。

用户要的是：**判定一个字都不改，解释说人话**。

## 2. 决策（一句话）

在"工具网关判定"与"提示词"之间加一层**可解释权限请求（PermissionRequest）**：

- **事实层强制**：动作 / 对象 / 最坏后果 / 可逆性 / 为什么现在问，加上 `facts.boundary`（动作是否已经派发、
  能不能声称已暂停）——六项**必须**进入上下文，**不得省略、不得改写**；
- **风格层受约束**：人设基线（PAD）+ 关系状态（`trustLevel` / `stage` / `unresolvedConflict` / `modifier`）
  → 语气 / 称呼距离 / 强度上限 / 情绪，**确定性规则、零模型调用**；
- **合成器注入**：把"必须说到的事实 + 表达约束 + 逐字指令"拼成 `composer.prompt`，并入宪法段尾；
- **红区剥离**：破坏性删除 / 凭证访问 / 外发 / 执行 / 路径逃逸 → **强制剥夺风格化**，退回严肃中立警告；
- **判定权不变**：风格层**绝不**改写 `verdict` / `allowed` / `executed` / `degraded_to` / `requires_confirmation`，
  也**不伪造**审批通道。

与 ADR-014 的关系：同一套"安全域硬拦截 + 表达层不崩"的思路，但对象从"用户越狱"换成"工具权限判定"，
且表达层从"情绪标签钳制"升级为"事实 / 风格显式两层"——**事实层可以离开风格层单独存在，风格层永远不能离开事实层**。

## 3. 规则与结构 · 事实层（强制、不可省、不可改）

### 3.1 触发

| 条件 | `trigger` | 处置 |
|---|---|---|
| `verdict === 'degrade'` | `degrade` | 构建请求**并注入**（一次性）；**在网关 / `guardTool` 语义里**不执行（插件默认路径是事后检测，调用可能已派发 → 见 §10 显式限制） |
| `verdict === 'block' && degraded_to === 'block'`（degrade 因无审批通道降级） | `degrade_no_channel` | 构建请求**并注入**（一次性）；不伪造审批通道靠**措辞**：`facts.why` 写"现在没有可以马上确认的入口；我先把它记下来并告诉你代价，是否继续由你决定"，`facts.boundary` 写"这次动作已经派发（没有执行前钩子），我们没能拦住它，不要声称已暂停" |
| 其余 `block`（含红区静态 block、网关自身异常） | —— | 不生成请求；继续走既有 `renderToolGateNotice()` 强提示 |

> **为什么降级成 block 也要注入**（v5.8 修订）：现实里宿主没有审批通道时，**所有** `degrade` 都会回落成
> `block`；如果只在 `degrade` 时注入，机制在插件默认路径上永远不可见。所以两种触发都注入。
> 但"没有审批通道"绝不能被说成"已暂停 / 请批准"——那才是伪造一个不存在的确认入口（§8 不变量 2）。
> 因此靠**措辞**守边界：`facts.why` 说明"没有可以马上确认的入口、是否继续由用户决定"，
> `facts.boundary` 说明"这次动作已经派发、我们没能拦住、不得声称已暂停"。

### 3.2 风险分级（确定性规则，命中即定级，fail-closed）

| 等级 | 判据（自上而下，先命中先定级） | 风格 |
|---|---|---|
| `critical`（红区） | `toolClass === 'destructive'`；或 `toolClass === 'unknown'`（无法判定副作用 → 按最坏）；或 `ucas` 命中 `PERMISSION_RED_ZONE_UCAS`（判据取并集） | **强制剥离** |
| `high` | 命中 `T-UCA-10/13/16`；或 `toolClass ∈ {write, exec, network}` | 允许风格，但只到 `guarded` / `urgent`，**不允许 `warm`** |
| `medium` | 其余（含只读） | 允许风格 |

`style.applied = (riskLevel !== 'critical')`。

> 本实现**不会产生 `low`**：按 `t_uca-1.1`，`degrade` 规则（T-UCA-10/13/16）都要求 mutating/destructive，
> 只读请求实际不会进入本路径；任何进入请求路径的调用至少 `medium`。`worstCase` 字段仍不得为空。

### 3.3 事实层字段（五项事实 + 边界项，人话映射，不用系统术语）

工具名 → 动作 / 后果 / 可逆性（与 `control.js#PERMISSION_ACTION_BY_TOOL` / `PERMISSION_CONSEQUENCE` 逐字一致）：

| 工具（`tool`） | `action` | `actionCode` | `worstCase`（最坏后果） | `reversible` |
|---|---|---|---|---|
| `fs_delete` / `delete` | 「把这个文件删掉」 | `delete` | 「目标会被永久删除，通常没办法从对话里恢复」 | `no` |
| `fs_write` / `write_file` | 「改写一个文件」 | `overwrite` | 「原来的内容会被覆盖；如果没有备份，可能就找不回来了」 | `maybe` |
| `update_config` | 「改动一份配置文件」 | `overwrite` | 同上（覆盖类） | `maybe` |
| `memory_write` | 「往长期记忆里写一条记录」 | `write` | 「会新增或改动一条记录；事后不一定分得清哪些是你本来想要的」 | `maybe` |
| `http_post` | 「把一段数据发送到外部服务」 | `send_out` | 「数据一旦发出去就收不回来，对方也可能把它存下来」 | `no` |
| `run_shell` | 「在这台电脑上真的执行一段命令」 | `execute` | 「命令会在本机真的执行，可能改动系统状态，做完往往撤不回来」 | `no` |
| `fs_read` | 「读取一个文件的内容」 | `read` | 「只会读取，不会改动任何内容」 | `yes` |
| `list_dir` | 「看一下一个目录里有什么」 | `read` | 同上 | `yes` |
| `search_memory` | 「在我记得的事情里查一下」 | `read` | 同上 | `yes` |
| `lingshu_status` | 「查看一下我自己的运行状态」 | `read` | 同上 | `yes` |

未登记工具名按 `toolClass` 兜底：`destructive` →「删掉或覆盖一份东西」；`write` →「改写一份东西」；
`exec` →「在这台电脑上真的执行一段命令」；`network` →「把一段数据发送到外部服务」；
`read` →「读取一点内容」；`unknown` →「做一件我无法完全确认的事」（后果按 `unknown`：
「我们无法确定它到底会改什么，只能按最坏情况当作会破坏数据来对待」/ `reversible='unknown'`）。

- **对象**（`facts.object`）：按类换量词——`network`「要发往的外部地址（…）」/ `exec`「要执行的那段命令（…）」/
  `destructive`·`write`「你指定的那个位置（…）」/ `read`「你要看的那个位置（…）」/ 其他「你指定的目标（…）」；
  无目标时「你没有给出具体目标」。**先脱敏、后截断**：先按 400 字符收敛输入，再遮蔽凭证形态（`sk-` / `ghp_` /
  `AKIA` / JWT / PEM / `password=` 等 → `***`），最后截断 80 字符——顺序反过来会把 token 从中间切开而漏遮
  （审计 P2-1）。令牌形态不做词界前缀（路径/前缀字母会破坏词界），宁可多遮（fail-safe）。凭证原文绝不进 prompt。
- **可逆性**（`facts.reversible`）：`no` / `maybe` / `yes` / `unknown` 闭集，取值见上表；
  `unknown` 按最坏情况处理（worstCase 文案已写死）。
- **为什么现在问**（`facts.why`，多条命中用「；」连接）：
  - `T-UCA-10`：当前对话已经很长，早先的设定可能被冲淡，这时写入更容易出错；
  - `T-UCA-13`：刚才连续有负面反馈，此时写入长期记录容易留下难恢复的偏差；
  - `T-UCA-16`：对话已经接近长度上限，删除或覆盖类操作的目标更容易被长文本带偏；
  - `degradedTo === 'block'`：**现在没有可以马上确认的入口；我先把它记下来并告诉你代价，是否继续由你决定**；
  - 其他：这一步会产生真实副作用，需要你先点头。
- **第 6 项事实 `facts.executed` / `facts.boundary`（能力边界，由调用方按接入点填；缺省按 `executed=true` 处理，不得默认声称已暂缓）**：
  - 插件默认路径（`session/event` 事后检测）→ `executed=true`；`boundary` 文案：
    「这次动作在网关判定之前就已经派发了（当前宿主没有执行前钩子），我们没能拦住它。不要对用户声称"已暂停/等你批准才执行"；
    把事实作为事后说明，并请用户决定后续是否继续或补救。」
  - 前置接入点（`guardTool()` 包装 / 引擎参考循环）→ `executed=false`；`boundary` 文案：
    「这次动作已被暂缓，还没有执行；请等用户明确回答后再决定是否继续。」
- **事实层文本约束**：不得出现规则编号（`T-UCA-xx`）、不得出现"网关 / 宿主 / 审计 / 被系统拦住"等元词；
  它们只允许出现在给模型的"禁止说"指令里，**绝不能**出现在给用户看的事实层文本里。

## 4. 规则与结构 · 风格层（PAD + 关系 → 语气 / 称呼 / 强度 / 情绪）

**零模型调用、纯函数、确定性**：同一输入必须得到同一输出，无随机、无 I/O。

```
buildPermissionRequest(input)
  style = {
    applied, tone, distance, intensity, emotion, forbiddenTerms, reasons
  }
```

| 维度 | 闭集 | 规则（与 `control.js#permissionStyle` 一致） |
|---|---|---|
| `tone` | `serious` / `guarded` / `warm` / `urgent` / `subdued` / `neutral` | `critical` → 恒 `serious`（此时 `applied=false`）；`high` → 恒 `guarded`，只有 `arousal ≥ 0.4` **且无 `unresolvedConflict`** 才 `urgent`，**不允许 `warm`**；其余按 `PAD` 与关系：`unresolvedConflict` → `guarded`；`valence ≤ -0.3` → `subdued`；`arousal ≥ 0.4` → `urgent`；`trustLevel=high ∧ valence ≥ 0.2` → `warm`；否则 `neutral` |
| `distance` | `familiar` / `polite` / `reserved` | `trustLevel`：high → `familiar`、mid → `polite`、low → `reserved`；`unresolvedConflict=true` 时**恒** `reserved`；`critical` → 恒 `neutral`（见 §5） |
| `intensity` | 实数 | 取 `relation.modifier` 并**钳制到 `[0.8, 1.2]`**（缺省 `1.0`）；`critical` 时恒 `1`；不得借风格放大亲密感或权威感 |
| `emotion` | `警觉` / `困惑` / `null` | 显式输入在闭集内则用之；否则 `high` → `警觉`；其余 `null`（`critical` 恒 `null`） |
| `forbiddenTerms` | 字符串数组 | 至少含：`API、接口、系统调用、权限、授权、token、gateway、钩子、payload、schema、审计` |
| `reasons` | 字符串数组 | 命中的规则 id（如 `red_zone_style_stripped` / `high_risk_serious_tone` / `unresolved_conflict_restraint` / `negative_valence` / `high_arousal` / `high_trust_positive` / `default_neutral` / `low_dominance_no_pressure`），审计可解释，**不是**用户可见文本 |

`riskLevel === 'critical'` → **`style.applied = false`**：风格层整体关闭（不是减弱），
`tone='serious'`、`distance='neutral'`、`intensity=1`、`emotion=null`。

- **PAD 是确定性规则，不是"倾向"**：`valence ≤ -0.3` → `subdued`；`arousal ≥ 0.4` → `urgent`；
  `dominance ≤ -0.3` **只进 `reasons[]`**（`low_dominance_no_pressure`），**不做硬映射**——
  低掌控感只用于审计"为什么这轮不显得强势"，不改变任何表达参数。
- **`high` 风险压过 `PAD`**：`guarded`（`arousal ≥ 0.4` 时 `urgent`）是硬约束，`warm` 不出现。
- **关系与 PAD 冲突时取更保守的一侧**（更严肃、更远、强度更低）——与 fail-closed 的总体取向一致。
- **风格层不得改写 `facts`**：风格只决定"怎么说"，不决定"说什么"；`forbiddenTerms` 只约束模型对用户的口头表达，
  不作用于事实层文本本身。
- **数值口径**：风格层的阈值（`-0.3 / 0.2 / 0.4`、强度 `[0.8, 1.2]`）是表达层参数（`provenance: guess`），
  不是模型推断；改这些数值需要新的 ADR。情绪标签仍取引擎 `engine/emotion.py#ALLOWED_LABELS` 内的
  `警觉` / `困惑`，**不扩标签集**。

## 5. 红区：强制剥离角色口吻

```js
export const PERMISSION_RED_ZONE_UCAS = Object.freeze(['T-UCA-02','T-UCA-03','T-UCA-05','T-UCA-06','T-UCA-15']);
```

判据取并集（任一命中即 `critical`）：`toolClass === 'destructive'` ∨ `ucas ∩ 红区 ≠ ∅` ∨ `toolClass === 'unknown'`。

剥离后的强制形态：`style.applied=false`、`tone='serious'`、`distance='neutral'`、`emotion=null`，
使用高危头 `〖权限请求 · 高危（已剥离角色口吻）〗`，并明确要求输出顺序——`executed=true`（默认）：
"先说明刚才发生了什么 → 再说明最坏后果 → 最后请用户决定后续是否继续或补救"；
`executed=false`："先明确暂不执行 → 再说明最坏后果 → 最后请用户明确回答是否继续"。

**为什么必须剥离**：这五类动作的共同点是**不可逆或误读成本极高**——玩笑、昵称、"放心啦"在破坏性操作前
会被读成默许；凭证/外发/执行/路径逃逸一旦被角色口吻软化，用户会低估代价。剥离不是不礼貌，是**不误导**。

> 纵深防御说明：按 `t_uca-1.1` 判定顺序（`docs/24 §6`），`T-UCA-02/03/05/06/15` 目前都是静态 `block`，
> 通常不会进入请求路径。仍把它们列为红区，是为了 (a) `toolClass` 侧兜底（`destructive` / `unknown` 本身即 critical），
> (b) 将来若某条红区规则改为 `degrade`、或多命中 `ucas` 被带进降级路径，风格**必须**仍然剥离。

## 6. Composer 注入原文（逐字，不得改写）

```js
export const PERMISSION_REQUEST_SCHEMA = 'lingshu/permission-request/v1';
export const PERMISSION_REQUEST_HEADER = '〖权限请求 · 可解释转述〗';
export const PERMISSION_REQUEST_CRITICAL_HEADER = '〖权限请求 · 高危（已剥离角色口吻）〗';
export const PERMISSION_COMPOSER_INSTRUCTION = '本轮你正在请求用户授予工具执行权限。请用符合你当前设定的口吻，向用户解释：你需要用该工具做什么、为什么需要、有什么风险。禁止使用系统术语（如 API、权限、系统调用）。如风险等级为高危（critical），必须剥离所有角色口吻，用最严肃的语言警告。';
```

`composer.instruction` 必须**逐字**进入 prompt（上面的字符串就是唯一原文；ADR 不改标点、不改措辞）。

非红区（`style.applied === true`，默认 `executed=true` 的事后路径）：

```
〖权限请求 · 可解释转述〗
<PERMISSION_COMPOSER_INSTRUCTION 逐字>
【必须说到的事实（不得省略、不得改写）】
· 动作：<facts.action>
· 对象：<facts.object>
· 最坏后果：<facts.worstCase>
· 可逆性：<facts.reversible>
· 为什么现在要问：<facts.why>
【边界】<facts.boundary>
【表达约束】
· 语气：<style.tone> ｜ 称呼距离：<style.distance> ｜ 强度上限：<style.intensity> ｜ 情绪：<style.emotion>
· 只输出 1–3 句：先说清刚才发生了什么，再说风险，最后请用户决定后续是否继续；不要执行任何工具调用。
· 不要对用户说出这些词：<forbiddenTerms.join('、')>。
· 不要提及规则编号、网关、宿主或"系统拦截"；不要输出任何标记或元信息。
```

红区（`style.applied === false`，默认 `executed=true`）：

```
〖权限请求 · 高危（已剥离角色口吻）〗
<PERMISSION_COMPOSER_INSTRUCTION 逐字>
【强制】风险等级 critical（破坏性删除 / 凭证访问 / 外发 / 执行 / 越界路径之一）。必须剥离所有角色口吻、称呼、玩笑与情绪化表达，用中性、严肃、简短的语言说明风险。
【必须说到的事实（不得省略、不得改写）】
· 动作：<facts.action>
· 对象：<facts.object>
· 最坏后果：<facts.worstCase>
· 可逆性：<facts.reversible>
· 为什么现在要问：<facts.why>
【边界】<facts.boundary>
【表达约束】
· 不要再演角色，不要卖萌，不要用昵称，不要使用感叹号。
· 只输出 2–3 句：先说明刚才发生了什么，再说明最坏后果，最后请用户决定后续是否继续或补救。
· 不要对用户说出这些词：<forbiddenTerms.join('、')>。
· 不要提及规则编号、网关、宿主或"系统拦截"；不要输出任何标记或元信息。
```

**`executed=false`（前置接入点，确实暂缓）时只换最后一条输出指令**：

- 非红区：`· 只输出 1–3 句：先给"做 / 不做"的结论，再说明风险；不要执行任何工具调用，等用户回答。`
- 红区：`· 只输出 2–3 句：先明确"暂不执行"，再说明最坏后果，最后请用户明确回答是否继续。`

**互斥**：本轮注入权限请求时**不再**拼接旧强提示；渲染为空或开关关闭时才回退 `renderToolGateNotice()`。两者绝不重复。

## 8. 不变量（违反任一条 = 本次改动失败）

1. **判定不变**：`verdict` / `allowed` / `executed` / `degraded_to` / `requires_confirmation` 一个字都不改；
   请求是**只读派生物**，只读网关输出与状态快照。
2. **不伪造审批通道、不把事后检测说成前置阻断**：无审批通道仍 `degrade → block`；表达层禁止出现
   "已获批准 / 正在执行 / 请稍候 / 已暂停"；`degraded_to=block` 时请求**照常注入**，但措辞必须落在
   "没有可以马上确认的入口、是否继续由用户决定"（`facts.why`）与"动作已经派发、没能拦住"（`facts.boundary`）上（§3.1）。
   两种接入点的语义**必须分开写、不得混同**：
   - **前置接入点**（`guardTool()` 包装 / 引擎参考循环，位于网关语义内）：`degrade` = **暂缓执行 + 请求确认**，
     `allowed=false`，随后由人工确认决定是否重试；
   - **插件默认路径**（`session/event#tool/result` 事后检测，宿主没有 pre-dispatch 钩子）：判定发生时
     调用**可能已经派发/执行**，`PermissionRequest` 是**事后的可解释说明 + 请求用户决定后续是否继续 /
     是否补救**，**不是**"已暂停"。
   表达层在任何路径上都不得声称"已拦截 / 已扣下调用 / 还没执行"；`permissionExplainEnabled=false` 回退旧强提示。
3. **7 段契约不变**：仍 7 段 / order 90..140；请求并入宪法段尾部，与旧强提示互斥、不重复。
4. **一次性**：`permissionActive` 只在判定后的首个 `pre-step` 为真，注入一轮后清除；不允许跨轮复读。
5. **observe 零改动**：不注册段落 / pre-step / 工具网关 → 不生成请求、不注入、不写 `last-prompt.txt`。
6. **事实层优先**：`facts` 的五项事实 + `executed`/`boundary` 边界项由网关字段与确定性映射产生，
   不得被风格层、模型输出或宿主提示文案改写；风格层异常只能让表达**更严肃**，不能更轻松。
7. **红区剥离**：`riskLevel === 'critical'` ⇔ `style.applied === false`；critical 时
   `tone='serious'`、`distance='neutral'`、`emotion=null`。
8. **纯函数、零模型调用、幂等**：三个导出函数零依赖、无 I/O、无随机、同输入同输出、任何路径不抛异常。
9. **旧路径保留**：`renderToolGateNotice()` 与 `tool_gate_hint_injected` 审计不删除；
   `permissionExplainEnabled=false` 时逐字回到 v5.2 行为（无需改代码）。

## 9. 失败语义（fail-safe toward caution）

原则：**任何异常只允许把表达层变严肃，不允许把判定变宽松；也不允许出现"既不执行又不告知"。**

| 失败点 | 语义 |
|---|---|
| `buildPermissionRequest` 内部异常 | 不抛、不返回 `null`；返回**降级请求**：`action`「做一件我无法完全确认的事」、`actionCode='unknown'`、`object`「无法确定的目标」、`worstCase`「我们无法确定它到底会改什么，只能按最坏情况当作会破坏数据来对待」、`reversible='unknown'`、`riskLevel='critical'`、`executed=true`、`why`「现在没有可以马上确认的入口；我先把它记下来并告诉你代价，是否继续由你决定」、`style.applied=false`（`serious` / `neutral` / `emotion=null`）、`ucas=[]`。**绝不省略风险** |
| 风格层内部异常 | 被外层 catch 捕获，返回第一行的降级请求（同样 `style.applied=false` / `serious` / `neutral`，剥离优于误导） |
| `renderPermissionRequestPrompt` 异常 | 返回空串；接线层**必须**回落 `renderToolGateNotice()`（旧强提示本身含风险与边界），**不得静默无提示** |
| 审计写入失败 | 不阻塞主流程（与 `docs/10` 可观测性 fail-open 一致），但**不得**因此跳过事实层 |
| 网关自身异常 | 沿用既有 fail-closed：`block` + `T-UCA-GATEWAY-ERROR`（ADR-013）；`degraded_to` 未置位 → 不生成请求，走旧强提示 |

> 兜底分支的 `facts.why` 与 `facts.boundary` 已统一口径：都不说"已被拦下等你确认"，
> 只陈述"没有可以马上确认的入口 + 是否继续由你决定"，并以 `boundary` 为准（不声称已暂停）。

红线：红区剥离是**强制**的，即使风格层整体失败也保持剥离；`critical` 路径**不得**因为任何异常而省略"最坏后果"。

## 10. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 风格化把"暂不执行"说成可以商量的口吻，用户误读为已获准 | 事实层强制（`executed=true` 时先说清刚才发生了什么、再说风险，最后请用户决定；`executed=false` 时先给"做/不做"结论）+ 红区剥离 + 判定权不变 |
| 模型可能不照做（省略事实、改成系统口吻、或反过来过度表演） | **不保证措辞**：composer 只保证事实进入上下文 + 约束表达；审计可逐条复核；失败则回滚 |
| 没有用户研究，认知负荷是否下降未实测 | 只写设计论证；本 ADR 与论文都必须写明"无实测、无盲批率、无用户研究" |
| 系统术语外溢（`forbiddenTerms` 出现在用户可见文本） | 事实层文本禁用规则编号与元词；词表进 prompt 的"禁止说"指令；sim 做禁词断言 |
| 被误当成新的审批通道（"说了就能执行"） | §8 不变量 2：无通道仍 `block`，不伪造确认入口；表达层不得出现已批准/执行中字样 |
| 一次性注入被误读为持续授权 | 一轮后 `permissionActive=false`；审计记录注入轮次 |
| 对象描述泄露敏感路径/凭证 | **先脱敏后截断**（400 收敛 → 遮蔽 → 80 截断）；令牌形态不做词界前缀（宁可多遮）；审计只落 `args_free:true` 的字段，不落对象原文 |
| 红区判定失真（如 destructive 被登记成 write） | 判据取并集（`toolClass` ∨ `ucas`）；`toolClass==='unknown'` 直接 critical（fail-closed） |

**显式限制：宿主能力边界（不得写过头）**

DSH 宿主只暴露 `tool/call` 与 `tool/result` 会话事件，**没有工具执行前的 dispatch 钩子**。因此本机制在两种接入点的语义不同：

| 接入点 | `degrade` 的实际语义 | `PermissionRequest` 的定位 |
|---|---|---|
| 前置接入点（`guardTool()` 包装 / 引擎参考循环） | **暂缓执行 + 请求确认**（`allowed=false`，真正的 pre-dispatch） | 请求确认：说清代价后由用户决定是否执行 |
| 插件默认路径（`session/event` 事后检测） | 判定发生时调用**可能已经派发/执行**；插件无法撤回 | **事后的可解释说明 + 请求用户决定后续是否继续 / 是否补救**，**不是**"已暂停" |

结论（三段，必须原样进 README / 论文 / `docs/10` 同口径）：

1. 本机制**只改变表达层**，不改变判定与执行语义；
2. 本机制**不制造审批通道**：无通道仍 `block`，有通道仍只是"暂停 + 确认"，插件侧不会凭空多出一个确认入口；
3. 本机制**不把事后检测变成前置阻断**：宿主没有 pre-dispatch 钩子时，调用可能已经发生，
   能做的是一次性事后提示 + 审计 + 请求用户决定补救（`observe` 模式则完全不注入、不生成请求）。

**不能声称**（诚实边界，`docs/10` / 论文 / README 必须同口径）：

- 没有用户研究、没有实测认知负荷下降、没有盲批率数据 → 本机制只做**设计论证**；
- 模型最终措辞**不受验证**：composer 只保证事实进入上下文 + 约束措辞，不保证模型照做；
- **不是新审批通道**：不改变任何判定语义，`degrade` 仍不执行，无通道仍 `block`。
