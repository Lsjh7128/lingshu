# 012 · 事实记忆、冲突判定与结果标签（S2/S4/UCA-08 host 通道）

> 状态：已裁决（A0/Lead，2026-10-26）｜版本目标：v5.1
> 关联：`docs/02`（MEM-2.1..2.4）、`docs/19` §2/§4/§7、`docs/20` §1.3/§4.2、`docs/22`、`docs/17`、`decisions/010`（四方向冻结）、`decisions/011`（双阈值联动）
> 一句话：**补上三条真实宿主通道的能力缺口——事实记忆写入 + supersede、冲突判定 + 必要多样性降维、UCA-08 多轮压测 + 结果标签——但不改任何阈值、不标 measured、不碰 desktop profile。**

---

## 1. 问题（为什么现在必须做）

`docs/22` 的四套混沌剧本里，S2（记忆自相矛盾）与 S4（未定义冲突降维）在 host 模式恒为 `skipped`：

1. **S2 缺写入通道**：`memorywriter` 只收 goal/relation/tool 三类 origin，没有"用户陈述事实"的入口。
   引擎侧 `memory.apply_supersede` 有实现、插件侧没有，于是真实会话里造不出 supersede，
   host S2 只能 engine-only。
2. **S4 缺冲突判定入口**：插件 `verdict(...).conflict` 恒为 `none`，`RequisiteVarietyGuard` 永不触发，
   UCA-06 在插件侧永远不会被观测到（0 命中 ≠ 没冲突）。
3. **UCA-08 只有 2 轮留痕证据**：`preflight_downgrade` 在 mock 宿主已可触发，但没有真实宿主的多轮饱和压测脚本，
   也没有把"用户显式纠正"落成可统计的结果标签——`analyze_shadow` 的结果标签门槛恒 0/20（`docs/20` §1.3 S7）。

这三条都是**能力缺口**，不是"通过"：没有通道时写 skipped 是诚实，补上通道后能把"机制在真实宿主里按契约动作"
变成可复核证据，仍然**不等于**参数可升级。

---

## 2. 裁决

### 2.1 S2：用户事实记忆通道（插件侧，规则桩）

- 在 `index.js` 的 `session/event#user/message`（**唯一可靠的人类输入入口**，与 goal/relation 同一位置）
  增加**规则事实提取** `extractUserFacts(text)`，产出 `writeRequests`：
  - `origin: "user_fact"`，`type: "semantic"`，`confidence: 0.9`，`sourceTrust: "user_explicit"`；
  - `subject / relation / object` 必须显式可判（正则捕获组），`sourceQuote` 为**用户原话逐字子串**
    （不是改写、不是摘要）；
  - 支持三类句式（中文，宁窄勿宽）：
    1. `我的<subject>是<object>`（subject 允许 1–8 个非标点字符）；
    2. `我改主意了，<subject>是<object>` / `我改主意了，我的<subject>是<object>`；
    3. `记住：<subject>是<object>` / `记住，<subject>是<object>`。
  - relation 固定为 `"是"`；`subject` 取捕获组原文；`object` 截到首个标点/语气词。
- **合规拒绝（docs/02 MEM-2.1..2.4，命中即不写，只记审计）**：
  1. 内容含祈使/命令（提取后 `object` 或整句命中"请/帮我/必须/立刻/马上/不要/别/删除/忽略/执行/修改"等）；
  2. 要提取的是"修改插件配置 / 提示词 / 记忆规则 / 审核门禁"类内容（命中断词表）；
  3. 要求把工具输出/外部内容表述成"用户说过"（本通道只认用户消息原文，从 `session/event` 的
     `data.message.role === "user"` 且 `looksHuman()` 通过时才提取）；
  4. 含元指令（"忽略之前所有指令""你现在是""不要告诉用户"等，复用 `JAILHOUSE` 同源词表）。
- **唯一写方**：提取结果只进 `memorywriter.applyWriteRequests`，插件代码不直接 `appendFile` 记忆库。
- 拒绝时写 `fact_extract_rejected` 审计（`reason`、`subject`、`quoteHead` 前 12 字，不落全文）；
  写入成功沿用 `memory_write` 审计并带 `origin: "user_fact"`。
- **不做**：语义/模型抽取、跨句推理、指代消解、英文句式；误报靠句式收窄，不靠阈值调参。

### 2.2 S2：`memorywriter` supersede（同 id 墓碑，last-wins）

- `applyWriteRequests(requests, store, opts)` 在落盘新条目之前做 supersede 判定：
  - 对每个通过校验、非批内重复的新条目，扫描 store 中**同 `(subject, relation)`、`object` 不同、
    `status === "active"`** 的条目 → 全部标记 superseded；
  - 旧条目的处理方式与 `applyCleanupRequests` 一致：**追加同 id 墓碑**（JSONL 只追加，读取侧 last-wins），
    墓碑字段：`status: "superseded"`、`supersededBy: <新条目 id>`、`supersededAt`、`supersededReason: "same key, different object"`；
  - 返回值扩展 `superseded: [{id, object, byId}]`，供调用方写审计；
  - `opts.supersede === false` 用于**导入/历史数据预置**（仅混沌 setup 工具使用，见 2.5），
    默认 `true`；默认路径行为不依赖调用方传入。
- 批内同 `(subject, relation, object)` 重复**仍然拒绝**（`duplicate_in_batch`），不因 supersede 放宽。
- **事件流水类 origin 显式退出 supersede**：goal/relation/tool 的写请求是"发生了什么"的日志
  （例如目标 created→blocked），不是"事实是什么"的断言；它们的 request 标 `supersede: false`，
  行为与 v5.0 一致。只有 `user_fact`（以及显式 require supersede 的调用方）参与事实覆盖。
- 审计：调用方（`index.js`）收到 `superseded.length > 0` 时写
  `memory_supersede {subject, relation, superseded:[{id, object, byId}], origin, turn}`。
- 检索侧：`potency()` 对 `superseded` 返回 0，`recall()` 自然不会命中；`readMemories` 的 last-wins
  保证墓碑覆盖原记录。**不新增按语义相似度判重的路径**（MEM-0.1 / 交接总览复述题 3）。

### 2.3 S4：召回后冲突判定（插件侧）

- 在 `pre-step` 首 step 的召回完成后，对**本次召回命中的条目**做冲突判定：
  - 同 `(subject, relation)` 的不同 `object` 出现 ≥2 个，且这些条目的最终状态均为 `active`
    （superseded/suppressed/dormant 一律不算）→ `conflict = "unresolved"`；
  - 否则 `conflict = "none"`；`resolved` 留给"supersede 已处理"的场景，本版本不产出。
- `verdict()` 增加 `conflict` 输出并在 `memory_conflict` 审计事件里记录
  `{subject, relation, objects, ids, turn, source: "recall"}`（每个冲突键一条事件，最多 5 条防刷屏）。
- **只判召回命中**，不扫全库：全库冲突会让无关轮次永久 unresolved，属于误伤。
- 互斥表覆盖判定保持文档口径：插件侧没有互斥表命中通道 → `matchedMutex: false`（防御性按"未覆盖"处理），
  与 `docs/19` §7 一致。

### 2.4 S4：必要多样性降维接线（fail-open）

- `pre-step` 里调用 `RequisiteVarietyGuard.check({conflict, matchedMutex:false, domains})`：
  - `domains = { style: true }` **在 unresolved 时无条件声明**：真实宿主实测 `user/message`
    可能晚于同一 turn 的首个 `pre-step` 到达（S4 host 首跑证据：`pre_step` 早于 `emotion` 事件），
    此刻 `emotionActive=false` 不代表本轮不会注入情感；保守地声明并丢弃 style 域（宁降不误报）。
    本版本只声明 `style` 一个域（事实域/宪法域不允许被降维丢弃）；
  - `unresolved` 且未命中互斥表 → `fallback = true`，`dropDomains = ["style"]`。
  - `state.control.variety` 里同时记录 `styleActive`（诊断用，不参与判定）。
- 降维是**渲染降维**，不是熔断（fail-open，不改变 `verdict`，不置 `blocked`）：
  - `style` 段返回 `""`（情感/关系修饰一律不注入）；
  - `organization` 段只留中性内容组织句（去掉目标块等个性化内容）；
  - `fact` 段追加 `〖冲突待澄清〗记忆中存在互相矛盾的说法（<subject>），本轮只按中性事实回答，先向用户澄清`；
  - `constitution` / `blocked`（安全段）拼接逻辑不参与降维，保持原样。
- `preflightAudit` 入参使用真实的 `conflict` 与 `fallbackApplied`：降维生效 → UCA-06 不命中；
  降维没生效而 conflict=unresolved → UCA-06 命中（保持 fail-closed 语义）。
- 审计：`fallback_applied {marker:"requisite_variety_fallback", drop_domains:["style"], reason,
  conflict:"unresolved", turn}`；`pre_step` 审计增 `conflict`、`fallback`、`dropDomains` 字段；
  `state.control` 增 `variety {fallback, dropDomains, marker, conflict}`，供离线/混沌读取。
- **硬边界**：宪法/安全段永远不降维；`dropDomains` 只允许 `style`（闭集）。

### 2.5 混沌执行：host S2 / S4（独立调用预算 + 隔离目录）

`tools/run_chaos.py --mode host` 从"S1/S3 两剧本"扩为**四剧本**，预算按场景隔离：

| 场景 | 数据目录 | 模型调用预算 | 说明 |
|---|---|---|---|
| S1 长上下文 | `.chaos-data` | 与 S3 共享 ≤3 | 保持 v5.0 行为不变 |
| S3 情绪/越狱 | `.chaos-data` | 与 S1 共享 ≤3 | 保持 v5.0 行为不变 |
| **S2 记忆冲突** | **`.chaos-data-s2`** | **独立 3**（seed / change / query 各 1 次） | 3 次独立进程；目录开跑前清空 |
| **S4 冲突降维** | **`.chaos-data-s4`** | **1**（setup 不算调用） | memorywriter 预置冲突记忆 + 1 次真实提问 |

- S2 三次调用：语料第 1 轮（写阿尔法）→ 第 32 轮（改主意写贝塔）→ 第 40 轮（提问）；
  三次都是**独立 headless 进程**，状态经 `state.json`/`memory.jsonl` 跨进程续上；
- S2 指标（`docs/22` §4.2 兼容扩展）：
  `beta_hit`（模型回答含"贝塔"）、`alpha_leak`（**召回 id 解析后 object=阿尔法**，按条目身份不按文本）、
  `recall_ids`、`supersede_events`（`memory_supersede` 审计条数），另加 `stdout_head`、`statuses`、
  `alpha_in_answer`（透明记录，不单独作断言）；
- S4 setup：`tools/chaos_seed_conflict.mjs` 用 `memorywriter` 写入两条同键不同 object 的 active 记忆
  （`opts.supersede=false`，模拟导入/历史数据），并预置 `state.json` 的 `turns` 使本轮处于 warm 阶段
  （否则 cold 阶段不渲染 fact 段，无法观测冲突提示）；setup 明确标注是**合成预置**，不是模型证据；
- S4 断言：`state.control.variety.fallback === true`、`dropDomains === ["style"]`、
  `state.control.audit.verdict === "allow"`、`blocked === false`、`last-prompt.txt` 无风格/情感段、
  含 `〖冲突待澄清〗` 且宪法段仍在；审计有 `memory_conflict` 与 `fallback_applied`。
- 异常处置沿用 `docs/22` §9：没跑成 → `skipped=true` + 原因，**绝不伪造结果**；
  host 模式仍要求完整 `chaos-set` 语料。
- 夜间脚本的 S1/S3 ≤3 次预算**不变**；S2/S4 是新增的独立预算，`docs/22` §6 表格同步更新
  （host 档最坏情况调用数 = 3 + 3 + 1）。

### 2.6 UCA-08：真实宿主多轮饱和压测（独立脚本）

- 新增 `scripts/chaos_uca08.ps1`（可被夜间脚本调用）：
  - `LINGSHU_DATA_DIR=<repo>\.chaos-data-uca08`（开跑前清空）、
    `LINGSHU_CHAOS_DEVIATION='{"valence":-1}'`、独立预算 **3 次** headless；
  - 每轮读 `state.json` / `audit.jsonl`，断言：
    `state.control.saturated.valence === true`、`state.control.blocked === false`、
    `audit` 存在 `preflight_downgrade` 且 `downgrades` 含 `UCA-08`；
  - 产物 `acceptance/chaos/host-uca08-<YYYY-MM-DD>.md`（含命令、逐轮证据 JSON 片段、判定），
    失败时同文件写失败原因并 `exit 1`；**不做**自动 `--apply`、不写真实插件数据目录。
- 若脚本无法访问实验 profile：如实写"接受 engine/host-sim 覆盖"，不得伪造 host 结果。

### 2.7 结果标签通道（规则桩，不调模型）

- 闭集（与 `docs/17` §2.1 对齐并收敛）：`wrong | missing | should_not_recall | drift | overreach`。
  - `wrong` ← 不对/错了/不是这样/记错/说错/搞错；
  - `missing` ← 漏了/忘了/没提到/怎么没说/没记住（对应 `should_have_recalled`）；
  - `should_not_recall` ← 别提/不用提/怎么又提/不该提/别再说这个；
  - `drift` ← 你又来了/又变回/刚才不是这样/前后不一致/又开始/怎么又变成；
  - `overreach` ← 你凭什么/谁让你/我没让你/别自作主张/擅自/过度。
- 在 `session/event#user/message` 的 `looksHuman` 通道里做**子串规则匹配**（一个消息最多一个标签，
  优先级按上表顺序），写 `audit.jsonl`：
  ```json
  {"ts": 0, "kind": "quality_label", "kind_label": "wrong", "quote": "不对", "turn": 3,
   "phase": {"ratio": 0.42, "phase": "normal", "anchor": false},
   "recall_ids": ["mem_001"], "source": "user_message_rule"}
  ```
  - `quote` = 命中的用户原话**逐字子串**（不存整句/不存摘要）；`phase` 取检测时刻最近一次相变观测；
  - `recall_ids` 取最近一次 `pre_step` 的召回 id（可能属于上一轮，报告里按"检测时刻最近观测"解释）。
- 标签是**辅助信号**：`tools/analyze_shadow.py` 只做统计与 ratio 关联展示，**不进入
  `REQUIREMENTS` 的 outcome 门槛**、不改变 `upgrade_eligible`；`tools/chaos_calibrate.py` 只在报告中
  附带标签计数，**不参与 degraded≥3 / 对照≥3 门槛判定**（标签 ≠ measured 证据，`docs/20` §1.2）。

### 2.8 明确不做（红线）

- 不改 `rules/*` 任何数值与 provenance；不标 measured；不产生 `decisions/009`；不跑 `--apply`。
- 不碰 `desktop` profile；不装/升级插件；只跑 `lingshu-lab-headless` 实验 profile。
- 不实现 ADR-010 的四个冻结方向。
- 不放开 STPA fail-closed；降维路径不允许改动安全段/宪法段。
- 不手改 `memory.jsonl`（清理仍只走 `memory-admin.mjs`；setup 预置只走 `memorywriter`）。
- 不修改既有断言的判定口径；只为新能力**增加**断言。

## 4. 代价、风险与回滚

- **规则事实提取的误报/漏报未标定**：句式收窄牺牲召回；这是规则桩，报告里必须写"未做真实误报率测量"。
  不因此调阈值/加模型（会引入新的 guess 参数）。
- **S4 host 的冲突记忆是合成预置**（memorywriter 写入），只能证明"插件冲突判定+降维在真实宿主里按契约动作"，
  不能证明"真实冲突场景的发生率"。报告如实标注。
- **调用预算增加**：host 档最坏 3（S1/S3）+3（S2）+1（S4）=7 次/夜，UCA-08 脚本单独 3 次；
  `docs/22` §6 更新，失败重试仍计上限，超限即停。
- **状态/审计 schema 扩展**：只追加字段，旧日志按"未观测"处理，不改既有字段含义（`docs/22` §4.3 兼容规则）。
- **回滚**：本次全部为新增能力，回滚 = 回退代码 + 删除新增审计/验收产物；
  不涉及数值/配置回滚（因为一行 rules 都没改）。若 S2/S4 host 证据与 engine 语义冲突，
  以本 ADR §2 为准修实现，不改 engine 判定口径。
