# ADR-008 · 控制论重构：冻结项、代价与回归

- **状态**：已接受（v4.0 收口）
- **日期**：2026-10-26
- **决策者**：实现方（承接《LINGSHU 认知控制论底层重构方案》，机制契约见 `docs/19`）
- **触发**：把 7 个控制论机制落进 `engine/` 后，出现两件必须留档的事——纯 ACT-R 打崩冻结基线、
  学习闭环对核心旋钮失明（`test_proposal.py` 失败）。本 ADR 记录**改了哪些冻结项、为什么、代价是什么**。

---

## 背景

v4.0 新增控制论层：

| 机制 | 落点 | 状态 |
|---|---|---|
| 积分控制（情感基线） | `engine/control.py#IntegralBaseline` | ✅ 实现 + 专项验收 |
| 相变监控（前馈） | `engine/control.py#PhaseShiftMonitor` | ✅ 实现 + 接线 + 专项验收 |
| 必要多样性（防御性降维） | `engine/control.py#RequisiteVarietyGuard` | ✅ 实现 + 接线（正常路径不可达） |
| STPA 前置拦截（UCA-01…08） | `engine/control.py#preflight_audit` | ✅ 实现 + **强制闸**（fail-closed） |
| ACT-R 激活（频率+近因） | `engine/actr.py` + `memory.potency` | ✅ 双通道取大 |
| 全局工作空间（动态权重） | `engine/compose.py#_compute_weights` | ✅ 只决定淘汰顺序 |
| Impasse 子目标 | `engine/metacog.py#impasse` | ✅ 实现 + 专项验收 |

实施过程中暴露两个问题，都是"看起来对、跑起来不对"：

1. **纯 ACT-R 替换会打崩冻结基线**：`recall@3` 从 `1.000` 掉到 `0.556`（power-law 对"中等年龄"条目
   的激活远低于指数衰减，排序整体翻转）。
2. **重建 `memory.recall` 时名额被写死**：把返回条数写成
   `rb.get("maxReturned", topK)`，而两个默认值都等于 3 → `topK` 永远无法 >3，
   学习闭环对 `retrieval.topK` **完全失灵**（三个旋钮 `resolved 0.0` / `not_effective`，
   `tests/test_proposal.py` 失败）。

---

## 决策

1. **保留双通道取大**，不做纯 ACT-R 替换：
   `potency = max(decay, importance × normalized(B) × actrWeight)`。
   理由与实测数字写在 `docs/19 §2.1`；`actrWeight` 是"救援力度"，不是"替代程度"。

2. **返回名额以 `retrieval.topK` 为准**（恢复 `docs/02 §6.1` / `docs/13 §8.1` 的既有语义）。
   `recallBudget.maxReturned` 保留为 C23 预算契约里的同名上限，但**必须与 topK 同源**，
   由 `tools/check_config_sync.py` 做跨键校验（不等即 fail）。
   默认参数下 `recall@3` 仍为 `1.000`——**冻结口径没有变，变的是"文档写了但代码没实现"的那部分**。

3. **不改考卷**：学习闭环的评估口径、回放集、护栏阈值一律未动（A10）。
   `tests/test_proposal.py` 的断言与修正样本**一行未改**，修的是实现。

4. **控制论参数收归单一来源**：`actr{d,ref,lo,hi}`、`control{integral* ,phaseShift*}`、
   `compose.weights{fact,organization,style,retrieval,boost*}`、`memory.actrWeight`
   全部写进 `rules/decay-params.yaml`；`engine/config.py` 只做零依赖影子，由 44 项一致性检查
   （43 键 + 1 跨键）双向校验。此前这些值只存在于 config.py，违反项目铁律。

5. **硬约束不动**：`ASSEMBLY_ORDER`、8 条互斥表、拒绝路径优先于风格、情感只作用风格域、
   记忆是唯一写方——全部保持。动态权重只回答"预算不够时谁先被牺牲"，不回答"谁可以压过谁"。

6. **fail-closed 范围不变**：只有宪法层 fail-closed。`preflight_audit` 放在"拼装完、发模型前"，
   命中任一 UCA 即 `block`，此时 pipeline **不产出可注入 prompt**，只返回安全熔断文本并留痕
   （`event.audit` / `blocked`）。

## 代价与已知缺口（诚实记录）

| # | 项 | 状态 |
|---|---|---|
| 1 | **UCA-08 未闭环**：`IntegralBaseline.saturated` 确实抑制了继续积分，但 `preflight_audit` 没有 saturated 入参、没有降级留痕 | ✅ v4.1 已闭环（见文末补记） |
| 2 | 控制论层仍有硬编码数值：`control.py` 的 trend 提前量 `0.02`、ratio 上限 `1.5`、history 容量 `64`；`compose.py` 的情绪强度阈值 `0.6` | ✅ v4.1 已收归 yaml（见文末补记） |
| 3 | `rules/decay-params.yaml` 有历史重复键 `memory.forget`（YAML 解析后者覆盖前者） | ✅ v4.1 已合并 + 增加重复键检测 |
| 4 | U 型排序的可观测面是**注入事件**（`event.domains.fact.entry_ids` / `injection_order`），引擎侧本来就不把记忆原文渲染进 prompt | ℹ️ 既有范围限制，非本轮引入 |
| 5 | 相变监控只在调用方给出 `context_used_tokens/context_window_tokens` 时观测；回放链不提供 → 端到端回放不触发锚点（专项测试用小窗口覆盖） | ℹ️ 设计选择：默认不改变回放行为 |
| 6 | 仅在合成回放与单元/集成测试上验证；未在真实长会话、未在 AstrBot、未进日常 profile | ⬜ 依赖真实使用 |

## 后果

- 正面：控制论层从"有实现、没验收、没接线"变成"有专项验收（144 断言）+ 接进流水线 + 强制闸"；
  学习闭环恢复对 6 个 L1 参数的观测能力（`topK=1/2/3/4 → recall@3 = 0.444/0.667/1.000/1.000`）。
- 负面：一次"重建函数"就足以让一整条学习闭环静默失效，而**现有验收不会自己发现**——
  本轮是靠 `test_proposal` 失败才定位的。这暴露的是"重建路径缺少对照基线"的结构性风险，
  缓解措施是把"冻结指标回归"写进每次改检索路径时的必跑清单（已体现在自检命令里）。
- 恢复入口：若必须回滚 topK 语义，只能同时把 `retrieval.topK` 冻结为 3，
  否则学习闭环再次失明——不建议，且回滚需另立 ADR。

本 ADR 定稿时把三件事记为"留待下一轮"；当天即补齐，**未改任何冻结项**，故不新立 ADR，只在此留痕：

| 2 · 4 个硬编码数值 | `control.trendThreshold` / `control.ratioMax` / `control.historyCapacity` / `compose.weights.styleBoostThreshold` 进 `rules/decay-params.yaml`，代码改读 config | `test_params_single_source` 8 条 + `check_config_sync` 48 项 |
| 3 · `memory.forget` 重复键 | 合并为一个块（有效值不变）；`check_config_sync.py` 增加**重复键检测**（真实 YAML 会静默覆盖，断言不会失败） | `check_config_sync` 重复键检查 0 fail |
