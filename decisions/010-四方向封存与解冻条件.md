# ADR-010 · 四个高阶方向封存与解冻条件

- **状态**：已封存（v4.4 阶段纪律）
- **日期**：2026-10-26
- **决策者**：H0（人类负责人）指令，A0 落为 ADR
- **关联**：`待办-冻结方向.md`（可执行待办）、`docs/20-真实标定协议.md`、`decisions/008`

---

## 背景

LINGSHU 当前处于**真实环境标定与开源阶段**（v4.3 起）：

- 参考实现有 570 项 Python + 324 条插件断言，但 `provenance: measured` 数量仍是 **0**；
- 真实流量约 8 轮，相变阈值（0.70/0.85/0.02）**没有任何边界样本**；
- 夜间混沌工程刚刚搭起（v4.4），第一轮报告还没跑完；
- 工程纪律（项目铁律）：**先让现有层可验证、可解释、可回滚，再谈扩展**。

四个高阶方向（工具闭环 / 元学习 / 多 Agent 黑板 / 多模态）都会显著扩大范围、
引入新的失败模式，且当前**没有任何一条真实证据表明它们已到必须做的时候**。
因此 H0 决定：**封存，不排期；只有可观测触发条件满足才允许解冻。**

---

## 决策

四个方向进入「冻结待办」，解冻必须同时满足：触发条件（可观测证据）+ 解冻前检查 + H0 批准 + 新 ADR。
**禁止"顺手做"**：任何实现、原型、依赖引入、配置开关都不允许在解冻前进入仓库主线。

| # | 方向 | 冻结理由（当前证据） | 解冻触发条件（必须可观测） |
|---|---|---|---|
| 1 | **行动闭环（工具调用）** | 插件目前没有工具错误回滚协议；STPA 只覆盖注入侧，未覆盖工具副作用；合成器不管工具执行 | 真实日志里出现 **≥10 个任务**因"必须调用外部 API（搜索/读文件）才能完成"而失败，且现有合成器无法管理工具错误的回滚（需有失败样本与人工复盘记录） |
| 2 | **自适应演化（元学习）** | 目前 0 个 measured 参数；回放集全合成；真实样本不足，自动搜索会过拟合合成分布 | 真实日志 **turn ≥1000 条**，且手动标定被证明效率极低（单个参数 `guess→measured` 人工耗时 ≥2 人日，且有 ≥3 个参数的实际升级记录） |
| 3 | **群体心智（多 Agent 黑板）** | 当前单 Agent 端到端响应未测到业务瓶颈；多 Agent 会引入一致性/成本/安全新风险 | 真实使用中**单 Agent 响应 P95 超业务阈值**（或出现 ≥20 次"必须写代码 Agent + 审查 Agent 同时在线"的任务），且延迟/复杂度数据有审计支撑 |
| 4 | **多模态感知** | 文本记忆图谱尚未成熟（真实记忆仅 2 条、measured=0）；宿主语音/图像接口未官方稳定 | DSH 官方**正式发布稳定的语音/图像特征提取接口**（有版本、有文档、非实验），且文本记忆图谱成熟（measured 参数 ≥5、真实记忆 ≥1000 条、recall 契约稳定运行 ≥30 天） |

---

## 解冻程序（缺一不可）

1. **观测**：每日标定/混沌日报里出现触发条件的证据（日志条目、指标、失败样本），写入 `acceptance/unfreeze-status.md`；
2. **ADR**：写新 ADR（记录触发证据、代价、风险、回滚方式），编号顺延；
3. **批准**：H0 明确批准；
4. **更新**：`交接总览.md` 的阶段与缺口表、本 ADR 状态、`待办-冻结方向.md` 打勾；
5. **才允许排期实现**。

> 触发条件不满足时，唯一允许的动作是**补证据**（补审计字段、扩真实样本），
> 不是"先做个原型看看"。

---

## 代价与风险

- **代价**：冻结期间四项需求会以 workaround 形式出现（手动工具、外挂脚本、人工转换）。
  这些 workaround **不得**写进核心层、不得进入插件包；只能在 `acceptance/` 或外部脚本里存在。
- **风险**：若业务压力骤增，可能被迫绕过解冻程序 → 由 H0 承担；本 ADR 的作用是让"绕过"必须显式发生。
- **可观测性缺口**（解冻前必须先补）：
  - 当前审计没有**工具失败/任务失败**的字段（方向 1）；
  - 当前审计没有**端到端延迟**字段（方向 3）；
  - 当前没有**真实结果标签**通道（方向 2 的前置，见 `docs/20` S4）；
  - 缺少宿主多模态接口的版本化探测（方向 4）。
