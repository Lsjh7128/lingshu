# ADR-015 · 控制台解耦为独立本地只读服务（跨 Profile 热切换）

- **状态**：已接受（`console-1.0`）
- **日期**：2026-10-27
- **决策者**：A3（前端 / 横切层）提出，A0/Lead 收口；约束由 H0 指令给定
- **关联**：`docs/25-跨环境控制台.md`、`console/API.md`、`docs/14-工程与可观测性.md`、`decisions/007-可观测性是地基.md`

---

## 背景

H0 要求在日常使用 DSH 时也能看系统的实时状态（Hot/Warm/Cold 记忆、相变阈值、STPA 放行日志），
且**绝对不能影响日常环境稳定**。已有控制台是 v0 静态生成页（`tools/report_console.py` →
`console/index.html`），它有三个已记录的缺陷（`acceptance/控制台趋势页-验收.md`）：

1. 只能看**一个** profile（写死 `$DSH_HOME/plugins/dsh-lingshu`）；
2. 页面是快照，想看新数据要重跑生成器；
3. 趋势所需的数据管道没建，页面无法表达阈值/回滚/缺失。

同时有两个硬约束：

- **事故 A**（2026-10-25）：把准实验插件装进 `desktop` 后整个会话无法对话；
  `apply()` 的 try/catch 保护不了宿主在 apply 之后的校验；
- 插件数据目录是全局平铺的（`$DSH_HOME/plugins/dsh-lingshu`），desktop 与 lab 的日志会混在一起——
  在"多 profile 观测"里这是致命的数据归属问题。

## 决策

**把控制台做成一个独立的本地只读 Web 服务**（`console/server.py`，`127.0.0.1:3000`，Python 标准库），
通过 `console/profiles.json` 登记表在多个 profile 之间按需切换；同时给插件增加
**`mode: "observe"`（静默监控）** 与 **`profileTag`（数据目录隔离）**：

1. Console 不内嵌插件、不依赖 DSH、不写任何数据；HTTP 只有 GET/HEAD；
2. profile → 数据目录的映射只在服务端注册表里，客户端只能传 profile id；
3. 脱敏在服务端用**白名单**完成（`console/redact.py`），记忆单条不出网、审计按 kind 裁剪；
4. observe 模式**不注册** `systemPrompt.section` / `agent/pre-step`（waterfall）/ 工具 / 工具网关，
   只被动写记忆、相变估算、STPA 留痕与审计；
5. desktop 接入由人工脚本完成（默认 dry-run、先备份、可回滚），Agent 不代跑。

## 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| 插件内嵌 UI（client half / webServer 注入） | UI 与插件同进程，违反"不影响稳定性"；且一个插件只能看自己的 profile |
| 继续静态生成（v0 模式） | 无法热切换/实时；每次刷新要重跑生成器；历史快照会过期 |
| 改 DSH Electron GUI | 改宿主代码、风险最高，且只能看当前 profile |
| 控制台直连 SQLite 优先 | 当前插件写 JSONL；先引入迁移属于无证据的架构升级（SQLite 仅保留适配器位） |

## 理由

1. **进程边界是唯一能同时满足"实时 + 多 profile + 崩溃隔离"的结构**；
2. **白名单脱敏放在服务端**，前端被改也拿不到原文——安全属性不依赖 UI 自觉；
3. **observe 模式减少接触面而不是靠小心**：不进 waterfall 是历史事故的直接教训；
4. **profileTag 解决数据归属**：没有它，"desktop 与 lab 混读"会把错误数据当成观测结论。

## 后果

**正面**

- 一个控制台看所有 profile，下拉即切，不重启；
- 控制台崩溃/被杀对 DSH 无影响；插件默认行为（active 模式）逐字不变；
- 脱敏有可执行断言（哨兵扫描 + 禁止键递归扫描），不是文档承诺；
- 接入/回滚各一条命令，desktop 的风险面压到"两处文件 + 一个 junction"。

**代价 / 残余风险**

- 需要维护一份注册表与两套数据源适配器（jsonl / sqlite）；
- observe 模式的相变是**估算**，不能作为标定证据；
- 无认证：只适合本机；若远程化需另立 ADR（TLS + token）；
- Console 只读当前文件，没有历史聚合层（不画 14 天趋势线）；
- desktop 真实接入仍需 H0 人工执行并重启应用（本 ADR 不把"脚本存在"等同于"已验证"）。

## 边界（违反任一即回滚）

1. Console 不得出现写接口 / 写文件 / 调用插件；
2. 任何响应不得包含对话原文、记忆 `content`/`sourceQuote`、注入预览、审计 `preview/quote/argsHead`；
3. 不得把 profile 映射开放成客户端路径参数；
4. observe 模式不得注册 prompt 段、waterfall 钩子、工具；
5. 默认只绑回环地址；不得把 `acceptance`/真实数据目录纳入监控源；
6. 不得为了"看到更多"放松 `tests/test_console_server.py` 的脱敏断言（那是考卷）。

## 回滚

- Console：`scripts/console_stop.ps1`（只停服务）；删除 `console/` 新文件与启动脚本不影响 DSH；
- desktop 接入：`scripts/console_desktop_onboard.ps1 -Rollback -Apply`（先退出应用）；
- 插件 observe：从 profile patch 移除 `mode/profileTag` 配置，重启应用即回到默认 active；
- 数据：`.console-data/`（演示）与 `~/.dsh/plugins/dsh-lingshu/profiles/<tag>/` 可独立删除，互不影响。
