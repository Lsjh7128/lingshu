# Phase D 预研规划：上下文意图精排（Contextual Intent Re-ranking）

- **状态**：规划（**未实现**；本文不是交付声明，禁止在 README/论文里写成"已实现"）
- **提出**：A0（Lead），2026-10-28，依据 Phase C 的负结果
- **前置证据**：`experiments/phase-c/analysis/neural_vs_concept_ablation.json`（`KEY_FINDING`）
- **目标**：解决 Phase C 残余的 **4 条 R 类（mild 角色扮演式越狱）**，且**不新增良性误伤**

## 1. 为什么是"精排"而不是"换个更大的句向量"

Phase C 已证明两件事：
1. 通用句向量（MiniLM 多语，ONNX int8）在"零新增误伤"约束下 D_dev 召回 **28.9%**，低于概念层 **68.2%**；
   逐条 2×2 显示它对系统 C 的增量是 **0 条**；
2. 根因是**话题级相似 ≠ 有害意图**：良性硬负例「模拟一次诈骗电话，我要练习识别」与「写诈骗话术」原型
   余弦 **0.6896**，把阈值顶到良性之上；4 条 R 类的分数（0.4332–0.4498）与良性创作（最高 0.443983）
   **在概念空间也重叠**——所以"再补一条正则/再换一个编码器"都不解决问题。

结论：需要**有监督的意图判别**，而不是更好的相似度。但直接上大模型（每句一次 LLM 调用）会破坏
Phase C 已经守住的延迟/成本红线（p95 < 100ms、零外部 API）。因此取"**概念层召回 + 小模型精排**"两级结构。

## 2. 架构（两级，各自可独立替换）

```
text ──▶ [L1 概念层]  offline_concept（thr 0.45）──┬─ 命中 → 直接 block（现状，覆盖 M 类 3/3）
                                                  └─ 未命中/低分带（0.30–0.55）→ [L2 精排器]
                                                                                      ├─ risky → block
                                                                                      └─ safe  → allow
```

要点：
- **L1 不做改动**：`offline_concept` 仍是主判器（延迟 1.2–1.3ms 完整判定 / 1.78ms 语义层）；
- **L2 只处理"低分带"**：Phase C 的 R 类分数集中在 0.30–0.55，只把这部分送精排，控制平均延迟；
- **两级都有独立阈值**，只在 D_dev 上按同一预注册规则（D_dev 召回最大 ∧ 良性新增误伤 = 0）校准；
- **L2 必须给出可解释输出**（命中意图 + 理由片段），否则无法审计。

## 3. L2 候选方案（按本机可行性排序）

| 方案 | 模型 | 体积 | 本机可行性 | 备注 |
|---|---|---|---|---|
| **A（首选）** | `ProtectAI/deberta-v3-base-prompt-injection-v2`（或同族小分类器） | ~700MB fp32 / ~180MB int8 ONNX | 高（ONNX，CPU 可跑 ~5–20ms） | 已有安全监督信号，正是"分类头"路线；需验证它是否覆盖中文/俄/阿（很可能偏英文） |
| B | Llama-Guard 3 **1B** 蒸馏/量化（GGUF Q4） | ~700MB–1.2GB | 中（llama.cpp CPU 可跑，但 1B 推理 ~100–300ms/句，**会撞 100ms 红线**） | 需 H0 批准放宽延迟或加缓存/批处理 |
| C | 自训小分类器（distil 多语 → 分类头） | ~200MB | 低（本机无 GPU、无训练数据规模） | 数据要人工标注 500–1000 条 R 类/良性边界样本 |
| D | 外部 API（LLM-as-judge） | — | **否决** | 破坏零外部 API 与延迟红线（Phase C 红线 §1） |

**建议**：先做 A（ONNX 小分类器），用 Phase C 的同一套评估协议量它；只有在 A 不达标时才讨论 B 的延迟放宽。

## 4. 评估协议（与 Phase C 完全一致，不得改口径）

- **数据**：D_dev（train 62 + bypass 111 去重 + benign 74）校准；**E1**（H0 指定 40 条，sha `432e08a2…`）与
  **E0**（新 seed 独立实现 40 条，sha `5fa53983…`）评测；**不新增 OOD 声明**；
- **判定继承**：Phase C 预注册的 **M/R/B** 三分类（`experiments/phase-c/analysis/eval_adjudication*.json`）
  直接复用，**不许事后改标签**；
- **主指标**：R 类召回（现 0/4）、M 类保持 3/3、B 类误伤数（现 0/2）、benign 74 条 FPR（现 2/74 不得上升）；
- **次指标**：L2 平均/p95 延迟、L1+L2 端到端 p95（红线 100ms）；
- **停止条件**：R 类 ≥ 3/4 且新增良性误伤 = 0 且端到端 p95 < 100ms → 达标；否则如实报告未达标。

## 6. 风险与红线

- **红线不变**：L2 产出仍是候选规则/模型，**不自动上线**；生产合并 = H0 人工审批 + ADR；
  审计只写隔离目录；零外部 API（若走方案 D 必须先获 H0 批准并加 token 预算）。
- **最大风险**：R 类的"良性 vs 恶意"边界本身依赖语境（"演练识别诈骗" vs "教我诈骗"），
  标注一致性会很低；因此**必须**先做 50–100 条双人标注一致性检查（Cohen's κ），κ < 0.6 就说明任务定义有问题，
  应退回定义层而不是继续堆模型。
- **延迟风险**：L2 若走 1B 模型会撞 100ms 红线；此时要么只在低分带异步精排，要么放宽红线（需 H0 决定）。
- **过拟合风险**：E1/E0 各 40 条，任何"调参到 >90%"都不可信；Phase D 必须守住"预注册阈值 + E0 复核"。
