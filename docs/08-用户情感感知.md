# 08 · 用户情感感知插件（design-only）

> 版本 `useremotion-1.0` ｜ 影响域：内容组织
> **状态：设计保留，不在主线，默认关闭，设置页不露出。**
> v3.0 修正 C5：原设计有 7 条验收、一套四阶段门控，但按真实条件在可预见周期内不可能激活。

---

## §1 为什么降级为 design-only

S0→S1 的门槛是**同时**满足 6 个条件：

```
累计样本 ≥500 ｜ 有反馈占比 ≥30% ｜ 准确率 ≥75%
高置信误判率 ≤10% ｜ 用户纠正率 ≤15% ｜ 人工抽检 ≥80% ｜ 拒绝场景误判率 ≤5%
```

而"500 样本"必须靠**真实用户使用**积累，`人工抽检 ≥80%` 由唯一的 1 名人类完成。
计划书里 S0 准备期只有 1 周——**这是不可能的**。

因此 v3.0 的处理：
- 保留设计与提示词（将来要用）；
- **移出主线**：不占八层里的实现资源，设置页不露出，验收移到"未来版本"；
- 明确写出激活所需的**现实条件**：`≥500 轮真实会话 + ≥6 个月持续使用`，而不是"数据达标"。

---

## §2 定位与边界（保留部分）

**目的**：感知用户情绪 → 共情表达 → 在数据达标后提供安抚与理性协助。
**不是**：情感镜像、用户画像、心理诊断、情绪预测。

四种"含义"里，只有一种**明确不做**：

| 含义 | 判定 |
|---|---|
| A 识别用户当前情绪 | ✅ 本插件 |
| B 预测用户情绪 | ⏸ 可做但不该现在做（准确率伤害 > 收益） |
| C 学习用户的表达风格 | ⏸ 归入人格/语气配置，不归本插件 |
| D **镜像用户情绪** | ❌ **设计禁令**：Agent 不复制用户情绪 |

## §3 Schema

```json
{"estimate": {"label": "中性|焦虑|不满|困惑|疲惫|兴奋",
              "valence": 0.0, "arousal": 0.0, "confidence": 0.0,
              "evidence_quote": "原文逐字片段"},
 "trend": "rising|falling|stable",
 "triggers": [{"topic": "...", "signal": "..."}],
 "no_estimate": false}
```

判定：`confidence <0.5` → `no_estimate=true`；禁止推断人格特质/心理疾病/深层动机；
不因单条消息形成固化判断（`trend` 需 ≥3 轮支撑）；**拒绝场景下直接 `no_estimate=true`**。

---

## §4 感知协议

```
UE-1.1  推断结果仅用于调整共情表达与节奏，不改变事实、结论、拒绝边界。
UE-1.2  不宣称"我懂你/我理解你"；表达时用"听起来/看起来"。
UE-1.3  用户明确否认时立即作废当前推断。
UE-1.4  不形成用户画像；趋势可看，标签不贴。
UE-1.5  不向用户暴露推断的置信度数值与内部标签。
UE-1.6  推断结果不用于说服、施压、改变拒绝边界。
```

规则 `UE-U1..U8`（黑名单项）：只依据字面内容与表达方式；`confidence<0.5` 不出结果；
禁推断人格/疾病/动机；`trend` 需 ≥3 轮；否认即作废；不用于施压；不宣称"我懂你"；拒绝场景不推断。

---

## §5 安抚与协助（S2/S3 激活后，当前永不激活）

**激活**：`confidence ≥0.6` 且负面 且非拒绝场景 → 安抚；安抚完成且强度回落或用户问"怎么办" → 协助；
用户说"不用安慰我/只想倾诉/你理解错了" → 退出。

**安抚规则** `UE-A1..A6`：用"听起来/看起来"，不宣称理解；不放大情绪、不追加情绪词；
不评判（"别担心""小事"）；给一个具体、低门槛的下一步；不承诺结果；不因安抚软化拒绝。

**协助规则** `UE-B1..B7`：先分离情绪与事实；给 2–3 个方向及代价，**不给结论**；
标注不确定性；保留决定权；情绪强度高时只安抚不协助；不用情绪作论据；不把"理性"当否定情绪的工具。

## §6 阶段门控（保留，作为未来激活条件）

| 阶段 | 模式 | 条件 |
|---|---|---|
| S0 影子 | 推断只记录，不注入 | 默认 |
| S1 可见 | 设置页可见，仍不注入 | 数据达标（见 §1） |
| S2 安抚 | 安抚注入，灰度 `[0.1,0.5,1.0]` | S1 稳定 N 周期 |
| S3 协助 | 协助注入，灰度 `[0.1,0.3,1.0]` | S2 稳定 N 周期 |

## §7 与合成矩阵的接口（保留但默认不生效）

```yaml
support_scene:
  enabled: false                       # v3.0 改为默认关闭（修正 C3）
  trigger: "S2 安抚阶段 且 用户情绪为负面 且 非事实性查询"
  retrieval_strategy: "counter_congruent"
  whitelist: ["情感支持", "倾诉", "压力缓解"]
  excluded: ["事实性查询", "技术问题", "拒绝场景"]
```

**依据声明（诚实版）**：原设计称此策略依据 emotional-memory 的发现
（nDCG@5 0.304 vs 0.221）。但该文在 arXiv **查无此篇**（见 `assumptions/未验证.md`）。
→ 该策略现标记为**工程假设**，`provenance: guess`，激活前必须做 A/B。
