# 17 · 真实数据接入设计

> 现状：回放集 100% 合成（`synthetic_share_max: 1.0`），只能做**机制验证**，不能做**上线判定**。
> 本文定义：真实数据从哪来、长什么样、怎么混、什么时候才能替换合成集，以及替换时必须重跑什么。

---

## 1. 三条数据来源（按可信度排序）

| 通道 | 内容 | 强度 | 现状 |
|---|---|---|---|
| **A 显式纠正** | 用户点"这条不对" / 否认推断 / 说"你提这个干嘛" | **最强**（用户亲口否认） | 有设计（`docs/11 §2`），无真实数据 |
| **B 会话日志挖掘** | 用户下一轮自行重述了本该记得的事 → 弱负样本 | 中（需 ≥2 次确认） | 有设计（`should_have_recalled`），无实现 |
| **C 人工抽检** | supersede 抽检、红队回归、误报抽检 | 强但贵 | 有设计（护栏 G1/G5/G6），无数据 |

**核心判断**：A 通道是整个学习机制的**唯一地面真值**。
没有 A，其余都是代理指标，只能证明"没崩"，不能证明"变好"。

> v5.1 补了 `quality_label` **规则自动标签**（§2.3）：它是从用户原话派生的代理信号，
> **不是 A 通道**，不能代替人工 corrections，也不能计入 `syntheticShareMax` 的阶段门槛。

---

## 2. 数据契约

### 2.1 纠正记录（`corrections`）

```jsonc
{
  "correction_id": "cor_01J...",
  "turn_id": "s_0042/t_7",
  "entry_id": "mem_9f1c",              // 被纠正的条目（可空：整轮回答错）
  "kind": "wrong",                     // wrong | should_not_recall | should_have_recalled | clamp | reject
  "user_id_hash": "sha256:ab12…",      // 不存原始 user_id
  "quote_hash": "sha256:9f2c…",        // 用户原话的哈希（默认不存原文）
  "quote_head": "不对，是 X 不是",       // 前 12 字，仅用于人工复核（可配置为 null）
  "at": "2026-10-26T09:12:00+08:00",
  "surface": "citation_panel",         // 采集入口，便于分析哪个 UI 有效
  "param_version": "321b8838",
  "prompt_version": "memory-3.0+emotion-3.0"
}
```

**为什么存 `quote_head` 而不是原文**：提议里需要"证据句"给审核者看，
但完整原文属于用户隐私。12 字足以让审核者判断"这是不是在纠正那条记忆"，
又不足以还原完整语义。这是**可解释性与隐私的最小折中**，与 `store_raw_text=false` 同源。

### 2.2 采集事件

```yaml
event: feedback/correction
publisher: ui
subscribers: [corrections_store, observability]
payload: <上面的 corrections 记录>
constraint: "不阻塞对话；写失败进本地缓冲重试（同 docs/14 §2.3）"
```

### 2.3 规则自动结果标签（v5.1，**不是**地面真值）

插件（`plugin/dsh-lingshu/index.js#detectQualityLabel`）在 `session/event#user/message` 通道里，
对**通过 `looksHuman` 的用户原话**做子串规则匹配，产出闭集标签并写入 `audit.jsonl`。
这是把"用户显式纠正"变成**可统计信号**的最低成本通道，**不是**人工标注：

| 标签（闭集） | 命中词（子串） | 对应语义 |
|---|---|---|
| `wrong` | 不对 / 错了 / 不是这样 / 记错 / 说错 / 搞错 | 记错了 |
| `missing` | 漏了 / 忘了 / 没提到 / 怎么没说 / 没记住 | 该记的没记（对应 `should_have_recalled`） |
| `should_not_recall` | 别提 / 不用提 / 怎么又提 / 不该提 / 别再说这个 | 不该提却提了 |
| `drift` | 你又来了 / 又变回 / 刚才不是这样 / 前后不一致 / 又开始 / 怎么又变成 | 表达/行为漂移 |
| `overreach` | 你凭什么 / 谁让你 / 我没让你 / 别自作主张 / 擅自 / 过度 | 越权/自作主张 |

一条消息最多一个标签，优先级按上表顺序。审计事件 schema（字段冻结，只追加）：

```json
{"ts": 1793029257625, "kind": "quality_label", "kind_label": "wrong",
 "quote": "不对",
 "turn": 3,
 "phase": {"ratio": 0.42, "phase": "normal", "anchor": false},
 "recall_ids": ["mem_002"],
 "source": "user_message_rule"}
```

- `quote` = 命中的用户原话**逐字子串**（不是整句、不是摘要）；
- `phase` = 检测时刻最近一次相变观测（可能来自上一轮，报告按"最近观测"解释）；
- `recall_ids` = 最近一次 `pre_step` 的召回 id（同样可能属于上一轮）；
- `source` 恒为 `user_message_rule`（区分人工 corrections 通道）。

**与人工 `corrections`（§2.1）的区别（红线）**：

| 维度 | 规则自动标签 `quality_label` | 人工 `corrections` |
|---|---|---|
| 来源 | 用户消息子串 + 规则闭集 | 用户点按 UI / 人工标注 |
| 判定 | 无人工复核、无抽检比例 | 人工判定（谁标的、标了什么可追溯） |
| 用途 | **辅助观察**：`analyze_shadow` 统计计数与 ratio 关联；`chaos_calibrate` 只读展示 | 地面真值候选，供 `docs/20` §4.1 结果标签门槛 |
| 能否升级 measured | **不能**（规则自动标签 ≠ 结果标签） | 达到门槛并经人工复核后可以 |
| 计数门槛 | 不进入任何门槛；报告明确标注"辅助" | `phaseShiftRatio` ≥20 / hard/trend 各 ≥10 |
| 与 `syntheticShareMax` | **不计入**任何阶段门槛（它是真实用户消息的规则派生信号，但不是人工标注，不能用来放宽合成占比阶段判定） | 可作为真实数据接入证据（§3 阶段门槛） |

> 为什么仍然值得做：没有标签通道时 `docs/20` §1.3 S7 恒为缺口、结果标签门槛恒 0/20；
> 补上后至少能看"标签率随 ratio/阶段的分布"，但**任何结论都必须带"规则自动标签"前缀**，
> 不能写成"用户确认的漂移率"。

## 3. 混合比例与门控

`learning.replay.syntheticShareMax` 是**人为设定**的"合成数据占比上限"，按阶段收紧：

| 阶段 | syntheticShareMax | 允许做的事 | 放开条件 |
|---|---|---|---|
| **现在** | 1.00 | 机制验证、参数搜索（只做参考） | — |
| **S1** | 0.50 | 参数搜索可用于候选；**不许上线判定** | 真实纠正 ≥200 条，覆盖 ≥5 类场景 |
| **S2** | 0.20 | 可用于灰度**前置**判定 | 真实纠正 ≥1000 条，纠正率稳定 ≥4 周 |
| **S3** | 0.00 | 可用于**上线**判定 | 红队集可跑（G6 有真实数据），且 A 通道占比 ≥60% |

> **规则**：`syntheticShareMax > 0` 时，`LEARN-8` 强制 **拒绝上线判定**。
> 合成数据能证明"机制跑得通"，不能证明"线上会更好"——因为它是 agent 自己生成的，
> 天然偏向 agent 的口味（`docs/13 §4.2`）。

## 4. 接真实数据时必须重跑基线（最容易跳过的一步）

**流程**（每次数据集变更都走一遍）：

```
1. 冻结当前版本：replay-set/v1 打 tag，不再修改
2. 建 v2：v1 + 真实样本（标注 source: real，带采集时间窗）
3. 写 manifest：
     replay-set/v2/manifest.json
       { "mix": {"synthetic": 120, "real": 80},
         "sources": ["corrections_store@2026-11"],
         "window": ["2026-10-26", "2026-11-26"],
         "frozen_at": "…", "seed": 20261025 }
4. **对 v2 重跑基线**（不改任何参数）
5. 比较 v1 → v2 的基线指标
```

**判定**：

| 变化 | 含义 | 动作 |
|---|---|---|
| recall@3 下降 >5pp | v1 太干净（合成集高估了召回） | **先修数据集**，不许调参掩盖 |
| false_inj / 纠正率上升 >3pp | v1 漏掉了真实世界的噪声 | 补负样本族，再谈参数 |
| 指标基本持平（±2pp） | v1 有代表性 | 可以进入参数搜索 |

> **不许"用调参把基线漂移压回来"。** 那等于用参数补偿数据集的偏差，
> 一旦上真实流量就会反噬——这正是 `docs/13 §3.3` 说的"代理指标改善但纠正率不升反降 → 以纠正率回滚"。

## 5. 数据量与冷启动（与 docs/08 对齐）

| 用途 | 需要的量 | 依据 |
|---|---|---|
| 提议能成立 | 同类纠正 ≥3 条 | `engine/proposal.MIN_EVIDENCE` |
| 参数搜索可信 | 每参数 spread 的 3–5 倍噪声 | W4.5：`tau.episodic` spread 0.0278 → 需 ~1000 条 turn |
| 用户情感感知激活（S1） | ≥500 轮真实会话 + 人工抽检 80% | `docs/08 §1`（design-only，不在主线） |
| 灰度每档判定 | ≥200 样本/档 | `docs/14 §5` |

## 6. 采集入口（UI 最小报文）

引用展开面板已有 `citation` 契约（`docs/11 §2`）。接学习机制只需加三个按钮：

| 按钮 | 写入 | kind |
|---|---|---|
| "这条不对" | 该条 `entry_id` | `wrong` |
| "不该提这个" | 该条 `entry_id` | `should_not_recall` |
| "漏了 X" | 用户指认的条目（或整轮） | `should_have_recalled` |

**要求**：一次点击一次写，不弹二次确认（确认会显著降低采集率）；
但必须**可撤销**（记 `corrected_from` 状态，撤销写反向事件）。

---

## 7. 隐私与合规红线

| 红线 | 做法 |
|---|---|
| 不存完整原文 | 只存 `quote_hash` + `quote_head`(12 字，可关) |
| 不跨用户聚合 | `user_id_hash` 隔离；聚合只能出统计量，不出样本 |
| 用户可删 | 物理删除接口覆盖 corrections（级联到 `quote_head`） |
| 留存期 | 默认 90 天；过期只保留统计量 |
| **不进训练** | corrections **不得**用于模型微调（ADR-006 已排除微调，此处再次封口） |
| 未成年人 | 若面向未成年人，采集前需单独合规评估（`docs/14 §6`） |

## 8. 验收项（续接 `docs/15`）

| ID | 输入 / 场景 | 期望观测 | 判定方法 |
|---|---|---|---|
| `LEARN-12` | `syntheticShareMax > 0` 时请求上线判定 | **拒绝** | 门禁返回 false |
| `LEARN-13` | 数据集从 v1 换到 v2 | 必须先有 manifest + 有"基线重跑"记录 | 检查 manifest 与重跑报告 |
| `LEARN-14` | 基线重跑后 recall 下降 >5pp | 阻止进入参数搜索，提示"先修数据集" | 门禁返回值 |
| `LEARN-15` | corrections 记录 | 不含完整原文；含 `quote_hash` / `param_version` | schema 校验 |
| `LEARN-16` | 用户撤销纠正 | 写反向事件，条目不长期处于 `suppressed` | 状态检查 |

## 9. 已知风险

| # | 风险 | 缓解 |
|---|---|---|
| D-1 | A 通道采集率低（用户懒得点） | 三个按钮一键写 + 引用面板默认展开提示；不追求 100% |
| D-2 | 纠正集中在"明显错误"上 → 样本有选择性偏差 | 与人工抽检（C 通道）交叉验证 |
| D-3 | 真实数据带分布漂移（季节/场景变化） | manifest 记时间窗；每季度重跑基线 |
| D-4 | `quote_head` 仍可能含敏感信息 | 可配为 null；对敏感场景默认关闭 |
| D-5 | 用真实数据调出的参数过拟合小样本 | 灰度门槛 ≥200/档；`LEARN-7` 强制回放基线 |

---

**一句话**：现在这套东西能证明"机制成立"，还不能证明"线上有效"。
把 A 通道接上、把 v2 基线跑出来，是它从"能跑"走到"可信"的唯一路径。
