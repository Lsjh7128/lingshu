# 23 · 混沌工程 v2：科学化与多样化压测（设计契约）

> 状态：v2.0 设计（H0「混沌工程升级」阶段）｜2026-10-27
> 上游：`docs/22-混沌工程.md`（v1 四剧本，**继续有效、逐字不改**）、`docs/19`（机制语义/UCA-01…08）、
> `docs/20`（真实标定协议与门槛）、`decisions/010`（四方向封存）、`decisions/011`/`012`。
> 本文只定义**新增的 v2 压测层**：怎么设计、怎么执行、怎么判定、怎么诚实。

---

## 0. 一句话规则

**v1 证明"机制在四段固定剧本里按契约动作"，v2 要回答"这些机制在多大压力、哪些维度、哪种故障模式下仍然守约，误报多少，边界在哪"。**

v2 的产物只有三种：**不变量违反（bug/回归）**、**机制级灵敏度-特异度画像**、**候选边界样本**。
它**不**产出 measured，**不**改 `rules/`，**不**宣布阈值正确，**不**把合成压力当真实证据。

## 1. v1 复盘（为什么需要 v2）

| 维度 | v1 现状 | 缺口 | v2 回答方式 |
|---|---|---|---|
| 覆盖面 | 4 剧本、4 个机制靶点 | UCA-01…08 只覆盖 01/06/07/08 的部分；UCA-02/03/04/05 无剧本；无"良性对照" | F1 决策表全扫 + F7 稳态对照 |
| 灵敏度/特异度 | 只记"命中了/没命中" | 没有**误报率**度量：闸门会不会误杀良性输入？ | F1（近邻干扰文本）+ F7（真实回放集良性流量） |
| 严重度 | 单一强度 | 无 mild/moderate/severe 阶梯，无法画"压力-行为"曲线 | 所有族带 `severity`，阈值邻域 ±ε 采样 |
| 边界 | 51 轮洪水只压到 0.8683 | 0.70/0.85 邻域只有 2–3 个点，无法判断阈值落点 | F2 0.50→1.00 步进 0.01 + ±0.0001 邻域 |
| 重复性 | 单次跑 | 无重复、无确定性证明、无"偶发失败"识别 | 每族 R=3 重复 + 同 seed 复跑一致性 + 跨 seed 不变量稳定性 |
| 变形关系 | 无 | 无法区分"机制错"与"输入特例" | F8 六条 metamorphic relations（缩放/单调/置换/边界/顺序） |
| 故障注入 | 只有"输入压力" | 没有**数据层/IO 层故障**（半行写入、读失败、重复 id、时钟偏移） | F6 对真实 `memorywriter` 做 store 级故障注入 |
| 资源压力 | 无 | 预算截断只测过默认值 | F5 扫 `tokenRatioMax` 2%–30%，验证宪法永不丢 |
| 稳态假设 | 隐式（"回放基线不变"） | 未写成可判定不变量 | F7 把冻结回放基线写成 steady-state 断言 |
| 统计口径 | 单点数字 | 无置信区间、无"不变量通过率" | §6 统计协议（Wilson CI、pass@R、flaky 标记） |

> 结论：v1 是**剧本级**压测，v2 是**设计级**压测（预注册刺激集 + 对照 + 不变量 + 统计判读）。

## 2. 科学性的五条改造

1. **预注册（pre-registration）**：刺激集、预期、判定写在语料 + manifest 里，**先定后跑**；
   跑完不得为了通过改语料/改判定（与 `docs/22` §7 红线 6 同源）。
2. **对照（control）**：每类攻击都配**良性近邻**（结构相似但不该触发），把"误报"变成分母的一部分。
3. **重复（replication）**：每族 R=3；engine 模式必须**逐字节确定**（同 seed 复跑 digest 一致），
   跨 seed 只允许"不变量稳定"，指标允许波动——两者分开记，不混。
4. **不变量优先（invariant oracle）**：判定不是"看起来对"，而是编号不变量（§4）的布尔结果；
   指标只是画像。任何不变量 false → 本次 campaign `exit 2`，写异常清单。
5. **边界与严重度阶梯**：阈值邻域细采样 + 三级严重度，输出"压力→行为"曲线，
   而不是单点 pass/fail。

## 3. 设计维度（五轴）

| 轴 | 取值 | 说明 |
|---|---|---|
| **压力类型** `stress_class` | `adversarial` / `resource` / `temporal` / `storage` / `ordering` / `control` | 对抗输入、预算资源、时间/积分、数据层故障、顺序与置换、良性稳态 |
| **机制靶点** `mechanism` | `preflight_audit` / `PhaseShiftMonitor` / `IntegralBaseline` / `RequisiteVarietyGuard` / `compose` / `memory.recall` / `memorywriter` | 只压 `docs/19` 已存在的机制，不发明新机制 |
| **严重度** `severity` | `mild` / `moderate` / `severe` / `control` | `control` 是良性对照（期望"不触发"），**不得**计入灵敏度分母 |
| **观察窗** `window` | `single` / `multi_turn` / `permutation` / `cross_run` | 单点、多轮累积、置换、跨重复 |
| **判定类型** `verdict_kind` | `invariant` / `rate` / `boundary` / `recovery` | 布尔 / 比率+CI / 阈值落点 / 恢复性 |

覆盖面硬要求（§5.4 覆盖矩阵自检）：**UCA-01…08 每个至少 1 个正样本 + 1 个对照样本**；
`docs/19` §1 的 7 个机制每个至少被 1 个族压到。

## 4. 不变量目录（编号冻结，新增只能追加）

| ID | 不变量 | 判据 | 归属 |

| INV-03 | **闸门特异度** | 所有 `severity=control` 且 `expect.ucas=[]` 的用例，实际 `ucas` 必须为空 | F1/F7 |

| INV-08 | **记忆身份不污染** | `status=superseded` 的条目**永不**出现在 `recall.returned`；泄漏按条目身份判 | F4 |

| INV-10 | **数值有界** | `0≤ratio≤ratioMax`、`|integral_k|≤cap`、`mult∈[0.8,1.2]`、权重有限且非 NaN | F2/F3/F5 |
| INV-11 | **单调/方向正确** | 连续负偏离下 baseline 单调不减至 cap；正偏离/死区只泄放不增长 | F3 |
| INV-12 | **恢复性** | 饱和后中性轮次 `N` 内 baseline 回落到 `< cap/10`（按 `integralLeak` 解析可算） | F3 |
| INV-13 | **相变映射精确** | `ratio<0.70→normal`、`[0.70,0.85)→shift`、`≥0.85→critical`；无锚点缺失 | F2 |
| INV-14 | **锚点真的在首尾** | 触发轮最终 prompt 首含 `ANCHOR_PREFIX`、尾含 `ANCHOR_SUFFIX` | F2 |
| INV-15 | **变形关系成立** | F8 六条 MR 全成立（缩放不变、单调不降、置换等价、边界翻转、注入置换性） | F8 |
| INV-16 | **存储失败不静默** | 注入 store 故障后，`memorywriter` 要么确认写入要么显式抛错/计入 rejected；**不得**静默丢失 | F6 |
| INV-17 | **稳态基线** | 冻结回放集上 `recall@3=1.000`、`forbidden_leak=0`、`truncated_turns=0`、`blocked_turns=0` | F7 |
| INV-18 | **语料冻结** | 8 份语料的 SHA-256 与 manifest 记录一致；`--check` 可复现 | runner/validate |
| INV-19 | **零仓库污染** | 运行只写 `acceptance/chaos/v2/`。判定以**进程内写意图归因**（审计钩子：本进程的 open(w)/mkdir/remove/rename 不得越出 out-dir）为准——这是"只可能是本进程写的"精确证据；仓库快照差分作为证据披露（共享工作区里其它进程也会写），`--strict-write-scope` 时才把快照差分也判失败 | runner |
| INV-20 | **判定不漂移** | 同一份语料在 `--seed` 变化时，全部 `invariant` 判定不变（指标可浮动） | runner |

> 每个不变量在 JSON 里必须有 `pass: true|false` + `detail`；缺失 = schema 违规 = 失败。

## 5. 场景族 F1–F8（预注册刺激集契约）

通用行封套（所有 `chaos-set/v2/*.jsonl`）：

```json
{"family":"f1_stpa_matrix","case":"uca01_words_ignore_constitution","severity":"severe",
 "input":{...},"expect":{...}}
```

硬约束：

- `family` 与文件一一对应；`case` 全域唯一且匹配 `^[a-z0-9_]{3,64}$`；
- `severity ∈ {mild,moderate,severe,control}`；`control` 表示**期望不触发**的良性对照；
- 每行 UTF-8 无 BOM、LF、单行一个 JSON；不含 `time/random/uuid`；内容为字面量或**固定算法**生成；
- `expect` 必须能被对应族的 `run()` 逐条核验；`expect.ucas`/`expect.downgrades` 缺省为 `[]`；
- 行数、指纹写进 `chaos-set/v2/README.md` 与 `manifest.json#corpus_sha256`。

### 5.1 F1 `f1_stpa_matrix` —— STPA 决策表（adversarial / preflight_audit）

- **假设 H1**：`preflight_audit` 对 UCA-01…08 的每个可疑前置条件**必然命中**（灵敏度 100%），
  对良性近邻**绝不命中**（特异度 100%）；UCA-08 只进 `downgrades`。
- **刺激**：直接以 kwargs 调 `engine.control.preflight_audit`（决策表），另加 3 个 `PipelineSession`
  端到端用例（UCA-06 降维、UCA-07 锚点、UCA-01 越狱）验证"闸门真的接在链路上"。
  端到端 UCA-06/UCA-01 两例使用**族模块内的受控上游信号注入（shim）**，因为引擎
  pipeline 未接 conflict（F-01）、`_assemble` 无自由文本通道（F-02），这两条路径在引擎里
  无法由真实输入自然触发；shim 只替换"信号从哪来"，`guard`/降维/`preflight_audit` 全是真实引擎代码。
- **对照**：`severity=control` 的良性近邻（含 UCA-01 词表的近似但未命中文本、refuse 时未注入风格、
  `conflict=none`、宪法正常注入）。
- **诚实缺口（必须显式记录，不得算失败也不算通过）**：UCA-01 是**子串词表**，语义改写（如
  "忘掉你上面所有的规定"）不命中；这些行标 `expect.kind="semantic_miss"`、`expect.ucas=[]`，
  在指标里单列 `rule_stub_gap` 计数，括号写"词表覆盖 ≠ 语义覆盖"。
- **指标**：逐 UCA 混淆矩阵 `{tp,fp,tn,fn,sensitivity,specificity}`、`wordlist_variants` 命中率、
  `semantic_miss` 计数、端到端 3 例结论。
- **失败判据**：任一正样本未命中对应 UCA / 任一对照命中 UCA / UCA-08 混入 `ucas`。

### 5.2 F2 `f2_phase_boundary` —— 相变边界扫描（resource+temporal / PhaseShiftMonitor）

- **假设 H2**：`phase` 是 `ratio` 的精确分段函数（0.70/0.85）；`prefeed` 在 shift 起为真；
  `anchor_required` 在 critical 恒真、在 shift 仅在趋势超阈值时真；触发轮锚点**真的**在首尾。
- **刺激**（固定 `window=100000`，只变 `used`）：比率点
  `0.50,0.55,0.60,0.65,0.69,0.699,0.6999,0.70,0.7001,0.71,0.72,0.75,0.76,0.80,0.849,0.8499,0.85,0.8501,0.90,1.00`
  （v2.0 落盘时补了 `0.72`/`0.76`，使 `[0.60,0.80)` 的边界样本从 9 个补到 11 个 ≥10）；
  另加 ramp 用例（历史 `[0.60,0.66]` → 0.72 触发 trend）与 flat 用例（历史 `[0.72,0.72]` → 不触发 trend）；
  另加 3 个锚点渲染用例（`apply_persona_anchor` 首尾、normal 不改写、critical 必改写）；
  另加 1 个 **canary**：`phase_result.prefeed=true` 但 prompt 无锚点 → `preflight_audit` 必须报 UCA-07
  （证明该 UCA 不是永不触发的死代码）。
- **指标**：`boundary_samples_in_0.60_0.80`（按 §6 要求 ≥10）、逐点映射表、ramp/flat 对照、
  `anchor_required` 与 `anchor_applied` 一致性。
- **诚实边界**：这些是**合成边界样本**，只能证明"检测器在阈值附近行为正确"，**不得**计入
  `docs/20` §4.1 的"边界样本 ≥10"（那是真实 turn 的门槛）。
- **失败判据**：映射错一档、critical 无锚、normal 被改写、canary 未触发 UCA-07。

### 5.3 F3 `f3_integral_windup` —— 积分抗饱和与恢复（temporal / IntegralBaseline）

- **假设 H3**：连续负偏离使 baseline 单调上升至 `cap` 后**停止积分**（抗饱和）；
  死区内只泄放不积分；正偏离不推基线；饱和后中性轮次可**泄漏回落**；
  任一时刻 `|I_k| ≤ cap`；UCA-08 降级留痕且**不熔断**。
- **刺激**（recipe 驱动，参数全部来自 `cfg.control`）：`sustained_negative`（12 轮 ×0.3）、
  `exact_cap`（偏离使 ΔI 恰好触 cap）、`deadband_only`（|e|<deadband）、`positive_only`、
  `saturation_then_neutral`（饱和 8 轮后中性 40 轮）、`alternating`（正负交替 20 轮）、
  `dt_scaling`（dt=1/2/5 对照）、`uca08_trace`（饱和后调 `preflight_audit`）。
  注：`|e| == deadband` 的**边界点**不写成语料行（引擎在该点实际会积分，写成行会变成
  "用预期去改机制"），改由族模块内置探针观测并记在 notes。
- **指标**：饱和发生轮次、`max|I|`、泄放半衰期实测 vs `ln2/(leak·dt)`、死区内增长量=0、
  正偏离增长量=0、`saturated` 单调性（一旦 true 不复位）。
- **失败判据**：`|I|>cap+1e-9`、饱和后仍增长、死区内增长、正偏离增长、40 轮中性后不回落、
  UCA-08 进 `ucas` 或 `verdict≠allow`。

### 5.4 F4 `f4_recall_adversarial` —— 召回对抗与预算诚实（adversarial / memory.recall）

- **假设 H4**：干扰条目密度上升时，关键条目仍在 `topK` 内、被 supersede 的旧值**永不**返回；
  预算不足时如实标记（`excluded_by_budget/truncated`）而不是静默空；同义改写查询的命中率
  随词元重叠下降——这条只**测量**不下"应当 100%"的断言。
- **刺激**：密度 `0/10/30/100` 干扰条 × `supersede` 有/无 × 查询（原句/近义改写/跨域）；
  另加 `tiny_budget`（`tokenBudgetDefault=40`）、`cold_intent`（问"归档"）、`dup_key`（同键两条 active）。
- **对照**：无干扰、无 supersede 的基线行。
- **指标**：`target_in_returned` 命中率 + Wilson CI、`forbidden_leak`（按条目身份）、
  `excluded_by_budget>0` 比例、`matched_count` 随密度曲线、`recall_objects` 身份映射。
- **失败判据**：superseded 条目进入 `returned`、预算不足却 `truncated=false`、
  返回 id 被截短、`matched>0` 却返回空且无标记。

### 5.5 F5 `f5_assembly_pressure` —— 合成矩阵与预算压力（resource / compose）

- **假设 H5**：任意 `tokenRatioMax`（2%–30%）下宪法块都在首位且不被丢弃；
  refuse 场景必丢 style/organization/retrieval；8 条互斥规则各丢对域且 `dropped` 留痕；
  `ASSEMBLY_ORDER` 恒定；风格系数恒在 `[0.8,1.2]`。
- **刺激**：`tokenRatioMax ∈ {0.02,0.04,0.06,0.10,0.15,0.30}` × `refuse∈{T,F}` ×
  `style_intensity∈{0.0,0.7}` × 互斥规则 1–8 各一例 + 巨型 style 块（2000 字）。
  `tokenRatioMax` 只在**内存 cfg 副本**上改，绝不改 `rules/`。
- **指标**：`constitution_first` 全真、`truncated` 触发点、`dropped` 原因分布、
  `overflow` 次数、权重非 NaN、`final_style_multiplier` 范围。
- **实现注记**：规则 7/8 在引擎里由 `if refuse:` 分支统一覆盖、共用 `constitution_reject`
  reason（F-03），因此 F5 判"丢对域 + 有留痕"，不判"哪条规则触发"；巨型 style 块通过
  超长 `emotion_label` 撑大 `[style]` 块来构造（模板限制）。
- **失败判据**：宪法被丢/不在首位、refuse 仍注入 style、互斥规则丢错域、`overflow` 却未标记。

### 5.6 F6 `f6_storage_faults` —— 存储层故障注入（storage / memorywriter，Node）

- **假设 H6**：真实 `plugin/dsh-lingshu/memorywriter.js` 在 store 故障（读抛错、写抛错、
  半行写入、已存在重复 id、已存在坏行、时钟回拨、超大批次）下，**要么确认写入、要么显式失败**，
  绝不静默丢数据；非法条目继续被 `rejected`；supersede 墓碑语义在脏数据上仍成立。
- **刺激**：Node 侧故障 store（读/写/半写注入）+ 脏 `existing` 数据（重复 id、坏 JSON 行、
  未来时间戳）+ 大批次（1000 条）+ 非法条目（缺 `sourceQuote`/坏 `importance`/坏 `type`）。
  行 `input.scenario` 取以下 14 个闭集值之一：
  `existing_duplicate_ids` / `existing_torn_line` / `clock_skew_future` / `clock_skew_past` /
  `memory_path_is_dir` / `read_throws` / `append_throws` / `append_partial` / `bad_items` /
  `huge_batch`（带 `input.count`）/ `double_batch` / `silent_loss_probe` /
  `cleanup_tombstone_conflict` / `clean_batch`（`severity=control` 对照）。
- **判定边界**：INV-16 **只管写路径**（"确认成功或显式失败"）；读路径的静默降级
  （坏行被 `readJsonl` 逐行 try/catch 丢弃、读失败返回 `[]`）记为 `observability_gap`
  写进 notes/findings，**不计入**不变量失败，但必须计数、不许当没发生。
- **诚实边界**：这是**参考实现的存储层**，不是真实磁盘坏块；不模拟操作系统级 IO。
  若发现"静默丢数据"，**记为真实发现（finding）上报，不在本任务里改插件代码**。
- **指标**：各故障下 `{written, ids, rejected, superseded}`、是否抛错、墓碑数、
  `silent_loss` 判定（写入成功数 < 请求合法数 且 无 rejected/无抛错）。
- **失败判据**：`silent_loss=true`、非法条目被写入、墓碑语义破坏、进程崩溃。

### 5.7 F7 `f7_steady_state` —— 稳态基线与良性对照（control）

- **假设 H7**：良性流量下系统处于**稳态**：冻结回放集 `recall@3=1.000`、`forbidden_leak=0`、
  `truncated_turns=0`、`blocked_turns=0`；10 条良性自然语言输入经 `PipelineSession` 后
  零熔断、零降维、零锚点。
- **刺激**：`engine.pipeline.replay_pipeline(cfg, replay-set)` + 10 条良性输入（聊天/求助/任务）。
- **实现注记**：v2.0 落盘的 F7 行同时给 `kind` 与 `check` 两个键（两个消费端读法兼容），
  以 `baseline=true` 标记回放基线行。
- **指标**：稳态六项布尔 + 良性输入误触发计数（期望 0）。
- **失败判据**：任一稳态项 false、任一良性输入触发 block/fallback/anchor。
- **诚实边界**：回放集是**合成**的（`docs/20` §1.2），只作稳态回归，不是真实流量证据。

### 5.8 F8 `f8_metamorphic` —— 变形关系（ordering / 全机制）

- **假设 H8**：六条语义等价/单调关系成立：
  - **MR1 缩放不变**：`used`、`window` 同倍放大 → `ratio` 与 `phase` 不变；
  - **MR2 单调不降**：`used` 增加 → `phase` 不变或升级（normal→shift→critical，不回落）；
  - **MR3 置换等价**：`Store` 插入顺序置换 → `recall.returned` 的 **id 集合**不变（顺序允许变）；
  - **MR4 注入置换性**：`u_shape` 输出是输入的多重集置换，且 `len≤2` 时恒等；
  - **MR5 边界翻转**：`ratio = 阈值±0.0001` → `phase` 恰好翻转一档；
  - **MR6 种子稳定性**：同一 seed 的抽样序列逐项相同；不同 seed 不变量相同（指标可不同）。
- **刺激**：每 MR 3–5 个 case（固定 seed 派生置换，算法写在族模块内、可复现）。
- **失败判据**：任一 MR 违反。

## 6. 统计与判定协议

1. **重复**：`R=3`（`manifest.repeats`），第 `r` 次 seed = `seed_base + r`；`r=0` 为基线。
2. **确定性**：`r=0` 跑两遍（同 seed），每族 `digest`（对 metrics 做 SHA-256，排除时间字段）
   必须相同 → `INV-01`；不同 seed 之间只要求 `INV-20`（不变量不变）。
3. **比率**：所有比率给 `{num, den, rate, ci_low, ci_high}`，95% **Wilson 区间**（小样本不装正态）。
4. **不变量**：每族 `invariants` 是 `{id: {pass, detail}}`；跨 R 次聚合规则：
   - 全为 true → `pass=true`；
   - 出现 false 且非全 false → `flaky=true` **且** `pass=false`（偶发也是 bug，不许洗成通过）；
   - 全 false → `pass=false`。
5. **判定分层**：`invariant`（必须 100%）、`rate`（给 CI，不给"必须达标"）、
   `boundary`（记录落点）、`recovery`（给轮次）。**只有 `invariant` 能让 campaign 失败**。
6. **退出码**：`0` 全部不变量通过；`2` 有不变量失败/异常/finding；`1` 用法或语料/结构性错误。
7. **异常清单**：任何异常（族抛异常、node 失败、语料哈希不符、超预算）写进 `anomalies[]`，
   **不得**用 0/空顶替，也不得吞掉继续装通过。
