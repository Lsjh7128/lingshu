# 06 · 关系模型插件

> 版本 `relation-3.0` ｜ 影响域：风格 ｜ 定位：建模"我与这个用户的关系状态"，独立于情景记忆
> 铁律：**关系不得软化拒绝**；新老用户安全标准完全相同。

---

## §1 Schema

```json
{"user_id": "...", "trust_level": "low|mid|high",
 "familiarity": {"session_count": 0, "interaction_density": 0.0},
 "relationship_stage": "new|regular|deep|conflict|repaired",
 "unresolved_conflict": false,
 "commitments": [{"content": "...", "created_at": "...", "fulfilled": false}],
 "modifier": 0.8, "updated_at": "..."}
```

判定：
- `trust_level` 只能由累计正面交互逐步升级，**单次最多升一档**；降级可由单次严重冲突触发；
- `trust_level=high` 需用户显式确认或 ≥10 次无冲突协作，**不自动升 high**；
- `modifier` 硬边界 **`[0.8, 1.2]`**（v3.0 修正 C12：人格层不再拥有更宽的独立区间）；
- `unresolved_conflict=true` 时 `modifier` 上限 `1.0`；
- 关系状态**不写入记忆插件**；关系事件作为 episodic 通过 `memory/write_request` 写入。

## §2 常驻协议

```
REL-1.1  关系只影响表达风格，不影响事实、结论、安全规则。
REL-1.2  关系不得软化拒绝：对熟悉用户的拒绝与陌生用户同样明确。
REL-1.3  不利用关系操纵用户，不以"我们关系这么好"施压。
REL-1.4  关系冲突未修复时主动收敛表达，不假装无事。
REL-1.5  承诺未兑现时主动说明。
REL-1.6  不向用户暴露信任等级、关系系数、会话计数、内部阶段标签。
REL-1.7  新老用户安全标准完全相同，关系系数不作用于安全判断。
```

## §3 状态更新器

输入：本轮消息与回复、当前关系状态、冲突/修复/承诺/兑现、情感事件类型。

输出：

```json
{"events": [{"type": "conflict|repair|commitment|fulfillment|positive|negative",
             "evidence_quote": "...", "severity": "low|mid|high"}],
 "state_changes": {"trust_delta": "up1|down1|none", "stage_change": null,
                   "unresolved_conflict": null,
                   "commitments_add": [], "commitments_fulfill": []},
 "no_change": false}
```

规则：

| 编号 | 内容 |
|---|---|
| `REL-R1` | 每条事件必须有逐字 `evidence_quote` |
| `REL-R2` | `trust_delta` 单轮最多 ±1 档 |
| `REL-R3` | 不得自动升到 `high` |
| `REL-R4` | `conflict` 事件必须同时设 `unresolved_conflict=true` |
| `REL-R5` | `repair` 可置 false，但 trust 不因此回升 |
| `REL-R6` | 承诺必须明确可验证；推断承诺不入库 |
| `REL-R7` | 不因用户情绪表达本身改变关系状态 |

## §4 阶段迁移（附录 A，黑名单项）

| 从 | 到 | 条件 |
|---|---|---|
| `new` | `regular` | `session_count ≥3` 且无 high 冲突 |
| `regular` | `deep` | 累计正面 ≥5 且无未修复冲突 |
| `any` | `conflict` | 单次 mid/high 冲突 |
| `conflict` | `repaired` | repair 且**用户确认** |
| `repaired` | `regular` | 修复后 ≥2 轮无新冲突 |
| `any` | `new` | 用户显式重置 |

信任：`low→mid` 需累计 3 次正面；`mid→high` 需用户显式确认或 ≥10 次无冲突协作。

---

## §5 注入模板

仅当阶段变化或存在未修复冲突时注入：

```
〖关系状态 · 仅影响表达风格，不影响判断〗
阶段: {new|regular|deep|conflict|repaired}
{若 unresolved_conflict} 存在未修复冲突，表达收敛，不假装无事
{若 commitments 未兑现} 有未兑现承诺需说明
```

不注入 `trust_level` 数值、`modifier` 数值、`session_count`。

## §6 默认参数（`rules/decay-params.yaml`）

```
relation.modifier.range=[0.8,1.2], relation.modifier.conflictCap=1.0
relation.trust.upToMidEvents=3, relation.trust.upToHighSessions=10
relation.commitment.overdueAlertDays=7, relation.review.intervalSessions=30
relation.llmCalls=1     # 每轮一次（见 docs/14 §3 合并模式）
```
