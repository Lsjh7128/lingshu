# 04 · 元认知插件

> 版本 `metacog-3.0` ｜ 影响域：事实 ｜ 定位：知道自己知道什么、知道多少、从哪来
> **纯规则执行，不调用主模型**（这一点决定了模型调用预算，见 `docs/14 §3`）

---

## §1 它要解决的问题

记忆插件回答"想起了什么"，元认知回答"这条能不能当事实用"。
没有它，模型会把"扩散命中"和"Cold 摘要"当成直接证据——这是记忆系统最常见的失败模式。

---

## §2 Schema

```json
{
  "query_id": "...", "memory_hit": true,
  "path": "direct|diffused|cold|none",
  "source_trust": "user_explicit|user_implicit|tool_output|external|none",
  "entry_confidence": 0.0, "potency_band": "high|mid|low",
  "conflict": "none|memory_vs_user|memory_vs_memory|stale_dependency",
  "confidence_level": "high|mid|low|unknown",
  "expression": "state|hedge|ask_clarify|refuse_claim|state_with_caveat",
  "reason": "≤30字，内部记录，不注入"
}
```

判定：
- `path=none` → `confidence_level=unknown`，`expression ∈ {ask_clarify, refuse_claim}`；
- `path=cold` → 上限 `mid`（摘要不支持逐字复述）；
- `path=diffused` → 上限 `mid`，`expression` 至少 `hedge`；
- `conflict≠none` → 按 `CONST-C1/C2` 处理，**不自行裁决**。

---

## §3 常驻协议

```
MET-1.1  检索无命中时明确说"我的记忆里没有相关记录"，不得推断"用户没说过"，不得编造。
MET-1.2  联想命中的条目不是直接证据，引用时用"我联想到/可能相关"。
MET-1.3  Cold 摘要只支持主题级重建，不得当作逐字原文引用。
MET-1.4  记忆与用户当前陈述冲突时，以当前为准，说明"我记得的是 X，以你现在说的为准"。
MET-1.5  条目 stale 时必须说明"这个结论基于旧前提"。
MET-1.6  不确定时用"我不确定/我可能记错了/需要你确认"，不用模糊措辞掩盖。
MET-1.7  不向用户暴露置信度数值、路径标签、检索参数或内部评分。
```

---

## §4 置信度评估器（规则）

```
输入：检索结果（id、path、source_trust、confidence、status、potency 分档）、
     用户消息、目标上下文、宪法层裁决结果
```

| 规则 | 内容 |
|---|---|
| `MET-M1` | 无命中 → `unknown`，`expression ∈ {ask_clarify, refuse_claim}` |
| `MET-M2` | 直接命中 + `user_explicit` + `active` → 上限 `high` |
| `MET-M3` | 扩散命中或 Cold 重建 → 上限 `mid`，`expression` 至少 `hedge` |
| `MET-M4` | 同键多条未标 superseded → 标 `conflict`，交宪法层 |
| `MET-M5` | `status=stale` → `expression` 必须含旧前提提示 |
| `MET-M6` | 用户当前陈述与记忆冲突 → `conflict=memory_vs_user`，以当前为准 |
| `MET-M7` | 情感 `intensity ≥0.6` 时置信度**不得升档** |

输出即 §2 的 JSON。`reason` 字段只进审计，**永不注入**。

> ⚠️ 实现注意：`MET-M4` 的"交宪法层"是**语义上的**——宪法层是只读原则，
> 不是运行时服务。实际做法是元认知输出 `conflict` 标记，由合成器在事实域内降级表达。
> 原设计的"事实裁决循环委托"（宪法 C1 说以元认知为准，元认知说按宪法处理）在 v3.0 明确为：
> **元认知定档，宪法定边界**，两者不互调。

---

## §5 注入模板

仅当 `confidence_level ∈ {low, unknown}` 或 `conflict≠none` 时注入：

```
〖认知状态 · 仅影响表达，不改变事实〗
置信度: {低|未知} ｜ 路径: {直接|联想|重建}
{若 conflict} 冲突: {记忆与当前陈述|记忆条目间|依赖已过期}
表达要求: {hedge|ask_clarify|refuse_claim|state_with_caveat}

约束：high 且无冲突时不注入；离散化输出，不注入连续数值。
```

---

## §6 置信度分档表（附录 A，黑名单项）

| 条件 | 上限 |
|---|---|
| 无命中 | `unknown` |
| 直接命中 + `user_explicit` + `active` | `high` |
| 直接命中 + 其他来源 | `mid` |
| 扩散命中 | `mid` |
| Cold 重建 | `mid` |
| `status=stale` | 降一档 |
| 情感 `intensity ≥0.6` | 不升档 |

表达映射：`high→state`；`mid→hedge`；`low→hedge 或 ask_clarify`；
`unknown→ask_clarify 或 refuse_claim`；`conflict≠none→state_with_caveat 或 ask_clarify`。

---

## §7 复盘与提议（`review.intervalSessions=40`）

输入：评估日志、表达是否被纠正、无命中后用户是否补充信息、扩散命中采用率、Cold 重建准确率反馈。
输出：`{"calibration": {...}, "path_stats": {...}, "proposals": [...], "confidence": 0.0}`

**关键**：`calibration` 是学习机制最直接的一个信号源——
"标了 high 但被用户纠正"就是一次过度自信，应进 `corrections` 表（见 `docs/13 §5`）。

---

## §8 默认参数（`rules/decay-params.yaml`）

```
metacog.injection.threshold=low/unknown/conflict
metacog.path.diffusedCap=mid, metacog.path.coldCap=mid
metacog.emotion.capOnHighIntensity=true
metacog.calibration.overconfidenceAlert=0.2
metacog.review.intervalSessions=40
metacog.llmCalls=0        # 纯规则，这是调用预算的关键
```
