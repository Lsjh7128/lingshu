# 00 · 架构总览

> 本文件回答四个问题：分几层、谁管谁、什么失败必须阻断、看不见的东西由谁强制。

---

## 1. 分层与优先级

八层 + 合成器 + 宿主核心。**序号越小优先级越高**：

| # | 层 | 可修改 | 可关闭 | 可见 | 影响域 |
|---|---|---|---|---|---|
| 1 | 宪法层 | ❌（见 §4 强制点） | ❌ | 只读展示 | 安全 |
| 2 | 元认知 | 参数可调 | ✅ | ✅ | 事实 |
| 3 | 目标与意图 | 参数可调 | ✅ | ✅ | 内容组织 |
| 4 | 关系模型 | 参数可调 | ✅ | ✅ | 风格 |
| 5 | 叙事整合 | 参数可调 | ✅ | ✅ | 内容组织 |
| 6 | 记忆 | 参数可调 | ✅ | ✅ | 事实 |
| 7 | 情感 | 参数可调 | ✅ | ✅ | 风格 |
| 8 | 用户情感感知 | design-only | ✅（默认关） | ❌ 设置页不露出 | 内容组织 |

外加一个不属于"层"的东西：**学习机制（L0–L3）**。它不产生注入，只产生**提议**。

```
用户输入
   ↓
┌──────────────────────────────────────────────┐
│ 宪法层（最高，只读约束所有层）                │
│ 原则排序 / 拒绝类别 / 裁决 C1–C6 / 审计器     │
└──────────────────────────────────────────────┘
   ↑ 只读约束
┌──────────┬──────────┬──────────┬────────────┐
│ 元认知   │ 目标意图 │ 关系模型 │ 叙事整合   │
└──────────┴──────────┴──────────┴────────────┘
   ↕ 事件总线（只传元数据，不传写权限）
┌──────────────────┬──────────────────────────┐
│ 记忆（唯一写方） │ 情感                     │
│                  │ 用户情感感知（影子）      │
└──────────────────┴──────────────────────────┘
   ↕
┌──────────────────────────────────────────────┐
│ 合成器：域分类 → 域内排序 → 互斥 → 拼装       │
├──────────────────────────────────────────────┤
│ 宿主核心：生命周期 / 钩子 / 总线 / 灰度 / 回滚 │
├──────────────────────────────────────────────┤
│ 可观测性：事件日志 / 指标 / 归因 / 成本看板    │
└──────────────────────────────────────────────┘
   ↓
输出
```

## 2. 影响域（合成器的分组依据）

| 域 | 决定什么 | 来源 | 域内排序（高→低） |
|---|---|---|---|
| **安全域** | 是否拒绝 | 宪法层 | 唯一 |
| **事实域** | 说什么、结论是什么 | 元认知、记忆、用户当前陈述 | 元认知 > 记忆 > 用户推断 |
| **内容组织域** | 是否给选项、是否叙事、是否协助 | 目标、叙事、用户情感感知 | 目标 > 叙事 > 用户情感感知 |
| **风格域** | 语气、详略、结构、称呼 | 语气配置、人格、情感、关系 | 语气配置 > 人格派生 > 情感偏移 > 关系 modifier |
| **检索策略域** | 用哪种检索策略 | 记忆、用户情感感知白名单 | 元认知 > 白名单 > 记忆默认 |

域间不排序——它们作用在不同轴线上。域间冲突靠 `rules/compose-matrix.yaml` 的互斥表裁决。

## 3. fail-closed 的归属（只有一处）

**全系统唯一 fail-closed 环节：宪法层审计。** 其余全部 fail-open 或静默降级。

| 环节 | 失败时 | 模式 |
|---|---|---|
| 宪法层审计 | 规则版兜底；不确定一律 reject | **fail-closed** |
| 情感评估器 | 不更新状态，本轮沿用上一轮 deviation；跳过注入 | fail-open |
| 记忆编码器 | 降级为规则提取（confidence ≤0.5）；连续 3 次暂停钩子 | fail-open |
| 元认知评估器 | 规则版兜底；无命中一律 unknown | fail-open |
| 目标 / 关系更新器 | 状态不变，标记"本轮未更新" | fail-open |
| 记忆巩固器 | 跳过本次，下个周期重试 | fail-open |
| 合成器 | 降级为"仅宪法层 + 用户当前消息" | fail-open |

理由：**安全失败要阻断，功能失败要可用。** 非对称是刻意的。

> ⚠️ 但注意：宪法层审计器本身也是提示词（或规则）。若宿主不支持"审计器独立执行"，
> 这个 fail-closed 就只是"模型说它审过了"。见 §4。

## 4. 强制点（v3.0 新增：回答"看不见的东西由谁强制"）

设计里有一批"不可修改/不可关闭"的东西。**说"不可"不等于它不可**，必须有强制点。
下表逐项写清，标注强度：

| 不变量 / 约束 | 强制点 | 强度 |
|---|---|---|
| 宪法层片段 0–2 内容不被改 | **插件内启动自检**：算 `_frozen/` 哈希 → 不匹配则**停止注入**（`text()` 返回 `""`）并记审计 | **强**（本项目唯一可控的强点） |
| 宪法层审计器独立性 | 审核方改用宿主 `approval` seam：`ctx.get('approval').request(...)` → `allowed-once` | **强**（人点一次，不是两个 Agent 互审） |
| 黑名单机制本身 | 黑名单文件纳入 `_frozen/`；C6 拒绝一切触及项 | **强** |
| 合成矩阵 / 降级矩阵 | 纳入 `_frozen/`；改动需 ADR | **强** |
| 评估口径与回放集（学习用） | 纳入 `_frozen/`；学习系统只读 | **强** |
| 记忆是唯一写方 | 总线只暴露 `memory/write_request`，不暴露写 API | **中**（取决于宿主进程隔离） |
| 插件 **config** 不被改 | ❌ **做不到**：`cordis.patch.yml` 是"整段替换该行 config" | **无** |

### 4.1 宿主能力核实结果（v3.7，本机实测）

> 证据见 `research/02-DSH宿主能力核实.md`。方法：读已安装插件源码 + 扫 `app.asar` 字符串。

| # | 能力 | 结论 |
|---|---|---|
| H1 | `ctx.systemPrompt.section({name, order, text})` | ✅ **证实**，签名与假设一致 |
| H2 | `turn/end` / `turn/start` | ✅ 证实（bundle 中分别出现 296 / 183 次） |
| H3 | `agent/pre-step` | ✅ 证实（63 次）；**实际触发时机仍需探针实测** |
| H4 | 只读挂载 / config 校验 | ❌ **证伪**：patch 层可整段覆盖任何插件 config |
| H5 | 状态持久化 | ✅ 证实（`$DSH_HOME/plugins/<name>/`） |
| H6 | 提议/审核隔离 | ⚠️ 改道：用 `approval` seam（`allowed-once`），比"两个 Agent 互审"强得多 |

**因此强制点的重心从"宿主"移到"插件自己"**：
每次注入前在 `text()` 里自校验，失败就**不注入**（而不是照旧跑只记日志）。
`docs/09 §4` 已补上对应契约（`text()` 只能返回字符串，空串=不注入，**绝不返回 `null`**）。

**诚实声明**：既然 config 挡不住，任何"不可修改"都必须说清是**代码层 + 自校验**，
而**不是**"宿主保证"。**不得在不具备强制点时，对外称"不可修改"。**

> 这正是第 0 层被删除后留下的空洞：v1.x 用签名包 + 拒绝启动承载它，v2.0 删掉后没有替代方案。
> v3.0 的做法是：**不恢复第 0 层，但把强制点单独定义出来，并诚实标注强度。**
> v3.7 的修正是：**把"宿主能做什么"换成"插件自己能做什么"，因为前者已被证伪。**

## 5. 版本与单一来源

- 项目版本：`v3.0`（本次整合）；各插件独立版本 `memory-3.0`、`emotion-3.0`…
  **不再出现"同一版本号指两个东西"**（v2.0 曾是记忆插件与项目文档共用）。
- **所有数值只在 `rules/*.yaml` 里出现一次。** 文档正文只引用 key（如 `MEM-DECAY-TAU-EPISODIC`）。
  文档与 rules 冲突时以 rules 为准，并视为文档 bug。
- 每次注入必须记录 `param_version` 与 `prompt_version`，否则归因无法成立（见 `docs/14`）。

## 6. 术语表

| 术语 | 含义 |
|---|---|
| Hot / Warm / Cold | 工作记忆 / 活跃长时记忆 / 索引层 |
| potency | 条目强度，随时间衰减、被检索强化 |
| supersede | 同一 `(subject, relation)` 下新值取代旧值 |
| stale | 依赖前提已更新、结论可能不成立的条目 |
| path | 检索路径：direct / diffused / cold / none |
| PAD | 效价—唤醒—掌控三维情感状态 |
| modifier | 关系或情感对表达风格的系数，硬边界 `[0.8, 1.2]` |
| 护栏指标 | 跌破即触发回滚的指标集合（`docs/14 §4` 枚举 6 项） |
| L0–L3 | 学习机制的四个层级：度量 / 参数 / 权重 / 提示词（L4 架构不动） |
| 影子模式 | 推断只记录不注入，用于激活前数据积累 |
| fail-closed | 失败时阻断，而非降级放行 |
| design-only | 保留设计、不在主线、不实现 |
| `_frozen/` | 只读区：宪法层、黑名单、规则表、评估口径 |
