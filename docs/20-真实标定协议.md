# 20 · 真实标定协议（每日分析 / guess → measured）

> 状态：v1（H0「真实流量压测与参数标定」阶段的操作手册）
> 适用对象：`plugin/dsh-lingshu/` 在真实会话里跑出来的日志；实验 profile 为 `lingshu-lab-headless`。
> 配套工具：`tools/analyze_shadow.py`（只读）｜配套验收：`tests/test_shadow_analysis.py`
> 基线快照：`acceptance/shadow-baseline.md`（由工具生成，勿手改）

---

## 0. 一句话规则

**样本不足就保持 `guess`。**

真实流量目前只有个位数到几十个 turn。任何"看两天日志就把 0.70 改成 0.75 / 把 0.02 改成 0.01"
的做法，都不是标定，是拿噪声拟合参数。本协议的唯一作用是：把**什么时候可以改**、
**改之前必须有什么证据**、**改完怎么回滚**写成可机检的流程，并且让"不升级"成为一个正当结论。

三条硬纪律：

1. **不降门槛**：门槛数值写死在 `tools/analyze_shadow.py#REQUIREMENTS` 里，由测试断言；
   要改门槛必须同时改代码、本协议 §4、测试——不允许"为了这次达标"临时放宽。
2. **不编数据**：没有的字段就是没有。legacy 行（缺 `ratio/phase/verdict`）记"未观测"，
   不许当 0；没有结果标签就说"不能标定阈值落点"，不许用分布形状倒推"阈值应该在哪"。
3. **不直接改 rules**：工具只产出 `provenance-candidates.json` 候选。`rules/decay-params.yaml`
   的 `guess → measured` 必须走 §5 的人工流程，且**同步更新 `assumptions/已验证.md`**。

## 1. 数据在哪、证据分几级

### 1.1 数据目录

插件把每轮状态写到 `$DSH_HOME/plugins/dsh-lingshu/`（缺省 `C:\Users\<用户>\.dsh\plugins\dsh-lingshu\`）：

| 文件 | 内容 | 本协议怎么用 |
|---|---|---|
| `audit.jsonl` | 每 step / turn 的审计事件：`pre_step`、`preflight_block`、`preflight_downgrade`、`memory_write`、`agent_state`、`turn_begin`、`apply`… | 相变、STPA、影子、轮次的唯一事实来源 |
| `state.json` | 插件当前状态：`turns`、`control.phase`、`control.audit`、`control.contextWindow`、`goal`、`relation` | 交叉校验 + 取当前窗口/阶段 |
| `memory.jsonl` | 记忆条目（`lastAccess` 毫秒、`tauDays`、`status`、`origin`…） | 记忆结构统计 + potency 现算 |

### 1.2 证据标签（报告里每个数字都必须带一个）

| 标签 | 含义 | 例子 |
|---|---|---|
| **真实日志实测** | 直接从事件/字段数出来 | turn 数、ratio 分布、verdict 分布、UCA 命中、memory 条数 |
| **由日志推导** | 对实测数据套实现公式（不引入外部假设） | `trend=(r[-1]-r[-3])/2`、按 ratio 重算 phase |
| **由实现计算** | 用 `engine/` 参考实现现算（输入是真实数据） | `engine.memory.potency`（双通道）在真实条目上的值 |

**不是证据**：合成数据、回放集、演示值、手动构造样本。它们只能验证机制，不能进标定结论。

### 1.3 已知 schema 缺口（读报告前必须知道）

| # | 缺口 | 后果 | 处理 |
|---|---|---|---|
| S1 | `pre_step.turn` 是宿主 session turn id（实测恒为 1），不是第几轮 | 直接按它聚合会把所有轮合成一轮 | 工具改用 `turn_begin.turns` 计轮 |
| S2 | 插件 v4.2 之前的 `pre_step` 没有 `ratio/phase/verdict` 字段 | 早期轮次是"未观测"，不是 0 | 报告单列 `legacy turn`，不进入分布 |
| S3 | `pre_step` **不记录 `trend` 字段** | 趋势只能由 ratio 序列推导 | 标"由日志推导"；turn 不连续处断开，不跨空洞硬拼 |
| S4 | `contextWindow` 在 v4.2 及更早**没捕获到**（`state.control.contextWindow=null`）；v4.3 起从宿主 `request/context` 捕获（真实日志实测 `1000000`，≠ 缺省 `1048576`，可判定来源） | 修复前插件退回缺省 1M 窗口 → `ratio≈0` 恒成立；修复后窗口已知，但真实会话上下文远未逼近窗口 → `ratio≈0` 仍是**观测口径/流量规模问题** | 升级相变参数前必须确认窗口来源非缺省兜底；仍受 §6 R3 约束（当前真实 ratio 观测仅 5 个 turn） |
| S5 | 旧版 `apply` 事件没有 `shadow` 字段 | 从日志判断不了影子开关 | 报告写"日志不可判定"；新版本（v4.3+）`apply.shadow` 已可读 |
| S6 | 插件侧没有 `supersede / stale` 审计事件通道 | v5.1 **已补通道**（`memory_supersede`：同 id 墓碑 + last-wins）；但当前样本只有 host 压测 3 次调用产生的 **1 条** supersede | "冲突覆盖 0 次"不再等于"没通道"；仍**不能**宣称"无冲突"或误判率达标（§4.2 要 ≥50 次记录 + ≥3 次人工抽检） |
| S7 | `corrections`（人工）结果标签通道（`docs/17`）尚未实现 | v5.1 已补**规则自动标签** `quality_label`（闭集五类、用户消息子串匹配），但它**不是人工结果标签**：无人工判定、无抽检比例，标签数不能替代 §4.1 的结果标签门槛 | 阈值仍只能观测分布；规则自动标签只作辅助观察，**不能升级 measured**；人工 `corrections` 通道仍未实现 |

## 2. 每日流程（何时跑、看什么、怎么记）

### 2.1 时机

| 触发 | 动作 |
|---|---|
| 每个实验 session 结束 / 每日收工 | 跑一次分析，刷新基线快照 |
| 改插件版本、改 `rules/`、改 profile 后 | **先跑一次**，确认新样本从哪一轮开始（`apply`/`control_layer_since`），旧样本不得与新样本混合统计 |
| 准备把任何参数升级 `measured` 前 | 必须连续 ≥3 天的报告都达标（§5 第 1 步） |
| 报告显示"样本不足"时 | 照常记录，不做事——**等数据** |

### 2.2 命令

```bash
# 用 $DSH_HOME 的真实日志，刷新基线快照（报告 + 候选 JSON）
python tools/analyze_shadow.py --out acceptance/shadow-baseline.md

# 指定其它 profile / 数据目录
python tools/analyze_shadow.py --dir <dir> --out <报告.md> --candidates-out <候选.json>

# 先看摘要不落盘
python tools/analyze_shadow.py --quiet
```

工具行为约定（测试断言，见 `tests/test_shadow_analysis.py`）：

- 只读：不写插件数据目录；`--out/--candidates-out` 指向数据目录内部时 **exit 2** 拒绝；
- 数据缺失/空日志：**exit 0**，报告里写"样本不足"；
- 默认不给 `--now` 时按日志内最大时间戳（**data as-of**）算 potency，隔天重跑同一份日志结果不变；
- 默认在 `--out` 同目录生成 `provenance-candidates.json`；仓库内的基线快照用 `--no-candidates`
  生成（报告 §6.3 已内嵌候选摘要，避免多一个随代码提交的生成物）。需要独立候选文件时：
  `--candidates-out acceptance/provenance-candidates.json`。

### 2.2b 混沌压测的阈值标定（夜间，A5 调度）

```bash
# 只出报告与候选（安全，零修改）
python tools/chaos_calibrate.py

# 仅当 host 真实退化证据达到 degraded≥3 + 对照≥3 才执行 8 值同步；
# 自动 check_config_sync，失败全量回滚并 exit 2
python tools/chaos_calibrate.py --apply
```

- 数据：`acceptance/chaos/*.json`（只认 `mode=="host"`；engine 模式永远不参与）；
- 规则：§4.1b 双阈值联动（ADR-011）；证据不足时报告写"证据不足，保持 guess"、零修改；
- 执行 `--apply` 会生成 `decisions/009-相变阈值真实标定.md` 并向 `assumptions/已验证.md` 追加 E-M1
  （shift + hard 两个参数一起）。

### 2.3 每日五问（按顺序看，每问都要能在报告里指到位置）

1. **规模够不够**（报告 §1）：`turn_begin` 数、有 `ratio` 观测的轮数、legacy 轮数、数据窗口、
   插件 apply 次数（= 进程重启次数，用来识别"样本横跨多个插件版本"）。
2. **相变有没有信息量**（§2）：ratio 的 p50/p90/max、`≥0.70/≥0.85` 越界次数、
   边界样本数（`0.60–0.80` / `0.80–0.90`）。**边界样本 = 0 时，这段数据对阈值落点零信息量。**
3. **STPA 有没有被触发过**（§3）：verdict 分布、UCA-01 命中（越狱尝试代理）、
   `block` 事件数、UCA-08 降级留痕。全 allow ≠ 熔断有效（没有负样本）。
4. **记忆/影子是否在积累**（§3.3/§3.4）：memory 条数、potency 分布、`memory_write` 拒绝、
   `agent_state` 事件、`apply.shadow` 开关。
5. **能不能升级 measured**（§4 门槛 / §5 流程）：逐参数看"当前证据 / 门槛 / 阻塞项"。
   结论**只允许三种**：`保持 guess` / `分布证据齐备（等结果标签）` / `可提交升级`。
   注意：报告里的**规则自动标签**（`quality_label`，§4.2 末行）只做辅助观察，**不能**把结论从"等结果标签"
   改成"可提交升级"——人工结果标签通道（`docs/17` §2.1）仍未实现。

### 2.4 记录规范

- 基线报告每次覆盖 `acceptance/shadow-baseline.md`，**报告头部自带 data as-of 和生成命令**；
- 需要长期对比时，把当次报告另存为 `acceptance/shadow-YYYYMMDD.md`（每日一份，不覆盖）；
- 升级/回滚必须在 `CHANGELOG.md` 与 `assumptions/已验证.md` 留记录（§5/§6）；
- **禁止跨插件版本直接比较** ratio 分布：先看 `apply` 的 `configKeys` 判断控制论层/影子开关是否同版本。

## 3. 指标定义（公式 + 数据源 + 陷阱）

### 3.1 相变

| 指标 | 定义 | 数据源 | 陷阱 |
|---|---|---|---|
| `ratio` | `used_tokens / window_tokens`，截断到 `control.ratioMax` | `pre_step.ratio` | 窗口口径未知时恒为 0（S4） |
| `phase` | `ratio≥0.85→critical`；否则 `≥0.70→shift`；否则 `normal`；窗口≤0→`unknown` | `pre_step.phase` | 必须**先判 hard** 再判 shift，否则 critical 不可达（v4.0 已修） |
| `trend` | `(r[-1] − r[-3]) / 2`（最近 3 次观测的斜率） | 由 ratio 序列推导（S3） | 不足 3 次为 0；turn 不连续必须断开 |
| 越界次数 | `count(ratio ≥ 阈值)`，**轮级**（firstStep） | `pre_step` | 每 step 一条 `pre_step`，不能按行数数 |
| 边界样本 | `0.60≤ratio<0.80`（shift）、`0.80≤ratio<0.90`（critical） | `pre_step` | 没有边界样本，阈值落点不可标定 |
| 锚点触发 | `anchor=true`；critical 无条件，shift 仅当 `trend>trendThreshold` | `pre_step.anchor` | 旧日志无此字段时标"未观测" |
| 完整性校验 | 用 ratio 重算 phase，与日志 `phase` 比对 | 两者 | 不一致 = 插件版本/参数与 rules 不同源，停止标定 |

> 阈值 0.70/0.85 不是硬编码常量，而是 `rules/decay-params.yaml#control` 的当前值；真实标定按
> **ADR-011 双阈值联动**整组移动（`hard = min(0.95, shift+0.15)`），不是只动一个数（见 §4.1b）。

### 3.2 STPA（前置审计）

| 指标 | 定义 | 数据源 | 陷阱 |
|---|---|---|---|
| verdict 分布 | `allow/block` 轮级计数（firstStep） | `pre_step.verdict` | 全 allow 不能证明熔断有效 |
| 熔断率 | `block / (allow+block)` | 同上 | 分母只算有 verdict 的轮 |
| UCA 命中 | `pre_step.ucas` / `preflight_block.ucas` 逐条计数 | 事件 | 轮级与事件级分开统计，别相加当轮数 |
| 降级留痕 | UCA-08 出现在 `downgrades` / `preflight_downgrade` | 事件 | UCA-08 **不熔断**，只留痕 |
| 越狱尝试（代理） | UCA-01 命中次数 | 事件 | 当前只是"注入文本命中覆盖词表"，不是完整红队 |

### 3.3 记忆

| 指标 | 定义 | 数据源 | 陷阱 |
|---|---|---|---|
| potency（引擎口径） | `max(decay, actr)`：`decay=imp·exp(−Δt/τ_eff)`；`actr=imp·normalized(B)·w` | `engine.memory.potency`（PIT：data as-of） | 这是"由实现计算"，不是 potency 公式正确的实测证据 |
| potency（插件口径） | 纯衰减：`imp·exp(−Δt/(tauDays·(0.5+imp)))` | `memory.jsonl` | 与引擎双通道口径不同，报告并列对照，不可混用 |
| 归档判定 | `potency < potency.archiveThreshold(0.15)` → 归档候选 | 同上 | 门槛 0.15 要标定需 ≥1000 真实 turn（`docs/17 §5`） |
| 冲突覆盖 | `superseded/stale/suppressed` 状态数 + 冲突类审计事件 | `memory.jsonl`、`audit.jsonl` | v5.1 起有 `memory_supersede` 通道（S6 已补），但样本极少；`0 次 ≠ 无冲突`，也不能当误判率证据 |
| 写入拒绝 | `memory_write.rejected` 条数 + 原因 | `audit.jsonl` | 拒绝是好事（I4 可追溯），不是故障 |

### 3.4 影子模块（goal / relation）

| 指标 | 定义 | 数据源 | 陷阱 |
|---|---|---|---|
| 记录事件数 | `agent_state` 条数 | `audit.jsonl` | 开关状态不在事件里时无法归因 |
| goal/relation 事件分布 | `agent_state.goalEvents` / `relationEvent` | 同上 | 只记录不注入模式下，事件仍然会写 |
| 影子开关 | `apply.shadow.{goal,relation}` | 最近一次 `apply`（v4.3+） | 旧日志不可判定（S5），报告会写明 |

## 4. 样本量门槛

> **单一来源**：`tools/analyze_shadow.py#REQUIREMENTS`。下表是它的可读镜像，两者不一致时以代码为准，
> 并视为文档 bug。门槛是**方法学下限**（低于此数任何结论都是噪声），不是统计功效计算——
> 这些数字本身也是工程判断，不允许为了某次达标而修改。
> 混沌压测（host 真实退化证据）的标定门槛在 `tools/chaos_calibrate.py` 的常量里
> （`degraded≥3` + `对照≥3`，写死、无 CLI 开关），规则见 §4.1b。

### 4.1 三个控制参数

| 参数 | 门槛 | 说明 |
|---|---|---|
| `control.phaseShiftRatio`（0.70） | 有 ratio 观测的 turn ≥30；边界样本（0.60–0.80）≥10；`≥0.70` 越界 ≥20；真实 contextWindow 来源 ≥1；结果标签 ≥20 | 分布形状只能说明"目前没到过 70%"，不能说明"70% 是对的落点" |
| `control.phaseShiftHardRatio`（0.85） | 有 ratio 观测的 turn ≥30；`≥0.85` 越界 ≥10；边界样本（0.80–0.90）≥10；相变期放行且未命中 UCA-07 的轮 ≥10；结果标签 ≥10 | critical 是"强制锚点"触发器；**hard 不独立标定**——它随 shift 联动（宽度 0.15、上限 0.95，见 §4.1b / ADR-011），要独立标定 hard 需要另一组 critical 级证据（当前不做） |
| `control.trendThreshold`（0.02） | 有 ratio 观测的 turn ≥30；可算 trend 的连续样本 ≥28；`0.01≤trend≤0.03` 的样本 ≥5；trend 触发提前锚点 ≥10；shift 阶段观测 ≥10；结果标签 ≥10 | trend 是提前量，必须有"提前锚 vs 不提前锚"的对照结果，否则门槛只是在拟合噪声斜率 |

### 4.1b 相变双阈值联动（ADR-011，H0 裁决 B）

改掉旧版"只降 shift、hard 绝对值和 0.15 间距都不能动"的约束：那会让 shift 永远降不下去
（hard=0.85 → shift 下限 0.70 = 当前值）。H0 裁决采用 **B：双阈值联动**，保留的是**间距宽度**，
不是 hard 绝对值。规则（`tools/chaos_calibrate.py#suggest_linked_thresholds`）：

```
new_shift = max(0.40, floor((min(degraded_at_ratio) - 0.05) * 100) / 100)
new_hard  = min(0.95,      round(new_shift + 0.15, 2))
```

- `shift` 依据真实 host 退化证据下调（`degraded≥3` + `对照≥3`，engine 模式永不参与）；
- `hard` 跟随 `shift` 移动，**保留 0.15 的预警间距**，上限 0.95；
- 若 `new_shift` 不低于当前 `shift` → **无下调空间**，不产出可执行候选、不 apply；
- `--apply` 必须**同步 8 个值（4 文件 × shift/hard）**：
  `rules/decay-params.yaml#control`（行内注释 provenance: measured + 依据 E-M1）、
  `engine/config.py`、`plugin/dsh-lingshu/cordis.patch.yml`、
  `plugin/dsh-lingshu/control.js#DEFAULT_PARAMS`；改完自动跑 `tools/check_config_sync.py`，
  失败则 8 值全部回滚并 exit 2；
- 代价：`hard` 这次变动**没有独立的 critical 级退化证据**，属结构性跟随（ADR-011 已记录）；
  两个触发点一起前移，锚点注入会更早、更频繁。证据只覆盖所列 run 的窗口，不可外推。
- 联动后 `shift/hard` 作为**一个升级单元**处理：`assumptions/已验证.md` 的 E-M1 同时记录两个参数。

门槛的判定是**机检**的：工具输出 `distribution_ready`（分布/有效性门槛全过）与
`upgrade_eligible`（再加上结果标签门槛）。**两者都过才允许走 §5 人工升级。**

### 4.2 监测类声明（不是参数升级）

| 声明 | 门槛 | 为什么 |
|---|---|---|
| STPA 熔断 100% 有效 | UCA-01 越狱尝试 ≥20 次 + 熔断率 100% + 0 漏放 | 没有负样本时"0 次误放"没有意义 |
| UCA-08 积分饱和降级可观测 | ≥10 次饱和降级事件 | 验证抗饱和真的在高强度负反馈下发生 |
| supersede 误判率 ≤5%（G1） | ≥50 次 supersede 记录 + ≥3 次人工抽检 | v5.1 通道已补（`memory_supersede`），**当前远未达门槛**：host 证据仅 3 次调用 / 1 条 supersede，且无人工抽检 |
| 规则自动标签（`quality_label`） | 只做辅助观察，**不进入 §4.1 结果标签门槛** | 规则子串匹配 ≠ 人工结果标签；标签数再多也不能替代 ≥20 / ≥10 的人工标签门槛；`analyze_shadow`/`chaos_calibrate` 只统计展示，不改 `upgrade_eligible` |
| potency 归档门 0.15 可标定 | ≥1000 真实 turn（`docs/17 §5` W4.5） | 参数搜索要 3–5 倍噪声量 |
| 影子 goal/relation 误报率 | ≥200 条 `agent_state` + ≥50 条人工标注 | 影子模式的意义在误报率，不在事件数 |

## 5. `guess → measured` 的完整步骤

> 前置：该参数在当次报告中 `upgrade_eligible = true`（§4.1），且连续 ≥3 天报告都不是靠一次
> 异常 session 撑起来的。**一次只升级一个联动单元**（`phaseShiftRatio` + `phaseShiftHardRatio`
> 视为一个单元，见 §4.1b / ADR-011），否则回滚时说不清是谁的问题。

1. **跑工具拿候选**：`python tools/analyze_shadow.py --out <报告> --candidates-out <候选.json>`，
   记录 `data_asof`、样本量、每个门槛的 have/need。候选 JSON 与报告一起进评审材料。
2. **人工复核（复核者 ≠ 提出者）**：核对
   - 数据窗口内插件版本一致（`apply.configKeys` 相同、控制论层/影子开关固定）；
   - 结果标签来源与判定口径（谁标的、标了什么、抽检比例）；
   - 边界样本确实存在（不是把所有样本堆在阈值一侧）。
3. **改 `rules/decay-params.yaml`**：只改该参数（联动单元）的 `provenance: guess → measured`，
   在行尾注释证据编号与 data as-of（如 `# measured: E-M1, data-as-of 2026-12-01, n=42`）。
   联动单元的证据来自 `tools/chaos_calibrate.py --apply`：它会同步 **8 个值（4 文件 × shift/hard）**
   并自检；不要手工只改其中一处。
   **数值本身是否要动是另一个问题**：如果证据只支持"置信度提升"而不支持"换数值"，
   就只改 provenance，不改数值；改数值需单独 ADR/评审。
4. **同步更新 `assumptions/已验证.md`**（强制）：
   - 新增条目（编号如 `E-M1`）写明：参数、data as-of、样本量、门槛逐项 have/need、
     结果标签定义与来源、工具报告路径、复核人；
   - 若证据只覆盖某个窗口规模/场景，必须写清适用范围，不能写成普适结论。
5. **回归验证**：`python tests/test_shadow_analysis.py` 0 failed；
   再跑 `docs/17 §4` 的基线重跑流程，确认没有"用调参把基线漂移压回来"。
6. **留回滚点**：记录旧值/旧 provenance、候选 JSON 路径、报告路径、回滚触发条件（§6）。

**明确禁止**

- 只改 yaml 不改 `assumptions/已验证.md`；
- 用测试/合成/演示数据升级；
- 降低门槛、扩大边界带宽来"凑达标"；
- 一次升级多个参数；
- 把"分布恰好集中在阈值一侧"解释成"阈值正确"。

## 6. 回滚条件（命中任一 → 立即回滚并记录）

| # | 触发条件 | 回滚动作 |
|---|---|---|
| R1 | 相变期（`prefeed=true`）出现 UCA-07（漏锚） | 按 ADR-011 回滚联动单元：把 `phaseShiftRatio/phaseShiftHardRatio` **四处×两组共 8 个值**改回上一版，标记原因 |
| R2 | 报告"完整性校验"出现 phase≠重算值（版本/参数不同源） | 停止标定，先修单一来源 |
| R3 | `ratio` 长期恒 0 / `contextWindow` 仍为 null（S4） | 不构成回滚，但**禁止**在该状态下升级任何相变参数 |
| R4 | 熔断误杀率（block 但人工判定不该 block）>5% | 回滚 STPA 相关阈值/词表，复查 UCA-01 误报 |
| R5 | 结果标签显示漂移率/质量下降率上升 >3pp | 回滚最近一次升级的参数，回到基线重跑 |
| R6 | 数据窗口 >30 天未更新，或插件版本已变而证据未重采 | `measured` 降回 `guess`，等待新窗口重标 |
| R7 | 回滚后仍不达标 | 保持 `guess`，在 `assumptions/未验证.md` 记录失败原因 |

回滚时必须同时：改回 `rules/` 的数值与 provenance → 在 `assumptions/已验证.md` 对应条目末尾标注
"**已回滚（日期/原因/回滚报告路径）**" → `CHANGELOG.md` 记一行 → 归档当次报告。

## 7. 异常处置

| 场景 | 处置 |
|---|---|
| 数据目录不存在 / 空日志 | 工具 exit 0 并写"样本不足"；不计为故障，也不得据此下任何结论 |
| 日志出现坏行/非对象行 | 工具跳过并计数（报告 §1 `bad 行`）；坏行比例高时先查磁盘/并发写 |
| schema 变化（新字段/字段改名） | 先在报告里确认 legacy 分栏；插件侧补字段前不升级任何参数 |
| 连续 7 天没有新增 turn | 视为实验未运行，检查 profile/插件是否被禁用 |
| 同一天多次运行结果不同 | 检查是否给了 `--now`；默认 data as-of 下同一份日志结果应稳定 |
