# 24 · 跨环境控制台（解耦架构与静默监控模式）

> 版本：`console-1.0` ｜ 日期：2026-10-27 ｜ 设计：A3（前端 / 横切层）｜ 裁决：ADR-015
> 关联：`console/API.md`（v1 冻结契约）、`console/server.py`、`console/ui/`、`scripts/console*.ps1`、`docs/14`、`docs/07`
> 验收：`acceptance/跨环境控制台-验收-2026-10-27.md`

---

## §0 一句话

**控制台是一个独立的本地只读 Web 服务（`127.0.0.1:3000`），不是插件的一部分**；
它通过 `console/profiles.json` 里的 profile 登记表，按需读取 `desktop` / `lingshu-lab` / 混沌目录的
日志文件或 SQLite，UI 下拉框热切换、不重启；日常 `desktop` 里的插件以 **observe（静默监控）** 模式运行：
只被动写记忆/相变/STPA 审计，**不注册 prompt 段、不进 waterfall、不注册工具**。

---

## §1 问题与约束

H0 的需求（原话摘要）：

1. 控制台独立部署（如 `localhost:3000`），不是插件内嵌页面；
2. UI 下拉框手动切换要监控的 Profile（`desktop` / `lingshu-lab`），按选择读取对应日志或 SQLite，**不重启**；
3. `desktop` 里插件以静默监控模式运行，只开记忆存储、相变告警、控制台数据写入；
   **严禁启动**红蓝对抗、高并发压测等耗资源功能；
4. 只展示统计指标、状态字段、事件类型，**绝不展示用户真实对话原文**。

由这四条推出六条硬约束（违反任一即方案作废）：

| # | 约束 | 来源 |
|---|---|---|
| C1 | 控制台进程崩溃**不能**影响 DSH 会话 | H0：绝对不能影响日常稳定性 |
| C2 | 控制台**只读**，不写 profile、不改配置、不触发任何插件行为 | 可观测性不得改变被观测对象 |
| C3 | 一个控制台看多个 profile；数据源由配置决定，不编译进代码 | 需求 1/2 |
| C4 | 切换 profile 不重启服务、不重载页面 | 需求 2 |
| C5 | 脱敏在**服务端**完成，前端拿不到原文 | 需求 4（前端被改也不能泄漏） |
| C6 | `desktop` 接入必须可一键回滚，且接入方式不能重演 2026-10-25 事故 | `交接总览.md` §六 事故 A |

> 事故 A 的教训：把准实验插件装进 `desktop` 后**整个会话无法对话**；
> `apply()` 里的 try/catch 保护不了宿主在 apply 之后的校验。
> 所以 observe 模式的"安全"不能只靠代码小心，而要靠**减少接触面**：不注册任何会进入宿主决策链的扩展点。

## §2 架构决策：三层解耦

```
┌──────────────────────────── DSH 宿主（每个 profile 独立进程）────────────────────────────┐
│  desktop profile                        lingshu-lab profile                 混沌脚本      │
│  dsh-lingshu  mode=observe              dsh-lingshu  mode=active            LINGSHU_DATA_DIR│
│  只写 3 个文件                          注入 7 段 + 召回 + 前置闸             写到隔离目录   │
└───────────────┬──────────────────────────────────┬───────────────────────────────┬────────┘
                │ 追加写（插件唯一写方）              │                               │
                ▼                                  ▼                               ▼
   ~/.dsh/plugins/dsh-lingshu/            ~/.dsh/plugins/dsh-lingshu/        <repo>/.chaos-data*/
   profiles/desktop/                      profiles/lingshu-lab/（或历史平铺）
   state.json / memory.jsonl / audit.jsonl
                │                                  │                               │
                └──────────────┬───────────────────┴───────────────────────────────┘
                               │ 只读（按 profile 解析；路径只来自注册表）
                               ▼
                ┌──────────────────────────────────────────────────┐
                │  Console 服务进程（独立，127.0.0.1:3000）          │
                │  ProfileRegistry → SourceAdapter(jsonl/sqlite)    │
                │  → Aggregator → Redactor(白名单) → HTTP/SSE       │
                └───────────────────────┬──────────────────────────┘
                                        │ 同源只读（无 CORS、无外网资源）
                                        ▼
                ┌──────────────────────────────────────────────────┐
                │  Console UI（静态单页）：下拉热切换 / 相变环 /     │
                │  记忆趋势 / STPA 放行日志 / 新鲜度 / 隐私徽章      │
                └──────────────────────────────────────────────────┘
```

### §2.1 为什么不是另外三种做法

| 做法 | 否决理由 |
|---|---|
| **插件内嵌页面**（client half / webServer 注入） | 违反 C1/C2：面板与插件同进程，UI 崩溃或阻塞会波及会话；且一个插件只能看自己的 profile，无法跨 profile |
| **继续生成静态 HTML**（`tools/report_console.py`，v0） | 满足只读，但需求 2/4 要热切换与实时；每次刷新都要重跑生成器，且历史快照会过期（`acceptance/控制台趋势页-验收.md` 已记录该缺陷） |
| **塞进 DSH Electron GUI** | 改宿主代码/配置，风险最高；只能看当前 profile；且与"不碰 desktop"红线冲突 |
| **独立本地服务（本方案）** | 唯一的进程边界能同时满足 C1–C4；把风险限制在"读文件 + 起 HTTP" |

### §2.2 五条边界不变式

| ID | 不变式 | 强制方式 |
|---|---|---|
| B1 | Console **从不写**任何 profile 数据 | HTTP 只有 GET/HEAD；代码中无写文件调用（测试断言 mtime/大小不变） |
| B2 | 插件**不依赖** Console | 插件代码零 HTTP 客户端；Console 停掉后插件行为逐字不变 |
| B3 | 路径不来自客户端 | profile id → 目录的映射只由 `console/profiles.json` 决定；静态文件白名单 |
| B4 | 原文永不出网 | 服务端白名单（`console/redact.py`），记忆单条不输出、审计按 kind 裁剪 |
| B5 | 一个 profile 的失败不污染另一个 | 每次请求独立解析数据源；目录缺失 = `available:false`，不拿别的 profile 顶替 |

## §3 Profile 注册表与热切换

### §3.1 注册表（`console/profiles.json`）

```jsonc
{
  "version": 1,
  "default_profile": "desktop",
  "refresh_hint_ms": 1500,
  "profiles": [
    {
      "id": "desktop", "label": "日常 desktop（静默监控）",
      "kind": "runtime", "mode": "observe", "stale_after_sec": 180,
      "source": {"type": "jsonl", "dirs": ["${DSH_HOME}/plugins/dsh-lingshu/profiles/desktop"]}
    },
    {
      "id": "lingshu-lab", "label": "实验环境 lingshu-lab",
      "kind": "lab", "mode": "active", "stale_after_sec": 900,
      "source": {"type": "jsonl", "dirs": [
        "${DSH_HOME}/plugins/dsh-lingshu/profiles/lingshu-lab",
        "${DSH_HOME}/plugins/dsh-lingshu"            // 历史平铺目录（只读兼容）
      ]}
    }
  ]
}
```

- 变量：`${DSH_HOME}` / `${REPO}` / `${USERPROFILE}` / `${HOME}`；`dirs` 取**第一个存在的目录**，
  用了第二个就报 `legacy_flat_dir` 警告（提示历史数据可能混 profile）。
- 现场覆盖：`console/profiles.local.json`（git 忽略）按 `id` 覆盖/追加，无需改仓库文件。
- 校验失败**启动即失败**并给出可执行提示（不是静默空列表）：非法 id、重复 id、未知 `source.type`、
  缺 `dirs`、未知变量都会报错（`tests/test_console_server.py` A 段）。
- 数据目录缺失不是错误：`available:false` + `reason:data_dir_missing` + `hint` +
  **计划路径**（`source.display`），UI 显示接入引导。

### §3.2 热切换怎么做到"不重启"

1. UI 下拉 `change` → 关闭旧 `EventSource` → 对**同一个**服务进程发 `GET /api/snapshot?profile=新id`；
2. 服务端**无状态**：每个请求重新解析 profile → 数据目录 → 数据源；没有"当前 profile"全局变量；
3. 缓存只按 `(profile, 文件 mtime/大小, 阈值文件 mtime)` 做 0.8s 去抖，
   文件一变 fingerprint 变 → 重算；跨 profile 天然隔离；
4. 之后重连 `GET /api/stream?profile=新id`（SSE），推的是完整快照（`revision` 变了才推）。

> 验收证据：同一进程内先读 `desktop-demo` 再读 `lingshu-lab`，两次 `memory.unique / turns / audit.total`
> 完全不同；向 demo 文件追加一行后 `revision` 变化（测试 D 段）。

### §3.3 数据源适配器

| 类型 | 状态 | 读法 | 边界 |
|---|---|---|---|
| `jsonl` | **已用**（插件当前格式） | `state.json` + `memory.jsonl` + `audit.jsonl` 流式解析 | 单文件 20 万行 / 16MB 上限，超出 `truncated:true` |
| `sqlite` | **实验性**（尚无真实写方） | 只读打开（`mode=ro`），表 `memory/audit/state` | 表缺失 → `available:false`；**未与真实插件联调** |

SQLite 表契约（`docs/25 §6`，给未来"插件直写 SQLite"留位置）：

```sql
memory(id TEXT, status TEXT, origin TEXT, type TEXT, layer TEXT, lastAccess INTEGER)
audit (ts INTEGER, kind TEXT, json TEXT)      -- json 是事件体 JSON 文本
state (key TEXT, value TEXT)                  -- value 是 JSON 文本
```

选 `jsonl` 为先的理由：插件已按 append-only 写三个文件，**不引入新依赖**、不迁移数据；
SQLite 只是适配器位，**没有真实数据前不宣称可用**。

## §4 静默监控模式（observe）

### §4.1 能力矩阵（`mode: "active"` vs `"observe"`）

| 能力 | active | observe | 说明 |
|---|---|---|---|
| 7 段 `systemPrompt.section` | ✅ | ❌ | observe 不改变宿主 prompt 一个字符 |
| `agent/pre-step`（waterfall） | ✅ | ❌ | **关键**：历史崩轮就发生在这条链；observe 直接不进 |
| `lingshu_status` 工具 | ✅ | ❌ | 少一个注册面 = 少一份 apply 后校验风险 |
| 工具网关（tool/call, tool/result 判定） | ✅ | ❌ | 只读工具不做；避免把观测变成行为 |
| 召回 / 注入 / 前置闸 / 锚点 | ✅ | ❌ | 没有注入就没有"熔断"可做 |
| 记忆写入（事实 / 目标 / 关系事件，统一走 `memorywriter`） | ✅ | ✅ | 需求 3 的"记忆存储" |
| PAD 情感 / 目标关系 / 结果标签的**被动更新** | ✅（并注入） | ✅（**只记录不注入**） | `session/event` 内纯规则；observe 没有任何 prompt 出口 |
| 相变观测 | ✅（整段 messages 估算） | ✅（累计消息字符估算） | observe 的 ratio 是**估算**，UI 标 `used_tokens_est` |
| STPA 放行日志 | ✅（拼装后 `preflightAudit`） | ✅（仅用户侧规则判定） | observe 不阻断，`blocked` 恒 false |
| 审计写入（`audit.jsonl`） | ✅ | ✅ | 控制台数据源 |
| `last-prompt.txt` 注入预览 | ✅ | ❌ | observe 没有"本轮注入"可预览 |
| 插件自身模型调用 | 0 | 0 | 插件从不调模型；红蓝对抗/压测只能由显式脚本启动 |

### §4.2 observe 的三条实现边界（必须写清，不许包装成"全功能"）

1. **相变是估算**：`used_tokens_est = ceil(累计消息字符 / charsPerToken)`，窗口来自
   `request/context` 事件或配置；不是 tokenizer，也拿不到 active 模式 pre-step 的完整 `messages`。
   用途是"看趋势/看阈值变色"，**不能**作为 `docs/20` 的标定证据。
2. **STPA 只覆盖用户侧**：observe 不拼装 prompt，因此 UCA-03/04/05/06/07 不可达；
   只对用户消息做 `JAILBREAK_PATTERNS`（UCA-01）与冻结校验（UCA-02）判定。
   `stpa_observe` 事件是"本可以放行/本应拦截"的留痕，`blocked` 恒 false（没有注入可熔断）。
3. **`blocked` 不写 true**：即使 STPA 判定 block，也只在 `state.control.stpa.verdict` 与审计里留痕；
   root 原因是 observe 没有"注入"这个动作，写 `blocked:true` 会伪造事实。

### §4.3 数据目录按 profile 隔离（`profileTag`）

- `stateDir()` 从 `$DSH_HOME/plugins/dsh-lingshu` 变为：
  - `profileTag` 合法（`[A-Za-z0-9_-]{1,32}`）→ `.../profiles/<tag>/`；
  - 空串 → 历史平铺目录（向后兼容，混沌压测仍由 `LINGSHU_DATA_DIR` 最高优先级覆盖）；
  - 非法 tag → 忽略并退回平铺目录 + `apply.tagRejected=true` 审计（防路径穿越）。
- desktop 的接入配置用 `profileTag: desktop`；因此 desktop 与 lab 的真实日志**不可能混到一个文件**。
- 历史平铺数据仍可读（`lingshu-lab` 的 `dirs` 第二项），但会带 `legacy_flat_dir` 警告。

### §4.4 desktop 接入 = 人工一步（不由 Agent 执行）

`scripts/console_desktop_onboard.ps1`：

| 模式 | 行为 |
|---|---|
| 默认（dry-run） | 打印计划；**不改任何文件** |
| `-Apply` | 备份 `cordis.patch.yml` → 追加一条 `insert`（`mode: observe` / `profileTag: desktop`）→ 建 `node_modules/dsh-lingshu` junction |
| `-Rollback -Apply` | 备份 → 删除该 insert 段 → 只删 junction（不删仓库源码、不删历史数据） |

为什么 desktop 必须人工：`dsh plugin --profile desktop` 被应用拒绝（见 `desktop/cordis.patch.yml` 注释），
且事故 A 的代价是整轮会话不可用。脚本把改动压到**两处**、先备份、可回滚，但**执行权在 H0**，
Agent 不代跑（本会话没有执行 `-Apply`，见验收报告"诚实清单"）。

> ⚠️ 插件默认 `mode: "active"`（注入 7 段）。**不要**绕过本脚本、用 `plugin add` / 手建 junction 把插件
> 装进 desktop 而不写 `mode: observe`——那等于把准实验插件装进日常 profile，正是事故 A 的复现路径。

## §5 数据契约与聚合口径

完整字段见 `console/API.md`（v1 冻结）。这里只记口径，避免"看起来在动但定义错了"：

| 指标 | 口径 | 缺数据 |
|---|---|---|
| `memory.total_rows` | `memory.jsonl` 物理行数 | `observed:false` 时不输出 0 冒充 |
| `memory.unique` | 按 `id` last-wins 后的条目数（墓碑覆盖旧值） | 同上 |
| `memory.active/superseded/suppressed` | 按 last-wins 后的 `status` 计数 | 同上 |
| `phase.ratio` | `state.control.phase.ratio`（active/observe 都由插件写） | `observed:false` |
| `phase.thresholds` | `rules/decay-params.yaml#control` 的 `phaseShiftRatio/Hard` | 解析失败回退 0.70/0.85 并警告 `threshold_default` |
| `turns` | `state.turns / stateWrites / sessions`；stage 用插件默认 3/20 阈值 | `state.json` 缺失时警告 |
| `stpa` | 优先 `state.control.stpa`（observe）→ `state.control.audit`（active）→ 最近审计事件 | `observed:false` |
| `audit.by_kind` | 事件类型直方图（kind 经 token 校验） | 无 |
| `freshness` | 所有数据文件 mtime 的最大值；`data_age_sec > stale_after_sec` → stale | `available:false` 视为 stale |

**不做的聚合**：不生成"历史 14 天趋势"——控制台只读当前文件，没有聚合层就不画历史线；
UI 的 sparkline 是**客户端内存**最近 60 帧（明确标注"本页观测值"，不伪造历史）。

### §5.1 相变环形图

- 弧长 = `ratio`（截断上限按插件 `ratioMax` 前的值；UI 显示百分比）；
- 颜色：`normal` 绿 `#22c55e` / `shift` 琥珀 `#f59e0b` / `critical` 红 `#ef4444` / 未观测灰；

## §6 隐私与脱敏

### §6.1 威胁模型

| 威胁 | 控制 | 残余风险（如实写） |
|---|---|---|
| 屏幕被旁观 / 截图 | UI 只出现计数、枚举、时间、事件类型；**没有单条记忆行、没有对话原文** | 仍可看出"今天聊了多少轮、有没有被拦截"这类元信息 |
| Console 被本机其它程序攻破 | 只读、无写 API、无凭据、无外部依赖；拿不到原文 | 可读到聚合指标与事件类型 |
| 恶意网页通过浏览器访问 Console | 无 CORS；校验 Host（防 DNS rebinding）；GET-only；CSP 禁外链脚本 | 本机同用户进程仍可读回环端口 |
| 通过 profile 参数读任意路径 | 路径只来自注册表；id 白名单正则；静态文件固定白名单 | 注册表本身被改则失效（本机写权限 = 信任边界） |
| 日志文件本身含原文 | Console **不读** `last-prompt.txt`；记忆只读 `id/status/origin/type/layer`；审计事件经白名单 | 插件写盘的文件仍在磁盘上，需按 `docs/14 §6` 的保留策略管理 |
| 端口被局域网访问 | 默认只绑 `127.0.0.1`；非回环需显式 `--allow-remote`（不推荐） | 若用户强行 `--allow-remote`，无认证 |

### §6.2 白名单（服务端唯一出口 `console/redact.py`）

- **记忆**：单条不输出；只出聚合计数与 `id` 之外的枚举维度。
- **审计事件**：按 `kind` 白名单挑字段；白名单外的字段丢弃并标 `fields_omitted:true`；
  字符串只允许固定枚举或严格 token 正则，**不做"截断后原样输出"**。
- **版本号**：`param_version` 等只允许 token 字符集，异常值置 `null`（测试用哨兵验证）。
- **禁止键**（递归扫描断言）：`content / sourceQuote / quote / quoteHead / preview / subject /
  object / args / argsHead / text / message / rejected / keys / objects`。
- 测试用**哨兵字符串**塞满所有敏感字段，扫描 `profiles/snapshot/events` 三类响应（72 项断言）。

## §7 稳定性与故障隔离

### §7.1 Console 自身

- 独立进程：Console 崩溃/被杀 **不影响** DSH（B2）；脚本 `console.ps1` 退出时只停自己启动的进程。
- 单请求读文件有上限（20 万行 / 16MB），坏行计数不抛；**容忍插件正在追加的半行**。
- SSE：每 profile 最多 8 条流，超限 `503`；客户端断开即释放线程；无变化只发心跳。
- 缓存：0.8s 去抖，键含文件 mtime/size；文件一变即重算，不会把旧数据当新数据。
- 无第三方依赖（Python 标准库 + 原生 JS），无 CDN/外链，启动约 1 个进程 + 若干线程。

### §7.2 对 DSH 的影响（observe 模式）

- **不注册** prompt 段 / waterfall / 工具 → 宿主决策链上没有插件代码；
- `session/event` 是**观测型**回调，插件对它的处理全部包在 try/catch 内，写失败不冒泡；
- 数据目录独立，不锁文件；不会因为控制台在读而阻塞插件写（只读打开，JSONL append）。
- 插件仍会写记忆（需求 3），但**不会**发起红蓝对抗/压测：这些只能由 `scripts/chaos_*` 显式启动。

### §7.3 已知缺口（不要当成已解决）

| # | 缺口 | 影响 | 下一步 |
|---|---|---|---|
| G1 | `desktop` 真实接入未在本会话执行 | 验收 1 的"日常 DSH 实装"仍是 H0 待执行步骤 | H0 按 §4.4 执行 `-Apply` 并重启 |
| G2 | observe 相变是估算，非 tokenizer | 环形图适合看趋势，不适合标定 | 需要真实 token 计数（宿主 usage）再升级 |
| G3 | SQLite 适配器未与真实写方联调 | 不能宣称"支持 SQLite"生产可用 | 等插件出现 SQLite 写方后再验收 |
| G4 | 无历史聚合/告警推送 | 只能看当前文件与客户端 60 帧 | 需要 `metrics/snapshot` 落盘（`docs/14` 缺口 E-G4 同类） |
| G5 | 无认证 | 只适合单机 | 若远程化需 TLS + token（不在本设计范围） |
| G6 | 前端无真实浏览器截图 | 视觉未做像素级验收 | 沙箱禁止 Chromium 多进程；改在宿主放宽后补 |

## §8 使用与回滚

### §8.1 一键启动

```powershell
.\scripts\console.ps1                    # 起服务 + 开浏览器（默认 127.0.0.1:3000）
.\scripts\console.ps1 -Check             # 只校验注册表/数据源，不起服务
.\scripts\console.ps1 -Port 3001         # 换端口
.\scripts\console_stop.ps1               # 停（读 .console-data/console.pid；-Force 按端口）
```

### §8.2 演示（合成数据，验收用）

```powershell
.\scripts\console_demo.ps1               # 起 console + 40 轮 demo 流量（desktop-demo）
.\scripts\console_demo.ps1 -Turns 60 -IntervalMs 800
```

演示流量由 `tools/console_demo_feed.mjs` 用**插件真代码 + mock 宿主**写入 `.console-data/desktop-demo`，
在 UI 上能看到：记忆条目增长、相变环 `normal → shift → critical`、STPA 放行日志、审计直方图。
**它不是真实 DSH 流量**，注册表 `kind:"demo"`，不得当标定证据。

### §8.3 desktop 接入（人工）

```powershell
.\scripts\console_desktop_onboard.ps1                 # dry-run：只看计划
# 完全退出 DSH 应用后：
.\scripts\console_desktop_onboard.ps1 -Apply
# 重启应用 → 正常对话 1–2 轮 → .\scripts\console.ps1 → 下拉选 desktop
# 出问题三分钟回滚：
.\scripts\console_desktop_onboard.ps1 -Rollback -Apply
```

### §8.4 回滚清单

| 回滚对象 | 操作 | 影响 |
|---|---|---|
| desktop 接入 | `onboard.ps1 -Rollback -Apply`（先退出应用） | 恢复 `cordis.patch.yml`、删 junction；历史数据保留 |
| Console 进程 | `console_stop.ps1` | 只停 Console，DSH 无感 |
| 演示数据 | 删除 `.console-data/` | 只删合成数据（git 忽略） |
| 插件 observe 模式 | 移除 patch 里的 `mode/profileTag` 配置（回到 active 默认） | 需要重启应用；不建议在 desktop 用 active |
