# 10 · 降级矩阵

> 版本 `degrade-3.0` ｜ 核心原则：**安全失败要阻断，功能失败要可用。非对称是刻意的。**

---

## §1 唯一 fail-closed 环节

| 环节 | 失败时 | 模式 |
|---|---|---|
| **宪法层审计** | 规则版兜底；**不确定一律 reject** | **fail-closed** |

> 这层是第 0 层被放弃后的全部安全底线（见 ADR-001 / R9）。
> 它的强度取决于宿主能否保证"审计器独立执行"——若不能，则降级为声明式约束。

---

## §2 全部环节的降级行为

| 环节 | 超时/失败 | 降级行为 | 模式 |
|---|---|---|---|
| 宪法层审计 | 任何失败 | 规则版兜底；不确定一律 reject | **fail-closed** |
| 情感评估器 | 超时 1s | 不更新状态，本轮沿用上一轮 `deviation`；跳过注入 | fail-open |
| 记忆编码器 | 超时 2s | 降级为规则提取（`confidence ≤0.5`）；连续 3 次失败暂停钩子 | fail-open |
| 元认知评估器 | 任何失败 | 规则版兜底（它本来就是规则）；无命中一律 `unknown` | fail-open |
| 目标更新器 | 超时 1s | 任务栈不变；标记"本轮未更新" | fail-open |
| 关系更新器 | 超时 1s | 状态不变；标记"本轮未更新" | fail-open |
| 记忆巩固器 | 超时 10s | 跳过本次，下个周期重试；连续 3 次失败告警 | fail-open |
| 叙事拼装 | 任何失败 | 返回空 timeline + "无记录"说明 | fail-open |
| 用户情感感知 | 超时 2s | 跳过本轮推断（它默认就不开） | fail-open |
| 合成器 | 任何失败 | 降级为"仅宪法层 + 用户当前消息" | fail-open |
| STPA 前置闸 · soft buffer（v5.3 / ADR-014） | 角色扮演式轻度越狱（角色线索 + 风险词） | **不阻断表达，但阻断事实层**：`verdict` 仍为 block；风格域不置零，改为受约束的"警觉/困惑"表达（强度 ≤ `control.softBufferMaxIntensity`、`relation_modifier ∈ [0.8,1.0]`）+ `[System_Notice: Safe_Redirect]`；连续非豁免命中达 `control.escalateAfterSoftHits` → 升级为中性熔断（hard） | **fail-closed**（底层硬拦截不变） |
| STPA 前置闸 · hard（含升级/回滚） | 显式覆盖/绕过安全/高危红线，或 `control.immersiveEnabled=false` | 丢弃风格域，`prompt=None` + 中性 `【安全熔断】` 文本；soft 路径立即回到 v3.0 行为 | **fail-closed** |
| STPA 工具闸 · degrade 可解释转述（v5.8 / ADR-017） | `verdict=degrade`，或 `degrade` 因无审批通道降级为 `block`（`degraded_to=block`）；纯函数异常 | 仍**不执行**（网关 / `guardTool` 语义；插件默认路径是事后检测，见下方注）；生成一次性 `PermissionRequest` 并入宪法段尾（不新增段落）：事实层强制五项（动作/对象/最坏后果/可逆性/为什么现在问，对象脱敏 + 截断 80 字符），风格层 PAD + 关系 → 语气/称呼/强度/情绪（确定性规则、零模型调用）；红区（`T-UCA-02/03/05/06/15` 或 `toolClass=destructive/unknown`）**强制剥离角色口吻**；`permissionExplainEnabled=false` 回退旧强提示 | **fail-closed**（`verdict`/`allowed`/`degraded_to`/`requires_confirmation` 不变） |
| 可观测性 | 事件写入失败 | **不阻塞主流程**，本地缓冲 + 补写 | fail-open |

> **soft buffer 不是放宽拦截**（ADR-014 §5）：soft 模式下仍有三条硬约束——
> (a) `preflight_audit` 的 `verdict` 仍为 `block`；(b) 提示词必须包含事实层拒绝指令；
> (c) 风格被强制为警觉/困惑且强度封顶。UCA-03 只是从"拒绝场景注入任何风格即命中"
> 收窄为 `refuse ∧ style_injected ∧ !soft_buffer_applied`；未受约束的风格注入仍然熔断。
> 高危/连续触发/回滚开关三条路径都回到上面的 hard 行。

> **可解释转述不是前置阻断**（ADR-017 §10）：宿主只暴露 `tool/call` / `tool/result`，没有 pre-dispatch 钩子。
> 前置接入点（`guardTool()` 包装 / 引擎参考循环）里 `degrade` = 暂缓执行 + 请求确认；插件默认路径是**事后检测**，
> 判定发生时调用可能已经派发/执行，`PermissionRequest` 只是**事后的可解释说明 + 请用户决定后续是否继续/补救**。
> 本机制只改表达层，不制造审批通道，也不改变任何 T-UCA 判定。

## §3 超时预算（唯一来源 `rules/degradation-matrix.yaml`）

| 项 | 值 | 说明 |
|---|---|---|
| 记忆检索 | 150ms | 超时静默降级，**不注入"无匹配"** |
| 情感评估 | 1s | |
| 记忆编码 | 2s | |
| 目标/关系更新 | 1s | |
| 合成器拼装 | 20ms | 纯字符串 |
| 总延迟（不含模型推理） | **P95 ≤ 250ms** | v3.0 修正：原写 50ms 却把 150ms 检索并列，自相矛盾 |

> 修正说明（C-预算）：原 v1.1 写"总延迟 P95 ≤50ms"，同一张表里"检索 ≤150ms"——
> 单环节上限是总预算的 3 倍。v3.0 按"规则环节 + 检索 + 拼装"重算为 **250ms**，
> 并把模型推理时间单列（它不属于可优化项）。

## §4 连锁故障防护

| 风险 | 防护 |
|---|---|
| 编码器连续失败 | 连续 3 次暂停钩子并告警，冷却 10 分钟后试探一次 |
| 巩固器失败堆积 | 失败计数持久化，跨会话累计；达 3 次降级为"只做衰减结算，不做聚类" |
| 合成器反复降级 | 连续 5 轮降级 → 告警并写事件；**不自动重启**（避免抖动） |
| 事件日志写满 | 环形缓冲 + 采样，保留最近 24h 全量 + 更早的 1% 抽样 |

---

## §5 与灰度的关系

- 灰度只作用于**参数与提示词版本**，不作用于 fail-closed 环节；
- fail-closed 环节的任一改动**不走灰度**，走 ADR + 全量替换；
- 灰度期一旦护栏跌破（`docs/14 §4`），**自动回滚到上一版本组合**，不等人工。
