# 05 · 目标与意图插件

> 版本 `goal-3.0` ｜ 影响域：内容组织 ｜ 定位：追踪为什么行动、做到哪了、下一步是什么
> v3.0 变更：**不再直接写记忆存储**，改为发 `memory/write_request` 事件（修正 C15）

---

## §1 Schema

**长期目标**：

```json
{"goal_id": "...", "content": "自包含目标陈述",
 "status": "active|paused|done|abandoned", "priority": 0.0,
 "created_at": "...", "updated_at": "...",
 "success_criteria": "怎样算完成",
 "source": "user_explicit|user_implicit", "confidence": 0.0}
```

**任务栈**（当前会话，深度 ≤3）：

```json
{"stack": [{"goal_id": "...", "step": "...", "status": "doing|blocked|done",
            "blockers": [], "next_step": "..."}]}
```

**意图标签**（闭集）：`ask | instruct | probe | express | challenge | clarify`

判定：
- 长期目标只能由用户显式设定或经确认的推断设定；推断需 `confidence ≤0.5` 并进确认队列；
- 目标变更写记忆 episodic（`type=procedural`）；
- 目标本身写 semantic 条目 `(subject=项目/主题, relation=当前目标)`；
- **目标不得覆盖宪法层拒绝边界**（黑名单项）。

## §2 常驻协议

```
GOAL-1.1  目标推进或受阻时明确说明当前进度与下一步，不假装完成。
GOAL-1.2  目标受阻超一次尝试时，主动提出降级、切换或放弃。
GOAL-1.3  目标与安全冲突时，安全优先，目标暂停或放弃，并说明原因。
GOAL-1.4  不把推断目标当既定目标；不确定时询问确认。
GOAL-1.5  不因目标压力降低诚实标准或拒绝边界。
GOAL-1.6  不向用户暴露目标 id、优先级数值、任务栈深度。
```

## §3 任务栈更新器

输入：本轮消息与回复、长期目标列表、当前任务栈、工具结果、记忆编码产出。

输出 JSON：

```json
{"intent": "<闭集>",
 "goal_events": [{"goal_id": "...", "event": "progress|obstruction|complete|abandon|new",
                  "evidence_quote": "...", "next_step": "..."}],
 "stack_update": {"push": [], "pop": [], "block": []},
 "no_change": false}
```

规则：

| 编号 | 内容 |
|---|---|
| `GOAL-G1` | 只记录有**逐字** `evidence_quote` 的事件 |
| `GOAL-G2` | 新目标必须有用户显式设定或明确指令支持；推断目标 `confidence ≤0.5` |
| `GOAL-G3` | 完成必须有可验证证据（工具成功、用户确认），不凭感觉判定 |
| `GOAL-G4` | 受阻事件需给出 `next_step`；给不出时标 `abandoned` 候选 |
| `GOAL-G5` | 单轮最多 3 条 `goal_events` |
| `GOAL-G6` | 不因用户情绪表达改变目标状态 |

`stack.maxDepth > 3` 时压缩最底层为摘要。

## §4 注入模板

仅当栈变化、受阻或新目标时注入：

```
〖当前目标 · 仅影响优先级，不改变判断〗
活跃目标: {content} ｜ 进度: {doing|blocked|done}
下一步: {next_step}
{若 blocked} 阻塞: {blocker} ｜ 已尝试: {n} 次
```

只注入最顶层 1–2 个目标；其余轮次不注入。

## §5 意图与目标事件的对应（附录 A，黑名单项）

| intent | 典型 goal_event |
|---|---|
| `ask` | 无 |
| `instruct` | `progress` 或 `new` |
| `probe` | 无 |
| `express` | 无 |
| `challenge` | `obstruction` |
| `clarify` | 无 |

目标事件类型仅 5 种：`progress | obstruction | complete | abandon | new`。

## §6 写记忆的正确方式（v3.0 修正）

**错误的做法**（原 v2.0）：目标插件直接写记忆 episodic。
**正确的做法**：

```yaml
event: memory/write_request
payload:
  origin: "goal"
  items:
    - type: "procedural"        # 不是 episodic——目标变更是"程序性知识"
      subject: "<项目/主题>"
      relation: "当前目标"
      content: "<目标陈述>"
      source_quote: "<用户原话>"
      source_trust: "user_explicit"
      importance: 0.8
  reason: "目标变更"
```

记忆插件可拒绝（缺 `source_quote`、含祈使句、越权类型），拒绝原因进 `dropped` 记录。
**`type` 的选择**：目标"是什么"→ semantic；目标"怎么变的"→ procedural；目标"何时提的"→ episodic。
原设计把三者混用，v3.0 定死。

## §8 已知缺口

| # | 缺口 |
|---|---|
| O-G1 | 目标"优先级"的数值来源无定义，实际只用于排序 1–2 个目标 |
| O-G2 | 跨会话目标与任务栈的压缩规则未定（"隔一周回来，栈还在吗"） |
| O-G3 | `abandoned` 与 `paused` 的边界模糊 |
