# 07 · 叙事整合插件

> 版本 `narrative-3.0` ｜ 影响域：内容组织 ｜ 定位：把条目串成"我的经历"的时间线与因果链
> 铁律：**仅用于查询时拼装，不自动生成叙事文本，不覆盖记忆条目，不持久化。**

---

## §1 Schema（临时生成，不落库）

```json
{"thread_id": "...", "topic": "...",
 "timeline": [{"at": "...", "entry_id": "...", "summary": "≤30字",
               "event_type": "decision|change|conflict|repair|milestone|failure"}],
 "causal_links": [{"from": "...", "to": "...", "type": "caused_by|supersedes", "confidence": 0.0}],
 "arc": "≤60字主题弧描述", "confidence": 0.0, "sources": ["<entry_id>"]}
```

判定：
- `timeline` 每个 entry 必须来自实际记忆条目，不得虚构；
- `causal_links` **只使用记忆已有边，不新建边**；
- `arc` 是组织方式，不是事实；引用 `arc` 时必须同时给出源条目；
- **不持久化**（不写记忆、不写文件）。

---

## §2 常驻协议

```
NAR-1.1  叙事是组织方式，不是新事实；每个节点必须可追溯到记忆条目。
NAR-1.2  不推断未记录的因果；只能陈述时间顺序，除非记忆中有 caused_by 边。
NAR-1.3  叙事与条目冲突时以条目为准。
NAR-1.4  缺失时间段明说"这段时间我没有记录"，不脑补。
NAR-1.5  不生成叙述性长文；按时间线列要点，附来源。
NAR-1.6  不向用户暴露 thread_id、arc 内部标签、因果置信度数值。
```

---

## §3 时间线拼装器

**触发条件**：查询含时间/演变/历史语义，或用户显式要求回顾。普通信息查询不触发。

触发词（闭集）：`上次 / 之前 / 后来 / 怎么走到 / 演变 / 历史 / 回顾 / 时间线 / 总结一下 / 梳理一下 / 复盘一下`

规则：

| 编号 | 内容 |
|---|---|
| `NAR-N1` | `timeline` 按时间戳升序，最多 `12` 个节点 |
| `NAR-N2` | 每个节点必须有 `entry_id`，不得虚构 |
| `NAR-N3` | `causal_links` 只从记忆已有边中提取，不新增 |
| `NAR-N4` | 缺失时间段显式标注 `gap` |
| `NAR-N5` | `arc` 只在节点 ≥3 时生成；`confidence` 取所有源条目 confidence 最小值 |
| `NAR-N6` | 元认知 `confidence_level=unknown` 时不拼装，返回空 timeline 并说明无记录 |
| `NAR-N7` | 情感、关系、目标状态**不参与叙事事实** |

---

## §4 与合成器的互斥关系

| 冲突组合 | 规则 |
|---|---|
| 目标 `blocked` × 叙事触发 | 叙事不触发（除非用户显式要求回顾） |
| 宪法层拒绝 × 叙事触发 | 叙事不触发（拒绝场景不注入） |
| 元认知 `unknown` × 叙事触发 | 不拼装（`NAR-N6`） |

---

## §5 复盘指标（`review.intervalSessions=40`）

```json
{"accuracy": {"user_corrections": 0, "untraceable_nodes": 0},
 "gap_ratio": 0.0, "causal_misread": false, "proposals": [], "confidence": 0.0}
```

`untraceable_nodes` 必须恒为 0——出现即 bug，不是调优对象。
`user_corrections` 进 `corrections` 表（`docs/13 §5`），是叙事准确性的唯一地面真值。

---

## §6 默认参数（`rules/decay-params.yaml`）

```
narrative.timeline.maxNodes=12, narrative.timeline.arcMinNodes=3
narrative.trigger.requireTimeSemantic=true, narrative.gap.explicitLabel=true
narrative.persist=false, narrative.review.intervalSessions=40
narrative.llmCalls=0     # 不调模型：拼装是纯规则 + 已有边
```

> `llmCalls=0` 是 v3.0 明确的一条：原设计没说叙事是否调模型，但它只需要
> "按时间排序 + 过滤 trigger + 附 entry_id"，全部可规则化。**这是把 5 次调用压到 3 次的关键之一。**

## §7 已知缺口

| # | 缺口 |
|---|---|
| N-G1 | `arc` 若用模型生成，会引入"文档里没有的东西"——建议 v3.1 改为模板化 |
| N-G2 | 多主题并行时间线如何切分，未定义 |
| N-G3 | `confidence` 取源最小值过于保守，会系统性低估长叙事 |
