# 11 · 冷启动与用户侧追溯

> 版本 `onboarding-3.0` ｜ 两块"让系统看起来不像黑箱"的设计

---

## §1 冷启动三阶段（v3.0 修正 C10）

| 阶段 | 轮次 | 启用 | 行为 |
|---|---|---|---|
| **冷启动** | 1–3 | 仅宪法层 + 情感 | 记忆/元认知/目标/关系/叙事**不注入** |
| **热身** | 4–20 | 全部 | 抑制"无记录"重复注入；记忆只注入 `confidence ≥0.7` |
| **常规** | 21 起 | 全部 | 正常 |

切换条件：冷→热 完成 3 轮；热→常规 完成 20 轮 **或** 记忆 ≥10 条 **或** 用户显式要求。
轮次按**跨会话累计**计算（隔一周回来从第 4 轮继续，不重置）。

### 依赖倒置修正（C10）

原设计冷启动只开"宪法层 + 情感"，但情感评估器的输入含 `goal_relevance`/`goal_congruence`，
而目标插件在冷启动未启用 → **前 3 轮情感评估的 goal 维度无来源**。

v3.0 定案：**冷启动期情感评估器强制输出 `no_event: true`**。
即前 3 轮情绪保持基线，不猜。代价是前 3 轮没有情绪表达变化，收益是不产生假事件。

## §2 用户侧追溯（citation 契约）

引用记忆的回复句末有 `🔍` 图标，展开显示来源、路径、置信度、原始证据，并提供
**"这条不对"一键纠正**。

```yaml
citation:
  entry_id: "..."
  path: "direct|diffused|cold"
  confidence_band: "high|mid|low"
  evidence_quote: "原文片段"
  source_at: "时间戳"
  status: "active|superseded|stale"
```

### 两条硬约束

1. **不显示内部数值**（`potency`、衰减参数、检索分数）——只显示分档与时效标签。
2. **纠正即生效**：用户点"这条不对"→ 条目 `status=suppressed` + 写 `corrections` 表，
   下一次检索跳过。**不需要二次确认**，但要能撤销（记录纠正前状态）。

### 与学习机制的接口（v3.0 新增）

这是**唯一的地面真值入口**。每次纠正写一条：

```yaml
corrections:
  - turn_id: "s_123/t_7"
    entry_id: "mem_456"
    kind: "wrong|should_not_recall|should_have_recalled"
    user_quote: "不对，是 X 不是 Y"
    at: "2026-10-25T15:04:00+08:00"
```

`kind` 三分：
- `wrong`：内容错（→ supersede 的负样本）
- `should_not_recall`：不该提（→ 检索精度的负样本，**这是原设计完全没利用的信号**）
- `should_have_recalled`：该提没提（→ 召回的负样本，靠用户重述检测，弱信号）

`docs/13 §5` 会消费这张表。

## §3 与"冷启动抑制刷屏"的关系

热身期只注入 `confidence ≥0.7` 的条目，是为了避免"新用户第一句话就被一堆低质量匹配淹没"。
但这条规则会产生一个副作用：**热身期的召回显得很笨**。
补偿手段：元认知在无高置信命中时输出 `hedge` 或 `ask_clarify`，
让 Agent 主动问"你指的是哪个方案"，而不是硬塞。

## §4 设置页需要露出的项（最小集）

| 项 | 位置 | 说明 |
|---|---|---|
| 冷启动/热身/常规 状态 | 概览 | 可手动跳过新手期（立即生效） |
| 记忆条目列表 + 删除 | 记忆 | 物理删除是唯一的硬删除路径 |
| 引用展开 + "这条不对" | 对话内 | 见 §2 |
| 人格/语气配置 | 情感与人格 | 基线需二次确认 |
| 表达漂移当前量 + 一键清零 | 情感与人格 | 仅 `drift.enabled=true` 时露出 |
| 学习提议队列 | 实验室 | 仅灰度期露出（见 `docs/13 §7`） |
| **不露出**：用户情感感知 | — | design-only，不进设置页 |
